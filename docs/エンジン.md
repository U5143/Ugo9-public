# ゲームエンジン（Godot・Unity・Unreal、ほか RPG ツクール MZ・GameMaker・GDevelop）

Ugo9 のキャラを各ゲームエンジンで動かすための設計。担当はゲームエンジンのセッション（`engines/`）。進み具合は 進行/ゲームエンジン.md。エディタで作ったキャラをゲームで動かすまでの手引きと見本は [エンジンの使い方](エンジンの使い方.md)。

## 守ること（全エンジン共通）

エンジンの中でも Ugo9 の軽さを崩さない。

- **CPU は 1 体あたり数百バイトの「フレームの塊」を作るだけ**。作るのは C の芯（`core/`）で、エンジン側は芯を呼ぶだけ。芯をエンジンの言語に書き直さない
- **頂点の変形は GPU**。`web/ugo.js` の頂点シェーダーと同じ計算を、各エンジンのシェーダー言語で 1 本書く
- **何体いても少ない描画回数**。同じモデル（同じテクスチャ）のキャラは、インスタンス描画で **1 回** にまとめる
- 頂点のデータは読み込み時に 1 回だけ GPU へ送る。毎フレーム送るのは、全キャラ分のフレームの塊を並べた 1 枚のテクスチャ（またはバッファ）だけ

## 共通の作り

### データの流れ

```
読み込み時（1 回）
  .ug9 のバイト列 → ugo_model_init（芯が全部を検査）
  → メッシュ：位置・UV・インデックス（エンジンの普通のメッシュ）
  → 頂点の表（テクスチャ）：頂点ごとに 3 テクセル
       [骨の番号 ×4] [骨の重み ×4] [パーツ, 差分の開始, 差分の数, 0]
  → 差分の表（テクスチャ）：項目ごとに 1 テクセル [差分の番号, dx, dy, 0]
  → アトラス：アルファを前もって掛けておく（premultiplied）

毎フレーム（CPU）
  キャラごとに：ugo_reset_params → ugo_apply_animation → ゲームが決めたパラメータ
                → ugo_update(dt) → ugo_set_transform（エンジンでの置き場所）
  全キャラのフレームの塊を 1 枚の RGBA32F テクスチャ（幅 1024 テクセル）に並べて送る

GPU（頂点シェーダー）
  VERTEX_ID で頂点の表を、INSTANCE_ID でフレームの塊を引く
  基準の位置 ＋ Σ 重み × 差分 → 骨（最大 4 本）→ キャラの置き場所 → 画面
  パーツの不透明度が 0 なら三角形を画面の外へ
```

頂点ごとの骨の番号・重みなどを、エンジンのメッシュの頂点属性ではなく**テクスチャ**に入れるのは、エンジンごとに使える頂点属性が違うため（Godot の 2D メッシュは位置・UV・色・CUSTOM0/1 しか持てない、など）。頂点番号でテクスチャを引く形なら、どのエンジンでも同じシェーダーの書き方になる。1 頂点あたりテクセル 3 回の読み出しが増えるが、差分と骨の読み出しに比べて小さい。Unity・Unreal で頂点属性の方が速いと分かれば、そこだけ変える。

### 形式の変化に追いつきやすくする

- 形式の版（1.0、2026-11-09 ユーザーの決定）：芯は主が同じなら新しい副のファイルも読み、知らない物は飛ばす。飛ばした時は `ugo_model_warnings` が 0 でないので、読み込みの時に警告を出す（Unity は `Debug.LogWarning` と取り込みの警告、Godot は `push_warning`、three.js は Web の UgoModel が console に出す）。読めない時（`UGO_ERR_VERSION`）は、ファイルの主と芯の主を比べて「作業用 JSON からコンパイルし直す」か「プラグインを新しく」を出す（Web と同じ文）
- ファイルの拡張子（2026-11-07 ユーザーの決定）：ランタイムが読むモデルは **`.ug9`**、表情のプリセットは **`.ug9x`**。中身は前の `.ugo` と同じなので、Unity の取り込みと Godot の読み込みは `.ugo` も当面読む

- エンジン側は `.ug9` の中身を自分で読まない。必ず `ugo.h` の関数を通す（表の位置・フレームの塊の区切りは `ugo_frame_*_offset` で受け取り、シェーダーへ uniform で渡す）。表が増えても芯が吸収する
- 骨のせん断・受け継ぎ方・IK・transform 制約は芯の中で計算済み。エンジンは骨の行列（フレームの塊）を受け取るだけ
- これから入るマスク（ステンシル）・合成モード・複数テクスチャは、「1 体を 1 回で描く」を「描く範囲（パーツの並び）ごとに、合成モード・ステンシル・テクスチャを切り替えて描く」に広げて入れる。描画の回数は「範囲の数」で決まり、キャラの数では増えない。そのため各エンジンの描画の部品は、最初から**範囲の並び**を持つ形にしておく（今は範囲 1 つ）
- シェーダーは各エンジンで 1 本ずつ。計算が合っているかは、Web 版（`web/ugo.js`）の絵と比べて確かめる（Godot は CI で、Unity・Unreal は手順書で）
- **描画順（形式 0.8）**：`ugo_has_draw_order` が 1 のモデルは、パーツの描く順がキャラごと・フレームごとに変わりうる。キャラの更新の後に `ugo_draw_order_key`（保存の順なら 0）と `ugo_draw_order`（描く順のパーツの番号）を読み、**隣り合うキャラで同じ並びの物をまとめ**、その並びのランごとに 1 回描く（シェーダーにはまとまりの最初のキャラの番号 `instance_base` を渡し、`INSTANCE_ID + instance_base` でフレームの塊を引く）。並びごとのインデックス（ランのメッシュ）は 8 通りまで覚え、超えたら一番前に使った物を作り直す（Web の `runsFor()` と同じ）。描画の回数は「まとまりの数 × ランの数」で、並びがそろっていれば今までと同じ。マスクは描画順に関係しない。`ugo_has_draw_order` が 0 のモデルは今までどおり
  - Godot：まとまり × ランごとの MultiMesh の描画を使い回す（`UgoDrawer::draw_ordered`）。Unity：まとまりごとの MaterialPropertyBlock と、描く順の render queue を持つマテリアル（同じ深さの半透明を Unity が並べ替えないように）。three.js：キャラごとのメッシュなので、並びごとのジオメトリ（頂点の属性は共有）に差し替える（`geometryFor`）
  - ワープ格子の角度（`warps[].angle`、0.8）は芯の中で済み、エンジン側は変わらない

### 使う人から見た API（エンジンごとに名前の書き方だけ合わせる）

| 部品 | 役目 |
|---|---|
| **UgoModel**（リソース／アセット） | `.ug9` とアトラス。パラメータ・アニメ・パーツの名前の一覧。複数のキャラで共有 |
| **UgoCharacter**（ノード／コンポーネント） | 1 体。`model`、`animation`（名前）、`playing`、`speed`、`loop`、`time`。`set_param(名前, 値)`（置いた値はそのまま残る）・`clear_param`・`get_param`、`play(名前)`・`stop()`、`blend(名前, 時間, 重み)`（重ねがけ）、`reset_physics()` |
| **エディタでの設定とプレビュー** | Play しなくてもエディタでアニメが動く（Unity は `previewInEditor`、Godot は `preview_in_editor`。切ると Unity は Time のスライダーで止めて見る）。インスペクタで、アニメと表情をモデルの名前から選ぶ、パラメータごとのスライダー（動かした物だけ保存され、ゲームの set_param がその上にかかる）。Unity は専用のインスペクタ（`UgoCharacterEditor`）、Godot は `parameters/<名前>` の項目と、animation・expression の候補 |
| **助け**（見る方向・まばたき・口） | 見る方向：Unity `lookTarget`（Transform）・`LookAt(点)`・`StopLooking()`、Godot `look_target`（Node2D）・`look_at_point(点)`・`stop_looking()`。顔（HeadTurnX/Y）・目（PupilX/Y）・体（BodyTurnX の 3 割）が向く（標準の名前が無いモデルは前の名前 AngleX/Y・EyeBallX/Y・BodyAngleX。Web の UgoLook と同じ決まり）。`look_from` は顔の位置（モデルのピクセル、既定はキャンバスの上から 4 分の 1）、`look_range` は向き切る距離。自動まばたき：`autoBlink`／`auto_blink`（EyeOpenL・R、2〜6 秒ごと）。口：`SetMouthLevel`／`set_mouth_level`（0〜1）、Unity は `lipSyncSource`（AudioSource の大きさ）、Godot は `lip_sync_bus`（オーディオバスの大きさ）。音からの口には雑音の門（Web の VoiceLevel と同じ数：門 −45 dB より大きい音が 0.05 秒続いたら開き、門 −4 dB より小さい音が 0.12 秒続くまで開いたまま、門から 25 dB で開き切る。Unity `lipSyncGateDb`・`lipSyncRangeDb`・`VoiceGate`、Godot `lip_sync_gate_db`・`lip_sync_range_db`）。キーボードの音や息では開かない。アニメと set_param の後・更新の前にかかる。パラメータの名前は Unity の `Helpers` で変えられる |
| **アニメの切り替え**（UgoCharacter の中） | `play(名前, 始める時間, 混ぜる秒)`：混ぜる秒が 0 より大きいと、今のアニメを進めたまま重さを下げ、新しいアニメを重ねて上げる（クロスフェード）。`play_next(名前, 混ぜる秒)`：今のアニメ（ループしない物）が終わったら次へ。終わった時に知らせる（Unity は `AnimationFinished` の event、Godot は `animation_finished` の signal）、`is_finished` |
| **アニメの層**（UgoCharacter の中、1.1） | 今のアニメ（`play`）を層 0 として、その上に層 1、2… を重ねる。`PlayLayer`／`play_layer(層, 名前, 混ぜる秒=0.25, 足す=false, 覆い, 重さ=1)`：層ごとに 1 つのアニメ、切り替えはクロスフェード。**足す**はアニメの「休みの姿からの変化」を上に足す（どんな姿にも頷きを重ねる、など）。**覆い**はその骨・パーツ・パラメータだけにかける（歩きながら右腕だけ振る）：Unity は `MakeMask(bones, parts, parameters)` で作って使い回す、Godot は `{ "bones": [...], "parts": [...], "params": [...] }`（書かない種類は全部、空の並びは無し）。`QueueLayer`／`queue_layer`（今のが終わったら）、`StopLayer`／`stop_layer(層, 混ぜる秒)`、`SetLayerWeight`／`set_layer_weight`（層全体の重さ）、`LayerAnimation`／`get_layer_animation`、終わった知らせ（Unity `LayerFinished`、Godot `layer_finished`）。層の時計はキャラの `speed` で進む。かけるのは今のアニメの後・set_param の前。Web の `UgoAnimator` と同じ決まり（芯の `ugo_apply_animation_ex`） |
| **エンジンの時間軸**（Timeline・Animator・AnimationPlayer） | Unity の **Timeline**：「Ugo9 Animation」トラック（UgoCharacter に結ぶ）と、モデルのアニメを名前で選ぶクリップ。クリップを重ねるとクロスフェード、イーズインは今の姿の上に混ざる、Clip In・速さ・外挿も使える。ループするアニメはクリップが長くてもループし続ける。Play しなくてもスクラブで姿が見える。Timeline のパッケージがある時だけ組み立てる（`Timeline/Ugo9.Timeline.asmdef`）。Unity の **Animator**・アニメーションの窓：UgoCharacter の `time`・`speed`・`playing`・`color` をキーにできる（`parameters` は並びなのでキーにできない。パラメータを時間で動かすのは Timeline か SetParam で）。Godot の **AnimationPlayer**：`time`・`animation`・`expression`・`parameters/<名前>` をそのままトラックにできる（キャラは `playing = false` にして `time` を動かすと、時間軸どおりになる） |
| **芯に追いついた物**（1.1） | 当たりの領域：Unity `AreaAt(ワールドの点)`・`AreaNames`、Godot `get_area_at`・`get_area_names`（パーツの名前が `hit:頭`・`当たり:頭` の物。描かないパーツでよい）。骨：Unity `BonePosition`・`BoneRotation`（剣や効果を手に付ける）、Godot `get_bone_transform`。手を伸ばす：Unity `ReachFor(骨, 点, 鎖の数=2)`・Godot `reach_for`（そのフレームだけ。届けたい間は毎フレーム呼ぶ）。風：Unity `wind`（ピクセル/秒²、y 上）・`windGust`、Godot `wind`（y 下）・`wind_gust`（揺れ物の鎖だけ。パラメータの物理には効かない）。カリングは芯の見積もりの四角（ugo_bounds_estimate）で、キャラごと・フレームごと |
| **表情**（形式 0.8、UgoCharacter の中） | モデルの表情の一覧（`expression_names`）。`show_expression(名前, フェード)`・`hide_expression`・`only_expressions(名前…)`（フェードは既定で表情自身の fadeIn・fadeOut）・`expression_weight`。`load_expressions(JSON)` でプリセット（`ugo9-expressions`、ファイルは `.ug9x`。Unity は `.ug9x` を TextAsset として取り込み `LoadExpressions(TextAsset)`、Godot は `FileAccess.get_file_as_string` で読んだ文字列を渡す）を読み、このモデルに無いパラメータの名前を返す（同じ名前ならプリセットが先）。かけるのはアニメと set_param の後・更新の前。名前の照合と計算は芯（`ugo_resolve_params`・`ugo_apply_params`・`ugo_apply_expression`）。three.js は Web の `UgoExpressionMixer` をそのまま使う |
| **ピクセルアート**（近い色で読む） | 芯の `UGO_RASTER_NEAREST`・Web の `sampling: 'nearest'` と同じ絵にする。Unity：`.ug9` の取り込みの設定 **Pixel Art**（テクスチャを Point・ミップマップ無しで作る。実行時に作る時は `UgoModel.LoadTexture(png, name, pixelArt: true)`）。Godot：`UgoModel.pixel_art = true`（キャラが描く前に）。three.js：`new UgoThreeCharacterFactory(THREE, model, textures, { sampling: 'nearest' })`。エンジンはテクスチャを自分で作り直すので、PNG 側の取り込みの設定（Filter Mode など）は効かない |
| **並べ方と色**（キャラ全体） | 色と不透明度：Unity `color`（SpriteRenderer.color と同じ）、Godot は普通の `modulate`・`self_modulate`、three.js `ch.color`（THREE.Color）・`ch.opacity`。全部のパーツの色に掛かる（不透明度 0 なら描かない）。UgoBatch の中のキャラの色は、フレームの塊の頭の 6・7 番目の数（芯は 0 のまま＝白・不透明）に入れてシェーダーで掛ける（6 番目は各色の暗さを 8 ビットずつ `(255-r)·65536 + (255-g)·256 + (255-b)`、7 番目は 1 − 不透明度）。並べ方：UgoBatch の中は、Unity `sortingOrder`（大きい物が前）→ `UgoBatch.sortByY`（下の物が前）→ 階層の順。Godot `z_index`（相対ならバッチまで足す）→ バッチの `y_sort_enabled` → 木の順。並べ方はモデルごとの描画の中で効く（違うモデルどうしは、モデルが最初に出た順）。three.js は普通の `renderOrder`。Unity の Sorting Layer（ほかのスプライトとの前後）：UgoBatch の下に無いキャラの **Sort With Sprites**（`sortWithSprites`）を入れると、普通の MeshRenderer として描き（隠した子に持つ。部品の連なりごとに 1 回）、`sortingLayerName` と `sortingOrder`（Order in Layer）でスプライトと前後する。UgoBatch の下では今までどおり（層の中は sortingOrder） |
| **クリックの当たり**（パーツの名前で） | 最後のフレームに描いた形で、点の前にあるパーツの名前を返す（描画順・マスクどおり。隠したパーツと、不透明度が `min_opacity`（既定 0.01）以下のパーツは飛ばす。テクスチャの透明な画素も当たる）。Unity：`PartAt(ワールドの点)`（無ければ null）・`HitTest`・`PartBounds(名前)`（ワールドの Bounds、名前無しでキャラ全体）・`WorldToModel`／`ModelToWorld`。Godot：`get_part_at(グローバルの点)`（無ければ ""）・`hit_test`・`get_part_rect(名前)`（ノードのローカル＝モデルのピクセル）。three.js：`ch.partAt(Raycaster か点)`（ビルボードの時は Raycaster）・`ch.partBounds(名前)`。計算は芯（`ugo_deform_cpu`・`ugo_pick_part`・`ugo_bounds`）で CPU。頂点の位置は聞かれた時だけ、更新ごとに 1 回作る |
| **PixiJS・Phaser**（Web の 2D エンジン） | `web/ugo_layer.js` の **UgoLayer**：画面と同じ大きさの WebGL2 のキャンバスに、キャラをモデルごとに 1 回でまとめて描く（`addModel`・`add(種類, { x, y, scale, rotation, order })`・`render(dt)`・`pick(x, y)`）。エンジンにはそのキャンバスを 1 枚の絵として見せる：PixiJS（v8）は `web/ugo_pixi.js` の **UgoPixiLayer**（`.sprite` を stage に）、Phaser（3.60 以上・4）は `web/ugo_phaser.js` の **UgoPhaserLayer**（Image）。毎フレーム `update(dt)` で描いて送り直す。エンジンの描画には触らないので、どの版でも、WebGL1 のエンジンでも動く。ほかのスプライトとの前後は、層ごと（層を何枚か重ねればキャラの間にスプライトを挟める）。キャラ 1 体ずつをエンジンのスプライトにしたい時は **UgoSpriteSheet**（同じファイル）：キャラごとの升目に描き（それでもモデルごとに 1 回）、Pixi は `spriteFor(キャラ)`、Phaser は `imageFor(キャラ, x, y)` で、升目を切り出したスプライト（原点はモデルの原点）。前後・移動・回転・色はエンジンのまま。揺れ物にスプライトの動きを伝えるのは `キャラ.moved(dx, dy)`、当たりは `sheet.pickIn(キャラ, x, y)`。升目はモデルのキャンバスの大きさ＋余白（既定 15%）で、はみ出した所は切れる |
| **開けばすぐ動く見本** | Unity の Samples「Playground」、Godot の `demo/playground.tscn`、Web の `web/engines/`（three.html・pixi.html・phaser.html、共通の欄は `web/engines/playground.js`）。見本のキャラで、アニメ・パラメータ・まばたき・マイクの口・クリックしたパーツが試せる。開き方は [エンジンの使い方](エンジンの使い方.md) の「4. 見本」 |
| **UgoBatch**（ノード／コンポーネント） | 中にあるキャラを、モデルごとに 1 回でまとめて描く。キャラはこの下に置くだけ。描く順は木の順 |

UgoBatch の下に無い UgoCharacter は、自分 1 体だけで描く（1 体 1 回）。群衆・大勢のキャラは UgoBatch の下に置く。ノードを置かずに数千体を動かしたい時のために、UgoBatch に「ノード無しのキャラ」を足す API も後で付ける。

座標：Ugo9 はピクセル・y 下向き。Godot の 2D はそのまま 1 ピクセル＝1 単位。Unity は y 上向きで「1 単位あたりのピクセル数」（既定 100）で割る。Unreal は x–z 平面（または x–y）で、1 ピクセル＝1 cm を既定にする。

## Godot

| 項目 | 案 |
|---|---|
| 芯の使い方 | **GDExtension**（godot-cpp、C++17）。芯の C をそのまま一緒にビルドする（共有ライブラリを別に配らない） |
| 対応する版 | **Godot 4.4 以上**（godot-cpp の `godot-4.4-stable` でビルド。GDExtension は新しい版でも読める）。CI は最新の安定版 4.7.2 で確かめる |
| 描画の方式 | 4.4 から 2D のシェーダー（canvas_item）で `VERTEX_ID`・`INSTANCE_ID` が使える。メッシュ（ArrayMesh、位置・UV・インデックス）を **MultiMesh** に入れ、インスタンスの変換は単位行列のまま。置き場所はフレームの塊の先頭（2×3 行列）で渡す。モデルごとに 1 つの canvas item を作り、そこへ MultiMesh を 1 回描く |
| フレームの塊 | `Image`（RGBAF）→ `ImageTexture.update` で毎フレーム 1 回送る。テクスチャの読み出しは `texelFetch`（フィルタ無し） |
| シェーダー | `engines/godot/shaders/ugo9.gdshader` 1 本（ビルド時に拡張へ埋め込む）。`render_mode blend_premul_alpha, unshaded, skip_vertex_transform` |
| 描画の器 | Compatibility（OpenGL）・Forward+・Mobile のどれでも同じシェーダーが動く見込み。CI は Compatibility（Mesa のソフトウェア描画）で確かめる |
| 画面の外で消えない工夫 | 頂点をシェーダーで動かすので、canvas item の範囲（custom rect）をキャラの置き場所から毎フレーム決める |
| 読み込み | `.ug9` を読む ResourceFormatLoader を拡張に入れ、`load("res://x.ug9")` で UgoModel になる。アトラスは同じフォルダの PNG（Godot が読み込んだ物を使い、無ければ画像を直接読む） |

スマホと Web（2026-11-12〜）：`ugo9.gdextension` に android.arm64・android.x86_64・web.wasm32・web.wasm32.nothreads を書いた。組み立ては `engines/godot/CMakeLists.txt` の頭の手順（Android は NDK の toolchain、Web は `emcmake`。Web は Emscripten の side module を `cmake/emscripten_shared.cmake` で作る）。CI の engines の `phones-web` ジョブで、Godot の Android・Web と Unity の Android の芯を組み立て、.gdextension が指す場所に置かれるか、Unity の C# が呼ぶ関数が全部出ているか、16 KB ページに合うかを見る。実機で動くかは PC で（書き出しの設定：Web は Thread Support の有無で nothreads の方が使われる）。

難しさ：**低〜中**。2D のシェーダーで頂点番号とインスタンス番号が使えるので、Web 版とほぼ同じ書き方になる。残る難所は、Web への書き出し（GDExtension を WASM の side module で作る）とスマホ（Android・iOS のビルド）。

## Unity

| 項目 | 案 |
|---|---|
| 芯の使い方 | **ネイティブプラグイン**（芯の共有ライブラリ：Windows の .dll、macOS の .dylib/.bundle、Linux・Android の .so）＋ **C#**（P/Invoke）。iOS と WebGL は共有ライブラリを使えないので、芯の C のソースを `Plugins` に入れて Unity にビルドさせる（`__Internal`） |
| 対応する版 | 案：**Unity 6.3 LTS（6000.3）以上**、**URP**（2D Renderer と Universal Renderer）。Built-in は余力があれば |
| 描画の方式 | `Graphics.RenderMeshInstanced`（または `RenderMeshPrimitives`）で、モデルごとに 1 回。シェーダーは手書きの HLSL（unlit・premultiplied）。`SV_VertexID`・`SV_InstanceID` |
| フレームの塊 | 使える所では `GraphicsBuffer`（StructuredBuffer）。GLES3・WebGL では Texture2D（RGBAFloat）に切り替える。シェーダーの中の読み出しを 1 つの関数にまとめ、どちらでも同じ本体 |
| 描く順 | 2D の並べ替え（Sorting Layer・Order in Layer）に乗るかを確かめる必要がある。乗らない場合は、MeshRenderer＋自前で頂点数ぶんの「空の」インスタンスを持つ方式に切り替える |
| 読み込み | ScriptedImporter で `.ug9` をアセットにする（エディタで置くだけ） |

難しさ：**中**。描画回数を 1 回にするのは素直にできるが、URP の 2D の並べ替え・SRP Batcher との兼ね合い、スマホと WebGL でのプラグインの配り方に確かめる所が多い。CI では動かしにくい（ライセンス）ので、ユーザーの PC で確かめる手順を書く。

## Unreal Engine

| 項目 | 案 |
|---|---|
| 芯の使い方 | **プラグイン**（Runtime モジュール）。芯の C をモジュールの中でそのままビルドする（できなければ CMake で作った静的ライブラリを ThirdParty として入れる） |
| 対応する版 | 案：**UE 5.6 以上**（最新は 5.8）。版ごとに API が少しずつ変わるので、確かめる版を 1 つに絞りたい |
| 描画の方式（第 1 段） | **Instanced Static Mesh** ＋ マテリアルの World Position Offset。マテリアルの Custom ノード（HLSL）で Web 版と同じ計算をし、「変形後 − 元の位置」を足す。頂点番号は UV の 1 チャンネルに入れ、インスタンス番号は PerInstanceCustomData。モデルごとに 1 回 |
| 描画の方式（第 2 段） | 速さが足りない・制約が多い場合に、独自の頂点ファクトリ（FVertexFactory）と FPrimitiveSceneProxy。最も速いが難しく、版ごとの追従も重い |
| フレームの塊 | UTexture2D（PF_A32B32G32R32F）を `UpdateTextureRegions` で毎フレーム更新 |
| 透明 | Translucent・Unlit、合成は AlphaComposite（premultiplied）。同じ描画の中の順は、インスタンスの順と三角形の順で決まる |
| 読み込み | エディタの Factory で `.ug9` をアセットにし、実行時に UStaticMesh を作る |

作り始めた（2026-11-12、ユーザーの決定。UE 5.6 から）：設計と段の計画は 進行/Unreal.md（上の表の第 1 段の案は見直し、独自の Scene Proxy と頂点ファクトリで作る）。コードは `engines/unreal/Ugo9`。

難しさ：**高**。マテリアル経由の計算は制約が多く（ループ・テクスチャの読み出しを Custom ノードで書く）、範囲（Bounds）の調整、版ごとの API の違いがある。CI では動かさず、ユーザーの PC で確かめる。

## エンジンに機能が無い時（ハブの方針、2026-10-30）

エンジンに無い機能は近似してよい。ただし：

1. エンジンごとの違いを下の表に書く
2. 重なりの無い普通の場面では、Web 版と同じ絵（今の差の水準）を保つ
3. 合成の screen は、画面のコピーを読む正確な方法を基本にし、近い式は遅い時の切り替えにする

テストは機能ごとの小さな場面に分け、重なりの無い場面は厳しい基準、近似の出る場面は「差の最大」と「差の出る画素の割合」を測ってから基準を決める。

| 機能（形式 0.4〜） | Web 版（2D） | three.js（3D） | Godot | Unity | Unreal |
|---|---|---|---|---|---|
| マスク | 画面サイズの画像に全キャラ 1 回（MRT、重なりは MAX） | キャラごとに、モデルの座標（キャンバス）の画像へ 4 チャンネルずつ（重なりは MAX）。3D に置いてもずれず、キャラ同士で漏れない。キャラ 1 体につき描画が 1 回増える | 画面サイズの SubViewport に 3 チャンネルずつ（rgb。Godot の加算の混ぜ方は rgb に α を掛けるので、α は使わない）、重なりは加算で近似 | キャラごとに、キャンバスのテクスチャ配列の層へ 4 チャンネルずつ（重なりは MAX）。頂点シェーダーで層を選べる GPU（D3D11・Vulkan・Metal）は全キャラを 1 回、選べない GPU はキャラごとに 1 回 | three.js と同じ（キャンバスのテクスチャ配列、キャラごと・4 チャンネルごとに 1 枚、MAX） |
| 合成 multiply・screen | 2 出力の合成、無ければ範囲で分ける | 範囲ごとに材質を分ける（Web の 2 出力無しと同じ式で正確） | multiply は `blend_mul` で正確、screen は画面のコピーを読む（基本）／近い式（切り替え） | 範囲ごとに材質を分ける（multiply は DstColor、screen は OneMinusSrcColor で正確） | 部品のまとまりごとに PSO の合成を替える（Unity と同じ式） |
| 複数テクスチャ | テクスチャ配列 | 8 枚まで（別々の sampler） | テクスチャ配列 | 8 枚まで（_UgoAtlas0〜7） | 8 枚まで（別々のテクスチャ） |

RPG ツクール MZ（engines/rpgmaker_mz）と GDevelop（engines/gdevelop）は Web 版（UgoLayer）と同じ描き方。GameMaker（engines/gamemaker）は拡張が CPU で変形した三角形を、合成とアトラスの頁のまとまりごとに描く（合成は gpu_set_blendmode_ext、頁ごとのテクスチャ。マスクはまだ）。名前の見比べは [エンジンのAPI.md](エンジンのAPI.md)。

    5. 結果：プラットフォームごとに「出た・動いた・口が動いた」と、エラーの全文

うまく行かない時：

| 起きた事 | 見る所・試す事 |
|---|---|
| `DllNotFoundException: ugo` | 手順 1 をやったか。Project ウィンドウの Packages →「Ugo9」→ Runtime/Plugins/Windows/x86_64/ugo.dll を選び、Inspector で「Editor」と「Standalone・Windows x86_64」にチェックがあるか。Unity を一度閉じて開き直す |
| `.ug9` が UgoModel にならない・テクスチャが白い | Console のエラー。`.ug9` を右クリック → Reimport |
| キャラが何も見えない | Console に「Shader error」が無いか（全文を記録）。Scene ビューでは見えるか。カメラが Orthographic か |
| 絵が上下逆さま・マスクの所だけおかしい | `build\unity\<場面>_diff.png` を添えて報告（マスクの向きの直しはこちらで行う） |
| 色が少し違う（半透明の重なり） | Color Space が Gamma か（`compare` の出力の 2 行目に出る） |
| Unity Hub の「ディスクから追加」で「プロジェクトが見つかりませんでした」 | 手順 2 のとおり Hub の「新しいプロジェクト」で作る。既にあるフォルダは、`Unity.exe -projectPath <フォルダ>` で直接開ける |
| `InvalidOperationException: You are trying to read Input using the UnityEngine.Input class` | パッケージ 0.5.1 より前の見本。新しい見本を Import し直す（Unity 6 の雛形は Input System だけ。見本は両方に対応した）。急ぐ時は Project Settings → Player → Active Input Handling を Both |
| 2 回目の Play から `MissingReferenceException`（Texture2D）で何も出ない | パッケージ 0.5.1 より前の物（Play の度にドメインを読み直さない設定で起きる）。新しいパッケージで直った |
| Android で `DllNotFoundException: ugo`・キャラが出ない | 手順 12-2 の `--android` をしたか。`Plugins/Android/libs/arm64-v8a/libugo.so` を選び、Inspector で Android に印、CPU が ARM64 か。Target Architectures に ARM64 があるか（ARMv7 だけだと、ARM64 の .so は入らない） |
| WebGL・iOS で `EntryPointNotFoundException` | 手順 12-3 の `--sources` をしたか。`Plugins/WebGL/ugo9/ugo.c`（iOS は `Plugins/iOS/ugo9/ugo.c`）の Inspector で、その platform だけに印があるか |
| ビルドした物でキャラが出ない・すぐ落ちる | 出力先の `<プロジェクト名>_Data\Plugins\x86_64\ugo.dll` があるか。`%USERPROFILE%\AppData\LocalLow\<会社名>\<プロジェクト名>\Player.log` のエラーを記録 |
| 描画回数がキャラの数と一緒に増える | 見本の左上の数字と、GPU の名前を報告（マスクを 1 回で描けない GPU かもしれない） |

コードは直さず、エラーの全文と、どの手順でそうなったかを記録する。
