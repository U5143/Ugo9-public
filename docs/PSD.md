# PSD から作る

パーツ分けした PSD（Photoshop・CLIP STUDIO・Krita などで書き出した物）を Ugo9 のモデルに変える。Krita（.kra）・OpenRaster（.ora）・レイヤー分けした PNG の組も、レイヤーを読んだ後は同じ道を通る（「Krita・OpenRaster・PNG の組から作る」の節）。

```
node tools/import_psd.mjs 絵.psd 出力フォルダ [--spacing 24] [--mesh auto|contour|grid] [--alpha 8] [--group-bones] [--no-clipping]
```

出力フォルダに `model.json`（作業用）・`model.ug9`・`atlas.png` ができる。ブラウザ（エディタ）からは `importPsdAsync` をそのまま import して使う（ビルド不要）。

```js
import { importPsdAsync } from '../tools/import_psd.mjs';
const { model, atlas, groups, layers, warnings } = await importPsdAsync(arrayBuffer, { spacing: 24 });
// importPsd（同期）も使えるが、ZIP 圧縮のレイヤーには opts.inflate（同期の展開）が要る
// atlas: { width, height, rgba }。PNG にするのは呼ぶ側（ブラウザは canvas）
```

## できること

| PSD | Ugo9 での形 |
|---|---|
| 画素のレイヤー | 1 つのパーツ（下のレイヤーが奥）。id はレイヤー名（同じ名前は `_2`, `_3` を付ける）。骨は `root` 1 本 |
| レイヤーの不透明度・塗りの不透明度 | パーツの不透明度（掛け合わせ） |
| 非表示のレイヤー（またはグループごと非表示） | 不透明度 0 のパーツ（警告） |
| レイヤーマスク | 透明度に掛けてから取り込む。フォルダのマスクは中のレイヤー全部に掛ける |
| ベクトルマスク | パスを塗って（Bézier を細かい直線に、各画素 4×4 で数える）透明度に掛ける。反転も |
| クリッピング | 一番近い、同じフォルダの中でクリッピングしていない下のレイヤー（土台）を `mask` にする（形式 0.4〜）。すぐ下がフォルダなら、そのフォルダの中のクリッピングしていないレイヤー全部を `mask` にする。土台が無い時は掛けずに警告、土台が空なら不透明度 0。`clipping: false` でクリッピングを使わない（`mask` を付けず、クリッピングしたレイヤーもそのまま描く。`layers[i].clipping` は残る） |
| 合成モード：乗算・スクリーン・覆い焼き（リニア）- 加算 | `blend`：`multiply`・`screen`・`add`（形式 0.4〜）。ほかのモードは通常として描き、警告。ただしクリッピングしたレイヤーなら下の行 |
| クリッピングした、Ugo9 に無い合成（オーバーレイ・ソフトライト・ハードライト・覆い焼きカラー・焼き込み・比較・差・除外・減算・除算・ビビッドライト・リニアライト・ピンライト・ハードミックス・色相・彩度・カラー・輝度・カラー比較）のレイヤー | 土台のレイヤーの画素に焼き込む（2026-11-09）。Photoshop の既定の描き方（クリッピングしたレイヤーはグループとして、土台の色の上に重ね、土台の透明度を保つ）。土台と一緒に動くので、動かしても崩れない。焼くのは、最後のそういうレイヤーまでのクリッピングしたレイヤー全部（順を保つため）。その上の乗算・スクリーン・加算はパーツのまま。お知らせ `layerBlendBaked`（info）。`bakeBlends: false` で前のとおり（通常で描いて警告） |
| グループ（`groupBones` / `--group-bones` の時） | グループごとに骨を作る（入れ子は親子。位置はグループの絵の下端の中央、上向き、長さは絵の高さの半分。骨の id はグループの id）。パーツはそのグループの骨に付く。開いた時点で、グループの骨を回すとまとめて動く |
| グループ（入れ子も） | model には入れず、`groups: [{ id, name, parent, parts, visible, opacity, blend }]` で返す |
| 透明でない所 | 輪郭に沿ったメッシュ（下） |
| 画像 | 余白を切り詰めて 1 枚のアトラスに詰める。周りに `margin`＋1 px の透明な縁を付け、透明な所には隣の色を広げる（縁が黒ずまない） |

### メッシュ

- 不透明な画素（`alpha` 以上）を `margin` px（既定 2）太らせた形の輪郭に、`spacing` の半分ほどの間隔で点を置く（角を先に選ぶ）。内側には `spacing` px（既定 24）おきの格子の点。これを Delaunay で三角形に分け、中心が形の外にある三角形を除く
- 不透明な画素が 1 つ残らず三角形に覆われているかを確かめ、覆われない所には輪郭の点を足して分け直す
- 細い線やくし形のように、輪郭の点が格子の 1.5 倍より多く要る絵は、格子のメッシュ（1 辺 `spacing` px のマスのうち不透明な画素を含む物）にする（`mesh: 'auto'`、既定）。`'contour'`・`'grid'` で決められる
- 小さい絵は細かくする（`spacing` を短い辺の 1/2.5 まで）
- エディタで細かさを変える時は `meshFromLayer(layers[i], { spacing, mesh, atlasWidth, atlasHeight, originX, originY })` → `{ vertices, uvs, triangles }`（同じアトラスのまま、メッシュだけ作り直す）

`layers` には、パーツごとに PSD 上の位置と大きさ（left / top / width / height）、マスクを掛けた後の RGBA、アトラスのどこに入れたかが入る（エディタがメッシュやアトラスを作り直す時に使う）。

読める形式：8・16 ビットの RGB・グレースケール（16 ビットは 8 ビットに丸める。Photoshop が `Lr16` に入れる形も）、PSD と PSB、圧縮なし・RLE・ZIP（ZIP は `opts.inflate` を渡す。Node なら `zlib.inflateSync`）。

## 文書と一緒に保存する・PSD を読み直す

- `layerMeta(layers[i])`：画素を除いた、JSON にしてよいレイヤーの説明（名前・グループの道筋 `path`・PSD 上の位置・アトラス上の範囲 `atlas` など）。文書と一緒に保存しておくと、後で `meshFromLayer(meta, { atlas: { width, height, rgba }, spacing, originX, originY })` でメッシュを作り直せる（画素はアトラスから読む）
- `reimportPsd(bytes, { canvas, parts, layers: 保存した layerMeta }, opts)`：絵を描き直した PSD を読み直す。レイヤーはグループの道筋と名前で突き合わせる（同じ名前は n 番目どうし）
  - 見つかったパーツは**メッシュをそのまま**（キーフォーム・重みが残る）、アトラスと UV だけ替える → `uvs: { パーツ id: [...] }`
  - 絵が動いた・小さくなったなどで、頂点が新しい絵の範囲の外に出たパーツ → `outside: { パーツ id: 頂点の数 }` と警告（メッシュを作り直してキーフォームを移すかはエディタで）
  - 新しいレイヤー → `added: [{ layer, part }]`（メッシュ付き）、無くなったレイヤー → `removed: [パーツ id]`

## PSD とモデルのつながりを見る（`tools/psd_links.mjs`、2026-11-10、機能の比べ #20・利用者の声 #22）

描き直した PSD を読み直す前に、各パーツのレイヤーがどうなったかの一覧。読み直し（`reimportPsd`）はフォルダの道と名前でつなぐだけなので、名前を変えたレイヤーのパーツは消えて、新しいパーツになる（メッシュ・キーの形・ウェイトが無くなる）。これを前もって見つける。

    node tools/psd_links.mjs model.json 新.psd [--json] [--write 直した.json]

- 名前でつながったレイヤー：`same`（同じ画素）・`moved`（同じ絵が dx, dy ずれた）・`resized`（絵の箱が変わった）・`redrawn`（同じ箱で画素が変わった：変わった割合）
- つながらなかった物：消えたレイヤーと新しいレイヤーで絵が似ている物（16×16 に縮めた見た目と大きさ、遠いほど下げる。既定 0.9 以上）を `renamed`（名前を変えた？、似ている度合い）にする。残りは `removed`（パーツが絵を失う）と `added`
- `layers`（`--write` では `source.psd.layers`）に名前の変更を入れて返す。これで読み直すと、そのパーツはそのまま残る
- 前の絵はモデルのアトラスから戻す（`layerPixelsFromAtlas`）。お知らせ：`psdLinkRenamed`・`psdLinkRemoved`・`psdLinkAdded`（info）
- エディタは「PSD を読み直す」の前にこの一覧を窓に出し、名前の変更を確かめてもらう（エディタの担当）
- 確かめ（`tests/psd_links_test.mjs`）：6 つのレイヤーに分かっている変更（そのまま・12, 5 動かす・30×30 を 44×36 に・右半分を塗る・eye_L を 左目 に・消す・新しく足す）をすると、それぞれがそう出る（塗った割合 0.5、似ている度合い 1）。名前の変更を入れると読み直しで eye_L が残る。遠くの違う大きさの絵は名前の変更と取らない。コマンドと --write

## アトラスの詰め方（2026-11-04、要望 9）

- 絵（不透明な所の外接矩形に、周りの余白を足した物）を、MaxRects で詰める
  - 空いた四角を覚えておき、各絵を一番合う所に置く
  - 置き方の決まり 3 通り（短い辺が一番合う・面積が一番合う・一番下）と、ページの幅（絵が入る 64 からの 2 の累乗と、最大の幅）を全部試す。ページの数が一番少なく、面積が一番小さい物を選ぶ
  - 絵が 400 枚を超える時は、置き方の決まりを 1 通りにする（時間を抑えるため）
- **90° 回す**：絵は 90° 時計回りに回して置いてもよい。画素を並べ替えるだけで、補間はしないので、絵は少しも変わらない
  - `layers[].atlas.turned: true` が回した印。width・height は回す前（PSD の向き）の大きさ
  - UV・メッシュの作り直し（`meshFromLayer`）・読み直し（`reimportPsd`）は、この印を見る
  - `atlasTurn: false` で回さない
- 形式は変わらない（変わるのは UV とアトラスの中の置き方だけ）
- **好きな角度で回す**（`atlasAnyAngle: true`、既定は切る。エディタの選択肢の名前の案：「アトラスをもっと小さくする（絵がわずかにぼやける）」）：斜めの細長い絵を、外接の四角が一番小さくなる角度で回して置く
  - 角度は、不透明な画素の凸包の各辺を水平にした時の外接の四角で選ぶ（回転キャリパー、±45° の中、1° 以上）
  - 外接の四角が 2 割以上小さくなる絵だけを回す
  - 画素を斜めに置き直すので、補間（双線形、アルファを掛けた色で）で縁と細い線がわずかにぼやける。中の色の差は 2 程度
  - `layers[].atlas.angle`（度）と `atlasArea`（回した絵の [幅, 高さ, 中心の x, 中心の y]）が印。UV・メッシュの作り直し・読み直しは、この印を見る
  - 斜めの髪の房・腕・剣の合成のキャラ（44 枚）で、アトラスが 7.02 → 1.98 M 画素（−72%）。丸い絵ばかりの合成の PSD では、どの絵も回らない。読み込みの時間はほぼ同じ

## Krita・OpenRaster・Procreate・Aseprite・PNG の組から作る（`tools/import_layers.mjs`、2026-11-08）

PSD でない重ねた絵も、レイヤーを読んだ後は PSD と同じ道（アトラス・メッシュ・クリッピング・グループ・警告）を通る。返す物も `importPsd` と同じ（`{ model, atlas, atlases, groups, layers, scale, warnings, notes }`）。外の依存は無い（ZIP・PNG・LZF は自前、展開はブラウザの DecompressionStream か Node の zlib）。

```
node tools/import_layers.mjs 絵.kra|絵.ora|絵.procreate|絵.aseprite|PNG のフォルダ 出力フォルダ [import_psd.mjs と同じ選択肢]
```

```js
import { importKraAsync, importOraAsync, importPngSetAsync, layeredKind } from '../tools/import_layers.mjs';
const kind = layeredKind(bytes);                       // 'kra' | 'ora' | 'procreate' | 'aseprite' | 'psd' | 'png' | null
const res = await importKraAsync(bytes, { spacing: 24 }); // importOraAsync・importProcreateAsync・importAsepriteAsync も同じ
// PNG の組：下のレイヤーが先。パスのフォルダはグループになる。left・top・visible・opacity・blend も渡せる
const res2 = await importPngSetAsync([{ path: 'body.png', bytes }, { path: '顔/目.png', bytes }]);
// Node（同期）：importKra(bytes, { inflate: zlib.inflateSync, inflateRaw: zlib.inflateRawSync })
```

| 形式 | 読む物 |
|---|---|
| OpenRaster（.ora：Krita・GIMP・MyPaint など） | `stack.xml` の `layer`（PNG、`x`・`y`）と `stack`（グループ）。`visibility`・`opacity`・`composite-op`（`svg:src-over`・`svg:multiply`・`svg:screen`・`svg:plus` を通常・乗算・スクリーン・加算に。ほかは通常で描いて警告）。最初の子が一番上 |
| Krita（.kra） | `maindoc.xml` の `paintlayer`（64×64 のタイル、LZF）と `grouplayer`（通過は `passThrough`）。色空間は 8・16 ビットの RGBA とグレー（16 ビットは 8 ビットに丸める）。`x`・`y` のずれ、`defaultpixel`、透明マスク（`transparencymask`）は透明度に掛ける。フィルターレイヤー（2026-11-10）は、設定（`layerN.filterconfig` の `<param name>`）を読み、PSD の調整レイヤーと同じ道で、同じグループの下のレイヤーの画素に効かせる：反転（Krita と同じ）、彩度を下げる・レベル補正（古い形の黒・白・ガンマの値）・HSV 調整（HSV と HSL の種類、色彩の統一）・カラーバランス・ポスタリゼーション・2 階調化（近いだけ）。ほかのフィルター（チャンネルごとのカーブなど）は飛ばして警告。ベクター・塗りつぶし・クローン・ファイルのレイヤーは画素を持たないので飛ばして警告（`layerNoPixels`）。フィルターマスクなどは効かせずに警告。CMYK・浮動小数は飛ばして警告（`layerColorSpace`）。Krita 1 のファイルは読まない |
| Procreate（.procreate、2026-11-09） | ZIP の中の `Document.archive`（NSKeyedArchiver のバイナリ plist：`size`・`tileSize`・`unwrappedLayers`（上が先）・`SilicaLayer`・`SilicaGroup`）と、レイヤーごとのタイル `{UUID}/{列}~{行}.chunk`（LZO1X）か `.lz4`（Apple の `bv41` の LZ4）。乗算済みの RGBA をストレートに戻す。不透明度・非表示・合成（`extendedBlend` か `blend` の番号：通常・乗算・スクリーン・加算ほか）・クリッピング（`clipped`）・マスク（灰色 1 チャンネルのタイル、透明度に掛ける）・グループ。背景の色を出している時は一番下のレイヤーに。形式を作った会社の説明は無いので、公開の説明（silicate・mica の README）から書いた。タイルの行が下からか上からかは説明に無いので、ファイルの中の縮小画像（`QuickLook/Thumbnail.png`）と重ねた絵を比べて決める（逆なら `procreateRowsFlipped`） |
| Aseprite（.aseprite・.ase、2026-11-10） | 形式の説明（Aseprite の公開文書）をもとに読む。最初のコマのセル（zlib の物と圧縮なしの物）を、色の形（RGBA・グレー・パレット付き）から RGBA に。パレットは新しい塊、無ければ古い塊。パレット付きの透明の番号は背景のレイヤーでは透明にしない。レイヤーの入れ子（子の深さ）はグループ、合成（19 種。加算は add）、不透明度（ヘッダの印がある時だけ。グループは別の印）、非表示、セルの不透明度（透明度に掛ける）。読まない物は警告：2 コマ目から（`aseFrames`）、タグ（`aseTags`、名前とコマの範囲）、タイルマップ（`aseTilemap`）、参照のレイヤー（`aseReference`）、セルの z（`aseZIndex`）、正方形でない画素（`asePixelRatio`）。ピクセルアートなので「近い色で描く」を勧める（`aseNearest`、info）。`frames: 'animate'`（2026-11-10）：全部のコマを読み、タグごとに 1 本のアニメ（タグが無ければ全体で `frames` の 1 本）。レイヤーのセルの絵が違うコマは、そのレイヤーの名前のグループ（`groups[].frames = true`）の中の別パーツ `名前#コマ`（その絵が最初に出るコマ、1 から）になり、パーツの不透明度のキー（step）で出し入れする。リンクのセルと同じ画素の繰り返しは 1 つのパーツ。コマの長さ（ミリ秒）がキーの時刻、タグの向き（前・後・往復・逆の往復）と回数（0 はループ）も。基準の姿は最初のコマ。違う絵が `maxFrameParts`（既定 512）より多ければ最初のコマだけ（`aseFramesTooMany`） |
| SVG（.svg、2026-11-10、利用者の声 #14） | `importSvgAsync(text, opts)`（`tools/import_svg.mjs`）。一番上の要素 1 つが 1 パーツ（Inkscape のレイヤー `<g inkscape:groupmode="layer">` はグループで、中の要素 1 つずつがパーツ）。名前は Inkscape のラベル・`<title>`・id の順。各パーツは、図の `<defs>`・`<style>`（グラデーション・パターン・クリップ・マスクが効く）と親の transform・style と一緒に、キャンバスの大きさでブラウザの SVG の描き方のまま描き、PSD と同じ道（`importLayerStack`）でモデルにする。大きさの mm・cm・in・pt・pc は 1 インチ 96 px。非表示のレイヤー・要素は描いてから隠したパーツに。ファイルの外の絵は描かれない（`svgExternal`）、文字はこのコンピュータのフォント（`svgText`、info）、`<foreignObject>` は外す（`svgForeignObject`）。Node では `opts.rasterize(svg, w, h)` を渡す（テストは Chromium で描く）。エディタで .svg を開けるようにするのはエディタの担当 |
| PNG の組 | 1 枚 1 レイヤー。キャンバスは一番大きい絵の大きさ（キャンバスの大きさで書き出した PNG はそのまま重なる）。CLI はフォルダの PNG を名前の順（数字は数として）に下から積む。フォルダに `order.txt`（1 行 1 パス、レイヤーの一覧と同じく上が先）があればその順。PNG は全部の色の型・ビット数・インターレースを読む |

## PSD にレイヤーを 1 枚足す（`tools/psd_add_layer.mjs`、要望 5）

エディタで描いたマスクの絵を、絵描きの PSD にレイヤーとして書き戻すための関数。描く道具はエディタ。

```js
import { addLayerToPsd } from '../tools/psd_add_layer.mjs';
const out = addLayerToPsd(psdBytes, { name: 'マスク 目', left, top, width, height, rgba, opacity: 1, hidden: false, blend: 'normal' });
```

- 足したレイヤーは一番上（フォルダの外）の通常のレイヤーになる。8 ビット RGBA、RLE。名前は Unicode（`luni`）でも書く
- ほかは 1 バイトも変えない：ヘッダ・カラーモードのデータ・画像リソース・今のレイヤーの記録と画素・レイヤーの後のブロック・統合された絵
- 統合された絵（ファイルの最後）は書き直さないので、レイヤーを読まないアプリでは足したレイヤーが見えない。Photoshop・CLIP STUDIO はレイヤーから描く
- 断る物（`code` 付きのエラー）：`psdAddNotPsd`（PSD でない）、`psdAddDepth`（8 ビットでない）、`psdAddMode`（RGB でない）、`psdAddNoLayerInfo`（16・32 ビットのレイヤーの置き場。まだ書けない）、`psdAddNoLayers`（レイヤーの無い 1 枚の絵：足すと元の絵が隠れる）、`psdAddBadLayer`（画素の数が大きさに合わない）
- 確かめ（`tests/psd_add_layer_test.mjs`）：psd-tools が書いた PSD・クリッピングの PSD・フォルダのある PSD に足し、今のレイヤーがそのまま読めること、足したレイヤーが一番上に名前・不透明度・非表示・画素どおりにあること、レイヤーの外のバイトが同じことを、自前の読み込みと psd-tools（入っている時）で確かめる。2 回足すこともできる

## PSD のレイヤーの画素を置き換える（`replaceLayerPixels`、`tools/psd_add_layer.mjs`、2026-11-08）

エディタの「軽い描き足し」で描き直した画素を、絵描きの PSD の元のレイヤーへ書き戻すための関数。

```js
import { replaceLayerPixels } from '../tools/psd_add_layer.mjs';
const notes = [];
const out = replaceLayerPixels(psdBytes, '顔/目', { left, top, width, height, rgba }, { inflate, notes });
// 'フォルダ/名前'・['フォルダ', '名前']・{ index }（フォルダを数えない下からの番号。importPsd の layers と同じ）
```

- 箱（キャンバスの座標、ストレートアルファ）の中の画素がレイヤーの画素の代わりになる（透明な画素は消す）。箱の外のレイヤーの画素はそのまま。箱がレイヤーの外へ出る時はレイヤーを広げる
- そのレイヤーの記録のほか（名前・不透明度・塗り・合成・クリッピング・表示・マスクとそのデータ・ブロック全部）と、ほかのレイヤー・フォルダ・リソース・後ろのブロックは 1 バイトも変えない。画素は RLE で書き直す（ZIP だったレイヤーは `opts.inflate` で開いてから）
- 統合画像（ファイルの最後）は、レイヤーの前と今の範囲の中だけ、レイヤーから描き直す（外は Photoshop が書いた画素のまま）。通常と分けられる合成モード（乗算・スクリーン・加算・覆い焼き・焼き込み・オーバーレイ・ソフトライト・ハードライト・比較・差・除外・減算・除算）、不透明度、クリッピング（Photoshop の既定「クリッピングしたレイヤーをグループとして描く」）、フォルダ（通過以外は分けて描く）、レイヤーとフォルダのマスク。Photoshop と同じく、透明がある所は白の上に描いた色で書く。調整レイヤー・レイヤー効果・色相などの合成は描かない
- **効果を外す**（`dropEffects: true`、2026-11-10）：読み込みは効果（影・境界線・光彩など、`tools/layer_effects.mjs`）を画素に描き込むので、その画素をそのまま書き戻すと Photoshop が効果をもう一度描いて二重になる。`dropEffects` で、そのレイヤーの効果のブロック（`lfx2`・`lrFX`・`lmfx`）を外して書く（ほかのブロックとほかのレイヤーはそのまま）。見た目は書き戻す前と同じ。`opts.notes` に `psdEditEffectsDropped`（外したブロックの名前）。確かめ（`tests/psd_effects_test.mjs`）：境界線の付いたレイヤー（`lfx2`・`lmfx`）の描き込んだ画素を書き戻すと、読み直したレイヤーは渡した画素と同じ（差 0）で効果が無く、ほかのレイヤーの効果は残る。外さないと境界線がもう一度描かれる（26 px が 36 px に）。psd-tools でも開ける
- マスクが箱の外を全部隠すレイヤー（psd-tools が書く PSD は全部のレイヤーがそう）は、マスクの外へ描いた画素は見えない。その時 `opts.notes` に `psdEditMaskHides` を入れる（マスクは変えない）
- マスクで割って戻す（`unmask`、既定で入）：渡す画素は importPsd が見せる形（レイヤーのマスク・ベクトルマスク・フォルダのマスクを透明度に掛けた後）と考え、マスクが見せる割合で透明度を割ってから書く。Photoshop がマスクを掛けると渡した画素どおりに見える。マスクが全部隠す所（0）は元のレイヤーの画素を残す。`unmask: false` で渡した画素をそのまま書く。マスクの割合は `psdMaskCoverage(bytes, index, box)`（`tools/import_psd.mjs`）で、読み込みと同じ掛け方
- 断る物（`code` 付きのエラー）：`psdEditNotPsd`、`psdEditDepth`（8 ビットでない）、`psdEditMode`（RGB でない）、`psdEditNoLayerInfo`（レイヤーの無い PSD・16 / 32 ビットの置き場）、`psdEditNoLayer`（その名前のレイヤーが無い）、`psdEditAmbiguous`（同じ道の名前が 2 つ以上：`{ index }` で）、`psdEditKind`（文字・スマートオブジェクト・塗りつぶし・調整レイヤー：画素は別のデータから作られる。描画アプリでラスタライズしてから。フォルダはレイヤーとして数えないので `psdEditNoLayer`）、`psdEditBadPixels`、`psdEditNeedsInflate`
- 確かめ（`tests/psd_replace_test.mjs`）：psd-tools が書いた PSD（`face.psd`・`clip.psd`）と、フォルダ・クリッピング・乗算・スクリーン・非表示のある PSD で、レイヤー自身の画素（マスクを掛けない）が「前の画素の上に箱」と一致、ほかのレコードとデータが同じバイト、マスクのチャンネルが同じバイト、統合画像は範囲の外が同じで中が描き直されている。psd-tools（入っている時）がレイヤーを読み、psd-tools 自身がレイヤーから描いた絵と新しい統合画像が範囲の中で ±1。ImageMagick（入っている時）もレイヤーの数と大きさ・位置どおりに読む。PSB（8 バイトの長さ）でも同じ PSD と同じレイヤーと統合画像になる
- Photoshop・CLIP STUDIO・Krita そのもので開くのは、ここではできない（PC での確かめ待ち）

### アトラスから PSD の画素へ戻す（`layerPixelsFromAtlas`、`tools/import_psd.mjs`）

エディタで描き足したアトラスの絵を、`replaceLayerPixels` に渡せる形にする。

```js
import { layerPixelsFromAtlas } from '../tools/import_psd.mjs';
const back = layerPixelsFromAtlas(meta, atlasPage, { scale });     // meta：importPsd の layers[i]（または保存した layerMeta）
const out = replaceLayerPixels(psdBytes, { index: meta.psdIndex }, back, { inflate });
```

- アトラスのページ（`{ width, height, rgba }`、ストレート）から、レイヤーの範囲（絵＋縁）を取り出し、PSD の座標の `{ left, top, width, height, rgba }` で返す
- 90° 回して詰めた絵は元の向きに戻す（画素そのまま）。角度を付けて詰めた絵（`atlasAnyAngle`）と、大きい PSD を縮めて読んだ絵（`scale` < 1）は、元へ戻す時に描き直す（双線形、色は透明度で重み付け）ので、縁が少しぼける
- importPsd の `layers[i].psdIndex`：そのレイヤーの PSD の中での番号（フォルダは数えない、下から。空・調整・読めないレイヤーも数える）。`replaceLayerPixels` の `{ index }` にそのまま渡せる。古い文書の layerMeta には無いので、その時は `path` で
- マスクのあるレイヤー：読み込みはマスクを透明度に掛けて取り込むので、戻した画素にはマスクが入っている。`replaceLayerPixels` は既定でマスクで割って戻す（下の節）ので、そのまま渡してよい
- 確かめ（`tests/psd_atlas_back_test.mjs`）：読み込み → 取り出し → 置き換え の往復で、そのままと 90° 回した絵は画素が一致。角度を付けた絵は透明度の差の平均 3.5、50 % で読んだ絵は 11 以下（縁が 2 px ぼけるだけで、中心はずれない）。空のレイヤーを飛ばしても `psdIndex` が PSD の番号どおり

## モデルの大きさを変える（`tools/scale_model.mjs`）

違う大きさの PSD でモデルを作ってしまった時に、メッシュ・格子・骨・キーを作り直さずに、モデル全体を k 倍にする。大きさの違う PSD を読み直す時に「合わせて縮める」を出すのはエディタ。

```js
import { scaleModel } from '../tools/scale_model.mjs';
const m2 = scaleModel(model, 0.5); // 新しいモデル（元は変えない）
```

- k 倍する物（px を持つ物）：キャンバス（大きさと原点）、頂点、差分（morphs）、骨の x・y・長さ、transform の制約の x・y、ワープ格子の rect と動き、アニメの骨の x・y、鎖の重力（px/秒²）、エディタの球・円柱の形（`editor.shapes` の center・radius）
- そのままの物：角度、拡大、せん断、UV、重み、不透明度、色、パラメータ、時間、ばねの強さと減衰、のりの組
- モデルの (0, 0) は動かないので、描いた絵は同じ絵を (0, 0) から k 倍にした物になる
- `source`（読み込みの記録）は変えない。読み直す PSD の大きさをどう扱うかは、エディタが決める
- 確かめ（`tests/scale_model_test.mjs`）：
  - k 倍して 1/k 倍すると元に戻る（0.5 は完全に同じ、0.37 は 1e-13 以内）
  - 4 つのモデル（下書き入りの PSD のキャラ、格子の見本、IK・transform・鎖の骨組み、Spine の取り込み）について、k = 0.5・0.37・2.5 で、パラメータとアニメの姿の頂点がどれも元の k 倍の所に来る
  - k = 0.5 の差は 0。ほかの k でも、.ug9 の値の丸め（幅の 65535 分の 1）の分だけ

## 絵の形で詰め直す（`tools/repack_atlas.mjs`、2026-11-10、機能の比べ #16・利用者の声 #56）

できたモデルのアトラスを、四角でなく絵の形で詰め直す。各パーツが描く三角形の届く画素（の周りの余白込み）を形として、その形どうしがぶつからない所へ置く（輪の内側に L 字が入る、など）。画素はそのまま動かすか 90° 回すだけで、描き直さない（ぼやけない）。UV だけが変わる。

    node tools/repack_atlas.mjs model.json --out 先 [--padding 2] [--cell 4]

- 詰め直して小さくならない時（ほぼ四角の絵が、もう四角でぎっしり詰まっている時）は、元のまま（`kept`）
- 同じ絵を描く複数のパーツ（Spine のスロットの写しなど）は 1 つにまとめて置く
- `--cell`：置き場を探す目の細かさ（既定 4 px。2 は少し詰まるが数倍遅い）
- PSD・Spine・どこから作ったモデルにも使える（アトラスは作業用 JSON の textures）
- 効き目（2026-11-10 に測った）：
  - 輪・L 字・斜めの帯の試しの PSD（12 枚、読み込みは四角で詰める）：378,368 px → 311,296 px（82%）
  - `tests/psd/face.psd`（ほぼ四角の絵）：小さくならず、元のまま
  - 提供の Spine のキャラ 6 体（Spine が詰めたアトラス、確かめだけに使用）：2 体は 69〜77% に、1 体はほぼ同じ、3 体は大きくなる（元のまま）。どのアトラスにも、どのパーツも使わない画素は無かったので、小さくなった分は詰め方の差。時間は 1 体 0.6〜6 秒（--cell 4）
- 確かめ（`tests/repack_atlas_test.mjs`）：上の試しの PSD で 82%、メッシュは同じ、ugo_export で描いた絵が前と同じ（差は最大 1）、全部の絵を 90° 回しても同じ、ほぼ四角の PSD は元のまま、同じ絵の 2 つのパーツは 1 つに

## 大きな PSD とアトラスのページ

- アトラスは 1 ページ 4096×4096 まで（`maxAtlasSize` で変えられる）。入りきらない時はページを増やし、`model.textures` を `atlas.png`・`atlas_2.png`… にする（実行時は 1 回の描画のまま、最大 64 ページ）。結果の `atlases` が全部のページ、`atlas` は 1 ページ目。`layers[i].atlas.page` がそのレイヤーのページ（1 ページ目は書かない）。`meshFromLayer` には `atlases` を渡すとページを選ぶ
- 4000×4000・40 レイヤー（51 MB）の PSD で 7 秒（前は 16 秒。透明な所に色を広げる処理を、各絵の周りだけにした）。描いた絵は psd-tools が重ねた絵と一致
- **大きなキャンバス**：縦か横が 4080 px を超えるキャンバスは、4080 px に収まるよう縮めて読む（お知らせ `psdScaledDown`。モデルは縮めた後の px になり、結果の `scale` が倍率）。キャンバスいっぱいの背景でも 4096 のアトラスの 1 ページに入る。縮める時は、新しい 1 画素が覆う元の画素の面積で平均する（透明度を掛けて平均するので、縁が黒ずまない）。`maxCanvas` で上限を変えられ、0 なら縮めない。読み直しでは、最初の読み込みの `scale` を `opts.scale` に渡すと同じ倍率で読む（キャンバスの大きさが変わっても、モデルとずれない。1 なら縮めない）
- **大きな絵のメッシュ**：縦か横が 48 × 24 px を超える絵は、点の間隔を広げて 48 マスほどに収める（お知らせ `meshCoarser`。`maxCells` で変えられる）。点が多すぎると三角形分割に時間がかかりすぎるため（8000 px の背景は 24 px 間隔だと 11 万点）。広げた時は、絵を q×q 画素のかたまりに縮めた写しで輪郭を取る（1 画素でも不透明なら不透明）ので、作るのも q² 倍速い
- 読み込む時、各レイヤーは不透明な所の外接矩形に切り詰めてから持つ（キャンバスの大きさで保存されたレイヤーでもメモリを食わない）

直した所（重かった順）：
- 三角形分割（Bowyer-Watson）：点ごとに全部の三角形を調べていたのを、外接円が重なる格子のマスの三角形だけ調べるようにした。三角形には作った順の番号を付け、生きている物を番号順に並べるので、前と同じ三角形が同じ順で出る。辺の鍵も文字列から数に
- 輪郭の点：角の数え方を、まわりに 0 を 1 周足したマスクで 1 回の走査に。点どうしの距離を見る表を、文字列の鍵の Map から配列のマスに
- 覆い方の確かめ：不透明な画素だけ調べる
- 膨らませる処理（マスクを margin だけ広げる）：画素ごとに幅の分だけ書いていたのを、最後に見た画素を覚えて 1 回で。縦は行の順に
- 透明な所に色を広げる処理：2 回目からは、前の回に塗った画素の隣だけ見る
- 色の並べ替え（チャンネル → RGBA）：色の方式ごとの 1 本のループに。RGB は 4 バイトを 1 回で書く
- 不透明な所の外接矩形：上下の行を先に決め、横は今の箱の外だけ見る。格子のメッシュ：列のマスの番号を先に計算
- RLE の展開：繰り返しは `fill`、そのままの所は `set` で
- 縮める処理：列ごとの足し先を先に並べ、行の足し場を使い回す

8000 px の残りは、ほとんどが縮める処理（キャンバスいっぱいの背景、6400 万画素を面積で平均する）。同じ処理だけを取り出すと 1.9 秒だが、PSD を読んだ後（メモリを 700 MB 使った後）だと 4 秒かかる。

## アトラスのページの大きさ（`atlasPage`、2026-11-10、機能の比べ #16・利用者の声 #56）

`importPsd(bytes, { atlasPage })`（Krita・OpenRaster・Procreate・Aseprite・PNG の読み込みも同じ）、コマンドは `--atlas-page tight|pow2|square`。

- `tight`（既定、今まで通り）：絵が要るだけの大きさ（幅は 2 の累乗か上限、高さは使った所まで）
- `pow2`：縦横とも 2 の累乗に広げる。`square`：2 の累乗の正方形に広げる（そういう大きさを求めるエンジン・古い GPU 向け）
- 絵の置き場は変わらず、広げた所は透明。UV はページの大きさに合わせて変わるので、どの点も同じアトラスの画素を取る
- 余白は `padding`（既定 2、コマンドは `--padding`）、ページの上限は `maxAtlasSize`（`--max-atlas`）
- 縁の色の押し出し（extrude）は要らない：どの絵も透明な縁（margin）を持ち、その色は絵の縁から広げてある（bleed）ので、絵の縁がアトラスの隙間に触れることがない
- 知らない値は `tight` にしてお知らせ `atlasPageUnknown`
- 多角形で詰める（絵の形に沿って詰める）は後で
- 確かめ（`tests/atlas_page_test.mjs`）：既定は前と同じ、`pow2` で 256×72 が 256×128、`square` で 256×256、どの点（108）も同じアトラスの画素、`padding 6`、知らない値、コマンド

## とても大きな PSD（2026-11-01）

PC の確かめで、7500×7300・291 レイヤー・136 MB の PSD をデスクトップ版で開くと落ちた（WebView2 が STATUS_BREAKPOINT）。Node では全レイヤーの元の大きさの画素を 1.46 GB 持ち、最大 2.1 GB、73.5 秒だった。直したこと：

- **1 レイヤーずつ縮める**：縮める PSD では、各レイヤーを展開したらすぐ切り詰めて縮め、元の大きさの画素は次のレイヤーの前に手放す。全部の元の画素を同時に持たない
- **PSD を 1 回だけ読む**：ブラウザの `importPsdAsync` は、ZIP のチャンネルを展開しながら 1 回で読む（`readPsdAsync`）。読み直しの `reimportPsdAsync` も同じ
- **チャンネルから直接縮める**：マスクの無い RGB のレイヤーは、RGBA に並べ替えずに R・G・B・A のチャンネルから縮める
- **縮める処理を速く**：新しい 1 列ごとに、元の列と重みの表を先に作り、足し算を変数の中で済ませる（倍精度）
- **アトラスはページごとに**：ページは最初に絵を置く時に作り、絵はアトラスに置いたらすぐ手放す（縮めた時。`keepPixels: false` でも）
- 縮めた PSD のメッシュは点の間隔を 2 倍にする（縮めた後の絵は小さく、点が多すぎるため）
- **メッシュを作らない**：`mesh: 'none'` なら、各パーツは絵の四角（アトラスに置いた範囲、4 点）で入る。メッシュは後で作る（エディタの「メッシュを作る」）。読み込みのメッシュの時間が省ける
- **途中経過**：`opts.onProgress({ step, done, total })` を、各レイヤーを読む前（`step: 'read'`）と、各絵をアトラスに置いてメッシュを作る前（`'mesh'`）に呼ぶ。それぞれの最後に `done === total` でもう 1 回。エディタが「読んでいます… 12 / 291」と出すのに使う

縮めない PSD の結果は前とバイト単位で同じ（`tests/psd/` の 7 つの PSD と 3000 px の合成の PSD で、モデル・アトラス・レイヤーの画素・notes のハッシュが一致）。縮める PSD は、縮め方の丸めとメッシュの点の間隔が変わる。

測った値（合成の PSD：7500×7300・ぼかした丸 300 枚・110 MB。`node tests/psd/make_big.mjs 7500 7300 300 build/psd_big/7500.psd`。この開発の機械は、PC の確かめの PC より 1.7 倍ほど速い）：

| | 前 | 後 |
|---|---|---|
| Node 22 `importPsd` | 44 秒・最大 3.0 GB | 16〜19 秒・最大 1.0〜1.4 GB |
| Chromium `importPsdAsync`（`tests/psd_big_browser_test.mjs`） | 45.5 秒・ページの最大 2.9 GB | 17.2 秒・ページの最大 1.17 GB（読んだ PSD の 110 MB を含む） |

### レイヤーを Worker で並べて読む（`importPsdParallel`）

```js
const r = await importPsdParallel(bytes, opts, run); // 結果は importPsdAsync と同じ
// run(job) -> Promise: job を Worker に送り（job.bytes は transfer できる）、Worker で decodePsdLayer(job) の結果を返す
```

- メインのスレッドは PSD の頭とレイヤーの記録だけを読み、レイヤーごとに仕事（`job`：そのレイヤーのチャンネルのバイトの写し・記録・フォルダのマスク・倍率・メッシュの設定）を作る。PSD を読むのは 1 回
- Worker の `decodePsdLayer(job)` が、展開（ZIP は DecompressionStream）・マスク・切り詰め・縮める・残す箱・メッシュ（アトラスの位置に関係しない所）までする。返す `rgba` は transfer できる
- メインのスレッドに残るのは、アトラスに詰める・置く・透明な所に色を広げる・メッシュの uv
- 同時に出す仕事は `opts.maxInFlightBytes`（既定 512 MiB、元の大きさの画素で数える）まで。1 枚でこれを超えるレイヤーは、ほかの仕事が無い時に 1 枚だけ出す
- `onProgress` の `'read'` は、仕事が戻るたびに呼ぶ
- `run` を渡さない時は、メインのスレッドで 1 枚ずつ読む（結果は同じ）
- transfer できる物：仕事では `job.bytes`（ArrayBuffer 1 つ。そのレイヤーのチャンネル全部）だけ。`job.folders` のフォルダのマスクは何枚ものレイヤーで同じ物なので写す。結果では `rgba.buffer` だけ（長さ 0 でない時）
- Worker を作り、何本にするかを決めるのはエディタ（`navigator.hardwareConcurrency - 1`、4 本まで）。テスト用の Worker は `tests/psd/layer_worker.mjs`（Node の worker_threads）と `tests/psd/layer_worker_web.mjs`（ブラウザ）
- 結果が importPsd とバイト単位で同じことを `tests/psd_parallel_test.mjs`（CI）で確かめている。PSD は `tests/psd/` の 7 つ、5000×4000 の縮める PSD、読めないレイヤー・CMYK・全部のレイヤーが読めない PSD。ほかに、仕事が同時に出ること、`maxInFlightBytes` の上限、途中経過も確かめる

## 動かした姿を PSD に書き出す（`tools/export_pose_psd.mjs`、2026-11-10）

ポーズ（パラメータの値、アニメのある時刻）か、アニメの各コマを、芯（`ugo_export`）で描いて PSD のレイヤーにする。描き足す時や、ほかのアプリへ渡す時に。

    node tools/export_pose_psd.mjs model.ug9 --out pose.psd [--by part|group|whole] [--depth N]
      [--param AngleX=20 ...] [--anim idle [--frames N] [--fps F] [--start 秒]] [--pad P] [--ss N]

- `--by part`（既定）：パーツごとのレイヤー（描画順）。パーツの合成（乗算・スクリーン・加算）はレイヤーの描画モードにする。今は見えないパーツ（目を開けている時の閉じた目）も空のレイヤーとして入る
- `--by group`：取り込んだ PSD のフォルダごと（作業用 JSON の `source.psd`。`--depth` で何段目まで）。フォルダの無いパーツはそれぞれ 1 枚。フォルダの中の合成は描き込む。`source.psd` が無い（.ug9 から）時はパーツごとにしてお知らせ
- `--by whole`：モデル全体を 1 枚
- `--anim` と `--frames`：コマごとにフォルダ（`idle 000`…、`--by whole` ならコマごとのレイヤー）。初めのコマだけ見え、ほかは隠す
- 各レイヤーは、そのパーツだけを芯で描いた絵（ほかのパーツは描かないが、マスクとしては効く）。キャンバスの場所に置き、描いた所だけに切り詰める。統合した絵（それしか読まないアプリ用）は初めのコマを白の上に
- `--anim` の無い時は、アニメを外して描く（パラメータは既定の値か `--param`）。物理は ugo_export と同じ（1 周ぶん先に動かす）
- 8 ビット RGB、レイヤーは RLE。PackBits と描画モードの表は `tools/psd_add_layer.mjs` の物を使う
- PSD を書く部分は `tools/psd_write.mjs`（Node の API を使わず、ブラウザでも動く。エディタの書き出しの窓用）：`writeLayeredPsd(幅, 高さ, items, merged)` と `trimLayer(rgba, 幅, 高さ)`。items の形はそのファイルの頭に
- 確かめ（`tests/export_pose_psd_test.mjs`）：見本を AngleX 20・口を開けた姿で。パーツの 16 枚を重ねると、全体を 1 枚で描いた絵と最大 11/255（縁）・平均 0.007 で同じ。黒目の 1,244 画素がどれも白目の中（マスクが効く）。顔が動き口が開く。idle の 2.0 秒からの 4 コマで 4 フォルダ × 16 枚、初めは目が開き後で閉じる、初めだけ見える。フォルダごと（1 段・2 段）、合成の描画モード。psd-tools でもフォルダ・見え方・統合した絵が読めることを確かめた。`tools/psd_write.mjs` を Chromium の中で動かして書いた PSD（切り詰めたレイヤー・乗算・不透明度 50 %・隠したフォルダ）がこちらで読める

## 読めない物・壊れた PSD

読めない所は止まらずに飛ばし、何を飛ばしたかを code 付きの notes で知らせる（一覧は `docs/警告の一覧.md`）。

| 物 | 扱い |
|---|---|
| レイヤーの無い PSD（1 枚の絵） | 重ねた絵（ファイルの最後の合成画像）を 1 つのパーツ `image` にする（お知らせ `psdFlatImage`） |
| CMYK | RGB に簡単に直して読む（色のプロファイルは使わない。`psdCmyk`） |
| グレースケール・ダブルトーン | 灰色として読む |
| インデックスカラー（レイヤーは無い） | パレットで色にして、重ねた絵を 1 つのパーツにする |
| 1 枚のレイヤーの画素が読めない（知らない圧縮・壊れたデータ） | そのレイヤーだけ飛ばす（`layerUnreadable`） |
| レイヤーの記録が壊れている・途中で切れている | レイヤーは読まず、重ねた絵があればそれを読む（`psdLayersBroken`） |
| キャンバスの外にはみ出したレイヤー | そのまま読む（はみ出した所も） |
| 読めない PSD（PSD でない・32 ビット・ビットマップ・Lab・マルチチャンネル・ヘッダーで切れている） | `code` と `vars` の付いたエラーにする（`psdNotPsd`・`psdVersion`・`psdDepth`・`psdMode`・`psdTruncated`）。エディタはそれで文を作る |

## レイヤーの種類

| 種類 | 扱い |
|---|---|
| 調整レイヤー（2026-11-09〜） | 反転・レベル補正・トーンカーブ・色相・彩度・カラーバランス・明るさ・コントラスト・ポスタリゼーション・2 階調化・露光量・グラデーションマップ・白黒・レンズフィルターは、届くレイヤーの画素に効かせてから取り込む（下の節）。チャンネルミキサー・特定色域の選択・自然な彩度・カラールックアップは読まない（警告）。`bakeAdjustments: false` で前のとおり全部飛ばす |
| 文字・スマートオブジェクト・塗りつぶしレイヤー | PSD が持っている画素の絵として読む（警告） |
| レイヤー効果（2026-11-10〜） | ドロップシャドウ・光彩（外側）・境界線（単色、外側・内側・中央）・カラーオーバーレイ・シャドウ（内側）・光彩（内側）は、レイヤーの絵に描き込んでから取り込む（絵の箱は効果の分だけ広がる。`tools/layer_effects.mjs`）。'lfx2'・'lmfx'（同じ種類を複数）を読む。境界線は画素ちょうど。影と光彩のぼかしは 3 回の箱ぼかしで近いだけ、ノイズ・輪郭（等高線）は描かない。レイヤーの下に置く効果（影・外側の光彩）を乗算などで指定しても、パーツの中では通常で描く（`layerEffectsPainted` の `close`）。塗り（fill）はレイヤー自身の画素だけを薄くし、効果は薄くしない。べベルとエンボス・サテン・グラデーションとパターンのオーバーレイ・グラデーションの境界線は描かない（`layerEffectsSkipped`）。読めない効果の記録は前のとおり `layerEffects`。`bakeEffects: false` で前のとおり描かない。描き込んだパーツは `layers[].effects` に効果の名前が入る（描き直して PSD に書き戻すと、Photoshop が効果をもう一度描く） |

## 調整レイヤーを効かせる（`tools/adjustments.mjs`、2026-11-09）

調整レイヤーの設定（PSD の `nvrt`・`levl`・`curv`・`hue2`・`blnc`・`brit`・`CgEd`）を読み、届くレイヤーの画素を変えてから取り込む。形式は変わらない。お知らせ `layerAdjustmentBaked`（info：種類・変えたレイヤーの数・Photoshop と同じか近いだけか）。

- 届く範囲：クリッピングした物はそのクリッピンググループ（土台と、下のクリッピングしたレイヤー）。そうでない物は、同じフォルダの中の下のレイヤー全部（通過のフォルダならその外の下まで）
- 調整レイヤーのマスク・ベクトルマスク・フォルダのマスクと不透明度の分だけ効かせる
- レイヤーごとに効かせる（重ねた絵にではない）。半透明に重なる所で非線形の調整（色相・彩度、トーンカーブなど）は少し違う。重ならない所・不透明な所は同じ。動かしても継ぎ目は出ない（各パーツが変えた色を持つ）
- 同じ（exact）：反転、レベル補正（チャンネル→マスターの順、ガンマ）、トーンカーブ（自然 3 次スプライン、psd-tools と同じ）、色相・彩度のマスターと色彩の統一（HSL：明度を先に、0〜255 の幅の直線で切り捨て（+25 で黒が 63）、色相は回すだけ、彩度は上げ 1/(1−a)・下げ 1+a。式の形は別の調べから。彩度は丸めで 1〜2 ずれる所がある）。近いだけ（お知らせに書く）：色相・彩度の色の範囲ごとの設定、カラーバランス、明るさ・コントラスト
- 残りの種類（2026-11-10）：ポスタリゼーション（`post`）・2 階調化（`thrs`、輝度 0.3/0.59/0.11）は psd-tools と同じ式。露光量（`expA`）は sRGB をガンマ 2.2 として線形で掛ける（psd-tools と同じ近似）。グラデーションマップ（`grdm`：色の分岐点・中間点・反転。輝度で色を選ぶ）・白黒（`blwh` の記述子：6 色の割合・着色）・レンズフィルター（`phfl`：色と濃度、輝度を保つ）は近いだけ
- 確かめ（`tests/psd_adjust_test.mjs`）：反転は 255 − v と一致。レベル補正は psd-tools の絵と平均 0.75・最大 ±6（psd-tools は途中を小数で持ち最後に切り捨て、こちらは 8 ビットの Photoshop のように段ごとに整数の表）。トーンカーブの直線の時は計算どおり、3 点の時は真ん中の点を通る。色相 180° で赤が水色、彩度 −100 で灰色、色彩の統一で暖かい色。カラーバランスで中間調を赤へ。明るさ（旧式）+20 で 20 足す。フォルダの中・クリッピング・不透明度 50 % の届き方。psd-tools はトーンカーブ・明るさ・コントラスト・色相・彩度の描画に scipy が要り、ここには無いので、それらは psd-tools と並べていない（PC 確認で）。ポスタリゼーション・2 階調化は psd-tools と ±0、露光量は最大 ±1（平均 0.40）。グラデーションマップは白黒の時に灰色のまま・2 色の時に両端と真ん中、反転。白黒は既定の割合で赤 102・緑 102・青 51・黄 153・灰はそのまま。レンズフィルターは濃度 0 で変わらず、100 % で色を掛ける

## アトラスを 1 枚ずつの絵に戻す（`tools/unpack_atlas.mjs`、2026-11-10）

読み込んだ後のモデル（作業ファイルとアトラス）から、パーツごとの PNG と、PSD のレイヤーのような重ね順の一覧（`layers.json`）を作る。描き直し・別のアプリへ渡す時に。

    node tools/unpack_atlas.mjs model.json --out build/parts [--linear] [--scale K]

- 各パーツのメッシュを初めの形でキャンバスの画素に描き、色は UV でアトラスから取る。回して詰めた絵・斜めに詰めた絵も、キャンバスの元の向き・場所に戻る
- 既定はアトラスの画素をそのまま（最近傍）。`--linear` で滑らかに。`--scale` で大きさを変える
- `layers.json`：キャンバスの大きさと、重ね順（初めが一番奥）の一覧。パーツ・ファイル名・場所（モデルの座標 `left`/`top` とキャンバスの画素 `canvasLeft`/`canvasTop`）・大きさ・不透明度・合成・マスク専用・PSD のフォルダ（`folders`、外側から。エディタが残す `source.psd.layers` から）
- 箱はメッシュの周りの数画素の余白を含む
- ワープ・ウェイトの付いたパーツは、モデルに書いたメッシュの形（初めの形）で出す
- 確かめ（`tests/unpack_atlas_test.mjs`）：画素ごとに違うグラデーションの PSD を、90° 回して詰めた時・どの角度でも詰めてよい時に読み、戻した各パーツの内側が元のレイヤーの画素と全部同じ（差 0）。重ね順と場所

## まだ（警告が出る）

- 乗算・スクリーン・加算以外の合成モード（オーバーレイ・ソフトライトなど）は通常として描く。フォルダの合成モード（通過以外）も使わない
- クリッピングの土台の不透明度は、クリッピングしたレイヤーには掛からない（Photoshop ではかかる）
- フォルダを土台にしたクリッピングは、フォルダの中のレイヤーの形を合わせた物の中に描く（中のレイヤーの不透明度やフォルダのマスクの濃さは掛からない）。画素のレイヤーが 1 枚も無いフォルダ（記録だけのフォルダ）は土台として見えないので、その下のレイヤーが土台になる
- 32 ビット（エラーで知らせる）。CMYK は色のプロファイルを使わずに直すので、少し色が違うことがある

## 確かめたこと（`tests/psd_test.mjs`）

メッシュ：輪（穴あき）・細い斜めの線・散らばった点・くし形・1200×900 の大きい形で、不透明な画素が全部覆われることを確かめた（大きい形で頂点 1,589、覆う面積は不透明な所の 1.01 倍、0.16 秒）。


別の実装（psd-tools 1.26）で書いた PSD（`tests/psd/face.psd`、作り方は `make_psd.py`）を読み、psd-tools が読む各レイヤーの名前・グループ・位置・画素（マスク込み）・不透明度が全部一致。モデルを `ugo_export` で描いた絵は、レイヤーを手で重ねた絵と画素単位で同じ（差 0）。Chromium でも `importPsdAsync` で読み、全レイヤーの画素が一致（ZIP はブラウザの DecompressionStream で展開）。

読み直し：`face_v2.psd`（顔を塗り直して 3 px 右へ、頬を消し、口を足した物）で、消えたレイヤー・足したレイヤーを見分け、変わっていない絵は全部の頂点の下の色が前と同じ、動いた顔は範囲の外に出た頂点を数えて警告することを確かめた。

合成の焼き込み（`tests/psd_blend_bake_test.mjs`）：土台に 6 つの合成（乗算・オーバーレイ・ソフトライト・覆い焼きカラー・色相・差）をクリップした PSD で、焼いた土台と、psd-tools がその 7 枚を描いた絵が、透明度 ±0・色 ±1（2801 画素のうち 3 を超える差は 0）。上のスクリーンと別の土台の乗算はパーツのまま。

フォルダへのクリッピング（`psd_robust_test`）：フォルダのすぐ上でクリッピングしたレイヤーは、フォルダの中のクリッピングしていないレイヤー全部が `mask` になり、フォルダの中のクリッピングは自分の土台のまま。中に何も描かれていないフォルダなら不透明度 0。`clipping: false` では `mask` もクリッピングの警告も無い。

クリッピングと合成：`clip.psd`（肌に乗算の影とスクリーンの光をクリッピング、加算の光、フォルダの中のクリッピング、下に何も無いクリッピング）で、`ugo_export` で描いた絵が Photoshop の式（クリッピングは土台の透明度を掛ける、乗算・スクリーン・加算）で手で重ねた絵と一致（差は最大 0.4/255）。

16 ビット・ベクトルマスク・フォルダのマスク：`face16.psd`（psd-tools で作成）の各レイヤーが psd-tools の読みと一致し、同じレイヤーを `Lr16` に移した形でも同じ。`vector.psd`（円のベクトルマスク）は本当の円の面積の割合と比べて差 11/255 以内（psd-tools はパスを粗く塗るので比べる相手にしない）。`folder_mask.psd` はフォルダのマスクの白い所だけに中のレイヤーが残る。
