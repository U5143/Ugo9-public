# 動画の書き出し（`web/encoders.js`）

エディタの書き出しの窓とランタイムの見本（`web/index.html`）が使う、ブラウザだけで動く書き出し。外の道具（ffmpeg など）は使わない。

## 1 コマずつ書く（`createWriter`、2026-11-09）

```js
import { createWriter, WRITER_FORMATS } from '../web/encoders.js';
const w = await createWriter('webm-alpha', 3840, 2160, 29.97);  // 形式、幅、高さ、fps
for (const rgba of frames()) await w.add(rgba);                 // 1 コマ（ストレートアルファの RGBA）ずつ
const blob = await w.finish();                                  // w.extension：'zip' | 'webm' | 'mp4' | 'mov'
```

コマを全部持たずに書くので、4K や長い動画でもメモリが足りる（全部のコマを持つ `encodeAll` は 4K・30 fps・10 秒で約 10 GB 要る。こちらは縮めた後のデータと十数コマだけ）。

| 形式 | 中身 | 透明 | 読めるアプリ |
|---|---|---|---|
| `png-zip` | 透過 PNG の連番（`frame_00000.png`…）を 1 つの ZIP に（4 GB を超えると ZIP64） | ○ | どれでも（After Effects・Premiere・DaVinci・Blender は連番を読む） |
| `mov-png` | QuickTime（.mov）に PNG のコマ。劣化なし | ○ | After Effects・Premiere・Final Cut・ffmpeg |
| `webm-alpha` | VP9。色と透明度を 2 本の VP9 に分け、透明度は各ブロックの付け足し（BlockAdditional）に入れる（WebM の透明の持ち方） | ○ | Chrome・Firefox・OBS・ffmpeg（libvpx） |
| `webm` | VP9 か VP8。背景の色の上に描く | × | ブラウザ・動画アプリ |
| `mp4` | H.264。背景の色の上に描く | × | どれでも |

- fps は何でも（24・30・60・25・29.97・23.976…）。29.97 などは 30000/1001 の時間で書く
- 幅・高さが奇数の時、`webm`・`webm-alpha`・`mp4` は偶数に足して書く（足した 1 列・1 行は背景か透明）
- WebCodecs が使えないブラウザでは `webm`・`webm-alpha`・`mp4` はエラー。`png-zip`・`mov-png` はどこでも
- **ファイルへ流す**（`opts.sink`、2026-11-12、進行の #391 の 2）：`png-zip`・`mov-png` は、ふつうはできた PNG を全部持ってから 1 つの Blob にする（1080p の透過で 1 コマ数百 KB〜1 MB、長いと GB）。`opts.sink` を渡すと、PNG ができた順にファイルへ書き、持つのは縮めている途中の 16 コマほどだけ。`fileSink(handle)` が、`showSaveFilePicker()` で選んだファイル（File System Access）から sink を作る（使えないブラウザでは null：今までどおり Blob で）。mov は最後に頭の mdat の大きさを書き直す（1 回戻って書く）。`finish()` は Blob の代わりに `{ size }` を返す。確かめたこと（`tests/writer_sink_test.mjs`）：mov・ZIP とも、ファイルに書いた物が Blob と同じバイト、終わる前に半分以上がファイルに出ている、mov を ffprobe が読む
- ProRes 4444 はブラウザでは作れない。After Effects に透明つきで持っていくなら `mov-png` か `png-zip`

## After Effects へ（`png-zip` に付く `import_to_after_effects.jsx`）

`png-zip` の ZIP には、連番と一緒に After Effects のスクリプトが入る（`opts.afterEffects: false` で入れない。`opts.name` はコンポの名前）。ZIP を 1 つのフォルダに展開し、After Effects の「ファイル → スクリプト → スクリプトファイルを実行」でこのファイルを選ぶと：
- 連番を 1 つの素材として読み込み（名前の順）、アルファはストレート（PNG のまま）、フレームレートは書き出した時の fps に揃える
- 連番の大きさ・fps・長さのコンポを作り、素材を置いて開く。取り消しは 1 回で戻る
- 連番がスクリプトの隣に無い時は、そう言って何もしない
- スクリプトは ASCII だけ（日本語の名前は `\u` で書く）。Windows の After Effects が文字コードを取り違えない
- **動きも渡す**（2026-11-10、利用者の声 #17）：`w.add(rgba, { params: { MouthOpen: 0.4 }, points: { 右手: [x, y] } })` のように、コマごとにパラメータの値と点（コンポの画素の位置）を渡すと、スクリプトがコンポに「Ugo9 motion」というヌルレイヤーを作り、パラメータごとにスライダー制御、点ごとにポイント制御を付けて、全部のコマにキーを打つ。After Effects の中で、エフェクトや別のレイヤーをキャラの動きに合わせられる（エクスプレッション：`thisComp.layer("Ugo9 motion").effect("MouthOpen")("スライダー")`）。値の無いコマは前のコマの値。数は小数 4 桁。何を渡すか（パラメータ・骨の位置）を選ぶのはエディタの書き出しの窓（エディタの担当）
- 確かめ（`tests/after_effects_test.mjs`）：After Effects の代わりに、スクリプトが使う部分（Adobe の After Effects Scripting Guide のとおりの名前）を置いて動かし、上のとおりに呼ぶことを確かめる。ES3（ExtendScript の JavaScript）で書けているかも acorn で確かめる。After Effects そのもので動かすのは PC 確認で

## パーツのまとまりをレイヤーに（`createLayerSetWriter`、AE・Premiere・DaVinci 向け）

髪・顔・体などのまとまりごとに透過の絵を書き、動画編集ソフトでレイヤーとして重ね直せるようにする。メッシュの曲がりは絵に入るので崩れない。

```js
const w = await createLayerSetWriter([{ name: '体' }, { name: '影', blend: 'multiply', opacity: 0.6 }, { name: '光', blend: 'screen' }], width, height, fps, { name: 'mira_wave', movies: false });
for (...) await w.add([体の絵, 影の絵, 光の絵]);   // まとまりごとに、それだけを描いた絵（下が先、ストレートアルファ）
const zip = await w.finish();
```

ZIP の中：
- まとまりごとの透過の連番 `01_体/frame_00000.png`…（`movies: true` の時は、まとまりごとの `01_体.mov`（MOV に PNG のコマ））
- `import_to_after_effects.jsx`：After Effects で実行すると、まとまりごとに素材を読み込み（ストレートアルファ・fps を合わせる）、1 つのコンポに描く順どおり（最初のまとまりが一番下）に積み、合成モード（乗算・スクリーン・加算・オーバーレイ・ソフトライト・ハードライト・比較（暗）・比較（明）・差・覆い焼き・焼き込み・除外・減算。無い物は通常）と不透明度を付ける。通常でない合成のレイヤーには「透明部分を保持」（`preserveTransparency`）を付ける（一番下のレイヤーを除く）。Ugo9 の乗算・スクリーン・加算は下の色だけを変えて透明度を増やさない（`web/ugo.js`）ので、これが無いと下の絵の外にはみ出した所に色が出る（2026-11-10、エディタの担当が見つけた）
- `ugo9_layers.xml`：Final Cut Pro 7 の XML（xmeml 4）。Premiere Pro と DaVinci Resolve が読み込める。まとまりごとに 1 本のビデオトラック（下が先）、合成モードと不透明度。ファイルの場所は ZIP を展開したフォルダからの相対（ソフトによってはリンクし直しを聞かれる）。連番 1 枚目を指すより MOV の方が確かなので、Premiere・DaVinci には `movies: true` を勧める。FCP 7 の XML には「透明部分を保持」に当たる物が無い。エディタの書き出しは、通常でない合成のまとまりの透明度に、下のまとまり全部を重ねた透明度を掛けてから渡す（下の絵の外には何も無い）ので、Premiere・DaVinci でも同じ見た目になる。掛けずに `createLayerSetWriter` を使う時は、はみ出した所に色が出る
- `layers.json`：まとまり・合成・不透明度・フォルダ名・大きさ・fps・コマ数

確かめたこと：Chromium で 3 まとまり・6 コマを書き、連番の画素が一致、MOV は ffprobe が png・6 コマ・24 fps と読む。.jsx は After Effects の代わりの物で動かし、積む順・合成・不透明度・ストレートアルファ・fps を確かめ、ES3 であることも確かめる。XML は python で読めること（整った XML）、29.97 が NTSC の 30、トラックの順・合成・不透明度を確かめる。After Effects・Premiere・DaVinci そのもので開くのは PC 確認で

## まとめて書く（`encodeAll` など、前から）

GIF・APNG・WebM・MP4 を、全部のコマを持ってから書く。GIF と APNG は Worker で並べて縮める（800×800・90 コマで GIF 1.15 秒、APNG 1.8 秒）。

## コマンドで書く（`ugo_export`、`cli/`）

エディタを開かずに、.ug9 から GIF・APNG・PNG 連番・スプライトシート・raw（RGBA）を書く。MP4・WebM・MOV は ffmpeg を通す。CPU で描くので、同じ入力からは Linux と Windows で同じバイトになる（[Windows.md](Windows.md)）。何体もまとめて書く時や、CI で絵を確かめる時に使う。

```sh
ugo_export model.ug9 --anim idle --out idle.gif --out idle.apng   # 1 回描いて 2 つの形に
ugo_export model.ug9 --anim talk --fps 60 --size 1920x1080 --format frames --out talk/
ugo_export model.ug9 --anim idle --camera 0:1 --camera 2:2.5:0,-420 --out zoom.mp4
```

**透明つきの MOV**（`.mov`・`--format mov`、2026-11-12、利用者の声 #12）：ProRes 4444 で、透明度を持ったまま書く（ffmpeg の prores_ks、YUV 4:4:4、透明度 16 ビット、ストレートアルファ）。Premiere・DaVinci Resolve・After Effects・Final Cut がそのまま読める、編集ソフト向けの形。大きいファイルになる（見本の 140×200・6 コマで約 0.2 MB）。`tools/ugo9.mjs export … --out a.mov` でも書ける。確かめたこと（`tests/export_mov_test.mjs`）：ffprobe で ProRes 4444・透明つき・コマ数と大きさが合う。ffmpeg で読み戻すと、透明度の差は最大 1、透明と不透明の画素はそのまま、半透明の縁は半透明のまま、色の差の平均 0.03（255 のうち）

おもな設定は `--anim`（重ねて書ける）・`--seconds`／`--frames`・`--fps`・`--size`・`--pad`・`--bg`・`--param 名前=値`。全部は `ugo_export --help` で出る。

**JPEG・範囲・アニメごと・コマ打ち**（2026-11-10、利用者の声 #25・#24、機能の比べ #92・#85）：
- `--out 名前.jpg`（`--format jpeg`）：1 コマなら 名前.jpg、何コマもあれば 名前_00000.jpg…（フォルダを渡すと frame_00000.jpg…）。JPEG には透明が無いので `--bg` の色（既定は白）の上に描く。`--quality 1〜100`（既定 90）
- `--crop X,Y,W,H`：`--size` の絵のうち、その範囲だけを書く（同じ絵の一部。原点のずらしの丸めで、色が 1 段違う所がある）
- `--each-anim`：アニメごとに 1 回ずつ書き出す。`--out` の `{anim}` がアニメの名前になる（無ければ拡張子の前に `_名前`）。`--anim` は無視する
- `--hold 2`（3…12）：2 コマ打ち。2 コマごとに新しい姿で、ファイルのコマの速さ（`--fps`）はそのまま

**29.97 などの NTSC のフレームレート**（2026-11-13、利用者の声 #12「フレームレートが食い違う」）：`--fps 29.97`（23.976・59.94 なども）は、MP4・MOV・WebM に 30000/1001（24000/1001・60000/1001）として書く。前は 2997/100 になり、編集ソフトでは 29.97 と別のレートとして扱われ、長いとずれた。APNG のコマの長さも 1001/30000 秒（前は 33/1000 で約 30.3 fps）。エディタの APNG（`web/encoders.js` の `encodeAPNG`）も同じ。30 などの整数と、12.5 などのほかのレートは前のまま。確かめたこと（`tests/export_ntsc_test.mjs`）：ffprobe でそれぞれのレートと、APNG のコマの長さ

**透過 GIF の縁**（2026-11-10、利用者の声 #12）：GIF の画素は「見える」か「透明」しかないので、半透明の縁がそのままの色で出て、置いた先のページで暗い（明るい）縁に見える。`--matte #rrggbb`（置く先のページの色）を付けると、4 分の 1 以上見える画素はその色と透け具合で混ぜて見える画素にし、それより薄い画素は透明にする。エディタの書き出し（`web/encoders.js` の `encodeGIF(..., { matte: [r, g, b] })`）も同じ決まり。

**継ぎ目の無いループ**（`--seamless`、2026-11-10、利用者の声 #35）：物理で揺れる物は、書く前に 1 周ぶん物理を先に動かす（`--warmup`、既定は 1 周）が、揺れがなかなか収まらない物（減衰の小さい揺れ）は、それでもループの頭で跳ねる。`--seamless` を付けると、先に動かした後、さらに 1 周ずつ物理だけを回し、ループの頭の姿が次の周と変わらなくなるまで待ってから書く（最大 `--seamless-loops N` 周、既定 50。描かないので速い）。何周回したかと、残った継ぎ目（2 周の間で姿の値がいちばん変わった量）を出す。収まらなかった時もそう言って書く。アニメの無い時は何もしない。`--each-anim` と一緒でもアニメごとに。確かめたこと（`tests/export_seamless_test.mjs`）：見本の揺れの減衰を 0.2 にしたモデルは、いつもの先回しでは 1 周後のコマが最初のコマと最大 255 違う。`--seamless` で 18 周回して最大 1。見本そのものは 1 周で変わらない

**背景の絵**（`--backdrop 絵.png[:X,Y,W,H]`、2026-11-13、機能の比べ #89）：キャラの後ろに絵（PNG・JPEG）を置いて書く。絵はモデルの空間に置くので、書き出しのカメラ（`--camera`）の拡大・移動で、キャラと一緒に動く。何も書かなければ、絵の形のままキャンバスを覆う（はみ出す所は切れる）。`:X,Y,W,H` を付けると、モデルの px でその四角に置く（原点はキャンバスの原点、`docs/形式.md` の canvas）。透明な所のある絵なら、その下は `--bg` の色か透明。MP4・GIF などどの形でも、スレッドの数でも同じ絵。モデルは変えない。確かめたこと（`tests/export_backdrop_test.mjs`）：キャンバスと同じ形の 4 色の絵で、出力の 4 隅がその色、モデルの描かれた所は（乗算などのパーツの数画素を除き）変わらず、全部不透明。左上 4 分の 1 に置くとそこだけ。カメラで赤の 4 分の 1 の中へ 2 倍に寄ると、モデルの無い所が全部赤。1 と 4 スレッドで同じバイト。幅 0 は 2、無い絵は 1

**長さの目安**（2026-11-12、進行の #391 の 4）：見本のモデル（物理あり）を `ugo_export` で MP4 に、4 コアの PC で、スレッドは既定（`--threads` 無し）で測った。モデルの大きさ・パーツの数で変わるので、目安として。

| 大きさ | `--ss` | 1 秒に描くコマ | 1 分・30 fps（1800 コマ）にかかる時間 |
|---|---|---|---|
| 1920×1080 | 2（既定、縁が滑らか） | 約 10 | 約 3 分 |
| 1920×1080 | 1 | 約 24 | 約 1 分 15 秒 |
| 3840×2160 | 1 | 約 5.7 | 約 5 分 |
| 3840×2160 | 2 | 約 1.5 | 約 20 分（描く物のメモリが大きく、既定ではスレッドが 2 本に減る） |

- 60 fps はコマが倍なので時間も倍。コア（プロセッサ）が多いほど速い（最大 8 スレッド）
- **メモリ**：MP4・WebM・MOV・APNG・PNG の連番・raw は、コマを書いたら持たないので、長さで増えない（1080p・70 秒で最大約 185 MB を確かめた）。**GIF とスプライトシートは全部のコマを持つ**（1 コマ = 幅 × 高さ × 4 バイト、1080p で約 8.3 MB。1080p の 70 秒・30 fps は約 17 GB で、足りなくなる）。長い物・大きい物は GIF にしない。合わせて約 4 GB（`--max-held MB`、既定 4096、0 で限り無し）を超える時は、描く前に止めて、量と代わりの形を言う（終了コード 2、何も書かない。スプライトシートは並べ直した写しも持つので 2 倍で数える）。前は途中でシステムに止められていた。確かめたこと（`tests/export_held_test.mjs`）：1080p の 70 秒の GIF（約 16 GB）は止まる、短い GIF は今までどおり、シートは 2 倍、APNG は数えない、`--max-held 0` で限り無し
- **ブラウザ（エディタ）の書き出し**：MP4・WebM・透過の WebM はコマごとに書く。PNG の mov・ZIP は、保存先を先に選べる時（File System Access があるブラウザ）はファイルへ流し、無い時は PNG を全部持つ（透過の 1080p で 1 コマ数百 KB〜1 MB）。GIF・APNG は全部のコマを持つので、描く前に `heldMemory(形, 幅, 高さ, コマ数, { matte })`（`web/encoders.js`）で量を見る：幅 × 高さ × 4 × コマ数（マット付きの GIF は 2 倍）が `HELD_LIMIT`（1.5 GB）を超えると `tooBig`、代わりの形（コマごとに書く形、透過の物が先）を `instead` で返す。1080p・30 fps なら約 6.5 秒、720p なら約 15 秒が境目。エディタの窓はこれで止めて知らせる（エディタの担当）。確かめたこと（`tests/held_memory_test.mjs`）：1080p の 70 秒の GIF は 16.2 GB で止める、720p の 3 秒は通す、コマごとに書く形は 0
- 急ぐ時：`--ss 1` で約 2.4 倍速い（縁が少しギザギザ）。下書きの確かめは小さい大きさで

**いくつかのコマを一度に描く**（`--threads N`、2026-11-12、進行の #391 の 3）：既定でプロセッサの数（最大 8）のコマを同時に描く。物理の揺れはコマの順に決まるので、スレッドごとに自分のインスタンスを持ち、同じ順で同じ姿の計算（先回し・`--seamless`・描くコマ全部）をしてから、自分のコマだけを描く（姿の計算は軽く、描く所が重い）。だから絵はスレッドの数で 1 バイトも変わらない。メモリは 1 スレッドあたり描く画面の約 20 バイト／画素（1080p・`--ss 2` で約 170 MB）で、既定では合計が約 1.5 GB を超えないようにスレッドを減らす。`--threads 1` で今までどおり 1 コマずつ。確かめたこと（`tests/export_threads_test.mjs`）：物理・2 つのアニメ・止めたパラメータ、2 コマ打ち・`--seamless`、カットのあるカメラ・最近傍・背景・切り抜きで、1・2・3・4・8 スレッドの raw・GIF・APNG が同じバイト。スレッドを入れる前の作りとも同じバイト。ThreadSanitizer で競合なし。速さ（4 コア、1080p・`--ss 2`・150 コマの MP4）：1 スレッド 45.5 秒、2 スレッド 24.7 秒、4 スレッド 15.9 秒（約 2.9 倍、MP4 は同じバイト）

**ピクセルアート**（`--nearest`、2026-11-10、利用者の声 #54）：テクスチャの画素を混ぜずに、一番近い 1 つを取る（芯の `UGO_RASTER_NEAREST`）。整数倍に大きくすると、ドットがそのままの四角になる（4×4 の絵を 8 倍で、どのドットも元の色ちょうど）。縁（パーツの輪郭）までドットのままにしたい時は `--ss 1` も付ける（既定の `--ss 2` は輪郭を滑らかにする）。プリセットでは `"sampling": "nearest"`。確かめたこと：`tests/export_nearest_test.mjs`

**画素に合っているかを確かめる**（`tools/pixel_check.mjs`、2026-11-12、機能の比べ #19）：`--nearest` でも、パーツが整数倍でない大きさ、少し回った向き、半端な位置で描かれると、ドットの幅がそろわない。このツールは、そういうパーツを、基準の姿と各アニメ（既定は 1 秒 12 コマで調べる）で探して、何がずれているかを出す。
- 調べること：大きさ（テクセル 1 つが出力の何 px か。1・2・3… なら良い）、向き（4 分の 1 回転からの角度）、位置（テクセルの角が画素の角からずれている量）。
- 使い方：`node tools/pixel_check.mjs model.ug9 [--scale 2] [--fps 12] [--json]`。`--scale` は書き出しの倍率（モデル 1 px が出力の何 px か）。2 倍で書くなら 1.5 倍のパーツは 3 倍になって合う。全部合っていれば終了コード 0、ずれがあれば 1。
- **直す**：`node tools/pixel_check.mjs model.json --snap --out fixed.json`。基準の姿で少しだけずれているパーツ（大きさがほぼ整数倍、回っていない、メッシュが曲がっていない）の頂点を、画素の上にそろえる（動くのは 1 px 未満）。回ったパーツ、大きさが半端なパーツ、メッシュが曲がっているパーツはそのまま残し、名前を出す。モーフ・骨・アニメは変えない。
- アニメの中で半端な位置を通る物（骨が 0.5 px 動くなど）は、どのアニメの何秒かを出すだけで、直さない（描く時に画素にそろえるのは芯の描画の仕事）。キーを整数の位置にするか、エディタで直す。
- 確かめたこと（`tests/pixel_check_test.mjs`）：1 倍と 2 倍で角の合ったパーツは出ない。0.3 px ずれ、1.5 倍、10° 回転、アニメで 0.5 px 動く物を見つける。スナップで 0.3 px ずれが整数の位置になり、ツールで合っていると出る

**カメラ**（`--camera T:倍率[:X,Y]`、2026-11-10、利用者の声 #24）：書き出す時だけの拡大と移動。モデルは変えない。
- T は最初のコマからの秒。倍率 2 で 2 倍に寄る。X,Y は画面の真ん中に来るモデルの点（モデルの px、原点はキャンバスの原点）。書かなければキャンバスの真ん中
- キーは 32 個まで、順はどうでもよい（時刻で並べる）。キーの間はゆっくり始まりゆっくり止まる。倍率は掛け算の目盛りで動く（1 → 4 なら真ん中で 2）。最初のキーより前と最後のキーより後は止まる
- **カット**（2026-11-10、利用者の声 #24 の残り）：キーの終わりに `:cut` を付けると（`--camera 2:2.5:cut`・`--camera 2:2.5:0,-420:cut`）、その時刻まで前のキーのまま止まり、その時刻に一度で切り替わる（間をゆっくり動かない）。プリセットのキーは `{ "t": 2, "zoom": 2.5, "cut": true }`。エディタの窓のカメラのキーも同じ形
- 確かめたこと（`tests/export_camera_test.mjs`）：倍率 1・真ん中なら `--camera` 無しと同じバイト。倍率 2 は 2 倍の大きさで描いた絵の真ん中と同じ（差は最大 1）。X,Y を右へ 40・上へ 30 ずらすと、絵が左へ 40・下へ 30 動く（差は最大 1）。1 → 4 の 2 秒で 1 秒目が倍率 2 と同じ。読めないキーは断る（終了コード 2）

## ゲームエンジン向けのスプライトシート（`web/sheet.js`・`tools/export_sheet.mjs`、2026-11-10、利用者の声 #2）

Ugo9 のランタイムが無いエンジン（GameMaker・Construct・GDevelop・Defold・Phaser・PixiJS など）向けに、全部のアニメを 1 枚のシートにする。

```
node tools/export_sheet.mjs model.ug9 --out build/sheet/hero.png [--fps 12] [--size 256x256] [--anims idle,walk] [--no-trim] [--no-dedupe] [--max-width 4096]
```

- アニメごとに `ugo_export` で 1 周を描き（物理は落ち着かせてから）、コマの見える所だけに切り詰め、同じ絵のコマは 1 つにまとめて、行に詰める。シートは、ほぼ正方形（最大 4096 px 幅）
- 横に `hero.json`：TexturePacker・Aseprite と同じ「JSON (Hash)」の形（コマの名前 `アニメ名_0000`、シートの中の場所、切り詰めた箱と元の大きさ、時間 = 1000 / fps のミリ秒）と、アニメごとの frameTags。多くのエンジンの読み込み（そのままか、広く使われている追加の部品）で読める
- エディタからも同じ関数（`packSheet(anims, w, h, opts)`）で作れる（書き出しの窓に出すのはエディタの担当）
- 1 つのアニメだけのシートは、今までどおり `ugo_export --format sheet`（切り詰めなし）

## 書き出しのプリセット（`web/export_preset.js`、`ugo_export --preset`、2026-11-10、利用者の声 #25）

書き出しの設定を名前付きの JSON に残し、エディタの書き出しの窓と `ugo_export` で同じ物を使う。窓の UI（残す・選ぶ・既定に戻す）はエディタ、形と読み書きはここ。

```json
{
  "ugo9ExportPreset": 1,
  "name": "PV 1080p 60",
  "formats": ["webm-alpha", "png-zip"],
  "fps": 60,
  "size": { "width": 1920, "height": 1080 },
  "background": null,
  "anim": "idle",
  "seconds": 4,
  "pinned": { "AngleX": 10 },
  "fileName": "{doc}_{anim}",
  "camera": [{ "t": 0, "zoom": 1 }, { "t": 2, "zoom": 2.5, "x": 0, "y": -420 }]
}
```

| 項目 | 中身 |
|---|---|
| `ugo9ExportPreset` | 版（今は 1）。これだけは要る。ほかは全部書かなくてよい |
| `formats` | `gif`・`apng`・`png-zip`・`webm`・`webm-alpha`・`mp4`・`mov-png`・`jpeg`。`ugo_export` は `--out` で形を決めるので読まない |
| `fps` | 1〜240 |
| `size` | `{ width, height }`：その枠の中に（キャラは真ん中、残りは透明か背景）。`{ long }`：長い辺をその px に。`scale` より勝つ |
| `scale` | キャンバスの何倍か（0.001〜16） |
| `background` | `"#rrggbb"`、または `null`（透明） |
| `matte` | GIF だけ：置く先のページの色 `"#rrggbb"`、または `null`（なし）。`--matte` と同じ（下） |
| `anim`・`seconds` | アニメの名前と長さ（秒）。モデルによるので、入れなくてもよい |
| `pinned` | 書き出す時に止めておくパラメータ（`{ 名前: 値 }`）。`--param` と同じ |
| `sampling` | `"nearest"`（ピクセルアート：近い画素を取る。`--nearest`、レンダラーの `setSampling('nearest')`）か `"linear"`（既定） |
| `fileName` | ファイル名の決まり。`{doc}`・`{anim}`・`{fps}`・`{w}`・`{h}`。既定は `{doc}_{anim}` |
| `camera` | カメラのキー（`t`・`zoom`・`x`・`y`・`cut`）。`--camera` と同じ動き（32 個まで）。`cut: true` はそのキーへ一度で切り替える |
| `jpegQuality` | JPEG の品質 1〜100（既定 90）。`--quality` と同じ。背景が `null` の時は白の上に |
| `region` | 書く範囲 `{ x, y, width, height }`（**モデルの px**）。`ugo_export` はその時の大きさで、範囲を覆う絵の画素に直して `--crop` と同じに切る。絵からはみ出す時は断る。後に書いた `--crop` が勝つ |
| `backdrop` | キャラの後ろの絵（2026-11-13）：ファイルの名前（`"背景.png"`）か `{ "file", "x", "y", "width", "height" }`（**モデルの px**、4 つ一緒か無し）。名前はプリセットのファイルの横から探す（絶対パスはそのまま）。`ugo_export --backdrop` と同じに描く。後に書いた `--backdrop` が勝つ。エディタの書き出しの窓はまだ描かない（読んで残すだけ） |
| `eachAnim` | `true`：アニメごとに 1 回書く。`--each-anim` と同じ（ファイル名の `{anim}`、無ければ後ろに `_名前`） |
| `holdFrames` | N コマ打ち 1〜12（1 は今まで通り）。`--hold` と同じ |
| `seamless`・`seamlessLoops` | `true`：継ぎ目の無いループ（物理を落ち着くまで回してから書く）。`--seamless` と同じ。`seamlessLoops`：回す周の上限 1〜1000（既定 50）、`--seamless-loops` と同じ |
| `perAnim` | アニメごとの設定（2026-11-13、利用者の声 #25「ループをシーンごとに決められない」）：`{ "idle": { "loops": 3, "seamless": true }, "walk": { "seconds": 2.5, "holdFrames": 2 }, "jump": { "skip": true } }`。そのアニメを書く時、全体の値より勝つ。`seconds`・`loops`（アニメの長さの何周か、0.001〜100。`seconds` があればそちら）・`seamless`・`seamlessLoops`・`holdFrames`・`fps`・`skip`（`eachAnim` で書かない）。`ugo_export` は `--preset` より後に書いた引数がそれにも勝つ。エディタは `presetToExportOptions(preset, アニメ, { duration })`（`skip` なら null） |

- 知らない項目（新しい版の物など）は、読んで書き直しても残る。読めない値は捨てて、注意を返す（`ugo_export` は 1 行ずつ出して書き出しは続ける）。新しい版の物は、知っている項目だけ読む。版の無い物・JSON でない物は断る（`ugo_export` は終了コード 2）
- 関数：`readExportPreset(テキストか物)` → `{ preset, notes }`、`writeExportPreset(preset)` → JSON のテキスト（版が先頭、決まった順）、`presetToExportOptions(preset)` → エディタの `exportAnimation` に渡す物（`size` は `'frame:WxH'`・`'long:L'`・倍率）、`presetFileName(決まり, { doc, anim, fps, w, h })`、`cameraAt(keys, t, 真ん中)`、`cameraTransform(出力, canvas, frameSize の { s, dx, dy }, keys, t)` → `setTransform` の 6 つの数
- `ugo_export --preset pv.json --out pv.mp4`：後から書いた設定がプリセットに勝つ（`--preset pv.json --fps 30` なら 30）。前に書いた物にはプリセットが勝つ。`--anim`・`--camera` は、プリセットの後に書くとプリセットの物と入れ替わる
- 確かめたこと（`tests/export_preset_test.mjs`、31 項目）：プリセットで書いた絵は、同じ設定を引数で書いた絵と同じバイト。後の引数が勝つ・前の引数は負ける。`long`・`scale` の大きさ。読めない値・新しい版・壊れた JSON・BOM と `\u` の名前。カメラの関数が `ugo_export --camera` と同じ式
- `cli/preset.c` の JSON の読み手（C99、外の依存なし）は、壊した入力で試す（`tests/test_preset.c`、CI で AddressSanitizer・UBSan の下）：良いプリセット 3 つの値、途中で切った全部の長さ、2 万通りの壊し方（ビットの反転・JSON の記号・でたらめなバイト・切り詰め）、1 万段の入れ子（深さの上限で断る）、10 万バイトの名前、2 万個の対の無いサロゲート、有限でない数。どれも 0 か 1 を返し、テキストの外を読まない。`jpegQuality`・`region`・`eachAnim`・`holdFrames`（2026-11-10）は、良い値と、範囲外・違う種類の値（落とす）も試す。`tests/export_options_test.mjs` で、それぞれ引数と同じバイトになることを確かめる（`region` は同じ所の `--crop` と同じ）

## 確かめたこと（`tests/video_writer_test.mjs`、`tests/video_test.mjs`）

Chromium で書き、ffmpeg で読み戻す。
- `png-zip`：24 コマ全部、画素が一致（透明も）。`unzip -t` も通る
- `mov-png`（29.97 fps）：ffmpeg が png・24 コマ・30000/1001 と読み、全部のコマの画素が透明も含めて一致
- `webm-alpha`：ffmpeg（libvpx）が透明つきで読み、透明度の PSNR 54.9 dB、色の PSNR 41.0 dB
- `webm` 60 fps・24 fps、`mp4` 29.97 fps：コマ数・fps・長さが合う
- 4K（3840×2160）の `webm-alpha`・`mov-png`・`mp4`：ffmpeg が 3840×2160 で読む
