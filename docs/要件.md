# 要件（2026-10-29 時点で決まったこと）

進める前に詰めるための整理。決まったことと、まだ決まっていないことを分けて書く。

## 使う人と配り方

- **他のクリエイターにも無料で配る**。自分だけの道具ではないので、次が要る
  - Windows と Mac で動くエディタ、説明書、安定性
  - 作ったキャラ（データ）は作った人の物。再生部品は、ゲームや配信に組み込んでも料金や契約が要らない形で配る（ライセンスの種類は未定）
- AI でキャラ作りを助ける機能は、今は入れない

## 素材の入口

| 入口 | 扱い |
|---|---|
| 自分の絵（パーツ分けした PSD）から新しく作る | 主な入口 |
| 他の人が描いた絵 | 使える。権利の確認は使う人の責任であることを説明書に書く |
| 今ある Live2D のモデル | **.moc3 の読み込み・書き出しはしない**（2026-10-30 決定）。Live2D の規約は、Live2D で作ったファイルを競合する道具で使うことを禁じ、.moc3 の仕様も非公開。元の PSD から Ugo9 で作り直す。Live2D 社の書面の許可が得られたら見直す。Live2D の公式の見本モデルはテストやデモにも使わない（調査_権利_Live2D_Spine.md） |
| 今ある Spine のデータ | **Spine の JSON の読み込み・書き出しはできる**（形式が公開され、開発元も自前のコードでの読み書きを認めている。危険は低い）。.spine（編集用ファイル）は扱わない。書き出した物を公式の Spine ランタイムで使う人には Spine のライセンスが要ることを表示する |

## 作り方（エディタ）

- **Live2D と Spine の考え方を合わせる**。既存のアプリに慣れた人がすぐ使えることを基準にする
  - 顔：Live2D 式（パーツ・デフォーマ・パラメーター・形の登録）
  - 体・ゲームの動き：Spine 式（骨・重み・タイムライン）
- 内部の仕組み（GPU で変形・差分の足し算・書き出し時のコンパイル）は、作る人からは見えないようにする
- 「パラメーター」という形にはこだわらない。**トラッキングで自然に動けば、動かし方の仕組みは何でもよい**

## 必ず要る表現（Live2D でよく使う物）

| 表現 | 今の試作 | 実現の見込み（推測） |
|---|---|---|
| マスク（クリッピング）と、マスクの反転（そのパーツで隠す） | 無い | GPU のステンシルで、描画 1 回のまま入れられる |
| 透明度 | ある | — |
| 乗算色・スクリーン色（上から色を乗せる） | 無い | パーツごとの色をフレームの塊に足し、シェーダーで掛ける。軽い |
| 乗算・スクリーン・加算などの重ね方 | 無い | 重ね方ごとに描画を分けるか、対応 GPU では 1 回で |
| パーツの接着（つなぎ目を一緒に動かす） | 無い | 書き出し時に、接着した頂点へ同じ動きを配る（実行時の負担なし） |
| 回転させた時の補間（縮まない回転） | 骨ならできる（角度で補間）。差分での回転は縮む | 回転は骨か「回転デフォーマ」で角度として持つ。奥行きの回転（Z）も検討 |
| 四隅の補正（X と Y を作ると角が伸びるのを直す） | 仕組みはある（2 軸の範囲＝角だけの補正） | エディタで「角の補正」を作りやすくする |
| なめらかな振り向き（格子で顔全体を曲げる） | 差分のみ。格子（ワープ）は無い | ワープ格子を GPU で評価する（設計の次の段階 2） |
| 多段の揺れ物（根元から先へ遅れて揺れる） | パラメーターのばね 1 段のみ | 骨の鎖の物理（Verlet・XPBD など）を CPU で軽く |

## 書き出し

- **動画用（焼く）と VTuber・ゲーム用（動かす）を分ける**
- **行き先を複数まとめて選べる**ようにする。動画は 1 回描いて、選んだ形式の数だけ圧縮する
- **VTuber・ゲーム用は、行き先ごとに方式を選べる**
  - 「そのアプリの標準の仕組みだけ」：Ugo9 の再生部品を入れず、アプリ自身が変形・描画する。足りない機能は書き出す前に警告する
  - 「Ugo9 の部品も使う」：全部の機能が出て、軽い
- **VTuber 用は Ugo9 自身の表示アプリを作る**（2026-10-30 決定）。VTube Studio は Live2D 専用で、Live2D 形式への書き出しは規約上むずかしいため。ブラウザでカメラの顔の動きを読み、背景を透明にして OBS に出す
- 標準の仕組みへ直接変換したい行き先：**Unity・Godot・Unreal**。各アプリの標準機能で何ができるかは [調査_各アプリ標準の2D機能.md](調査_各アプリ標準の2D機能.md)。要点：ワープ（格子）と 2D の形の登録はどのアプリにも標準では無く、マスクの反転・スクリーン色・接着もほぼ無い。標準の部品（骨・ブレンドシェイプ）に、アプリの中で動く小さなスクリプトとシェーダーを足す形なら、多くを再現できる見込み（推測）
- glTF は補助の行き先（検証の結果、主な行き先には向かない。[検証_glTF.md](検証_glTF.md)）

## 3D アプリに置く・Spine から持ち込む（2026-10-30 決定）

- **Spine → Ugo9 の読み込みを先に作る**（Spine の JSON と .atlas）。Ugo9 → Spine の書き出しは後で
- **3D アプリに置く**：ゲームエンジンの 3D の場面・Blender などの制作ソフト・3D の VTuber アプリ・Web の 3D の全部
  - 決まった動き：glTF（焼いた動き）。カメラを向く・奥行き・影の設定を足す
  - 全部の機能：各エンジン用の Ugo9 の部品で、3D の場面の板に描く
  - 3D の VTuber アプリ：VRM 1.0 の板として出す（振り向きは板が回る形。まばたき・口・揺れ物は動く）

## 分かっていること（計測）

- Pixel 9：Ugo9・CPU で変形・glTF のどれも 400 体まで 60 fps。CPU の時間は Ugo9 が他の半分以下（[検証_glTF.md](検証_glTF.md#実機で測る)）
