# 1 つのコマンド（`tools/ugo9.mjs`、2026-11-10、機能の比べ #96・利用者の声 #25）

作業ファイルの読み込み・書き出し・まとめる・ほどくを、1 つのコマンドの 4 つの言葉で。中では、このリポジトリのそれぞれの道具を動かすだけ（その道具の知らせと終わりの値がそのまま出る）。

```
node tools/ugo9.mjs pack   <フォルダ | model.json> --out 名前.ugo9
node tools/ugo9.mjs unpack <名前.ugo9> --out フォルダ
node tools/ugo9.mjs import <ファイル> --out フォルダ | 名前.ugo9 [-- 読み込みの道具のオプション]
node tools/ugo9.mjs export <フォルダ | model.json | 名前.ugo9 | model.ug9> --out ファイル [--as 種類] [--target 1.0|1.1] [--light [0.5]] [-- 書き出しの道具のオプション]
node tools/ugo9.mjs info   <フォルダ | model.json | 名前.ugo9 | model.ug9> [--json]
```

- **pack**：作業用 JSON とその絵を、エディタの作業ファイル（.ugo9）に。絵はモデルのテクスチャと、横の `manifest.json` に挙がった物（下絵など、その役目のまま）
- **unpack**：.ugo9 を `model.json`・絵・`manifest.json` に戻す。もう一度 pack すると役目も戻る
- **import**：ファイルの名前でなく中身で道具を選ぶ。PSD・PSB（`import_psd`）、Krita・OpenRaster・Procreate・Aseprite・PNG のフォルダ（`import_layers`）、Spine の JSON・バイナリ（`import_spine`、横の `名前.atlas` を使う）、.ug9（`import_ug9`）、.ugo9（unpack）。`--out` が `.ugo9` で終われば、読んだ物をそのまままとめる。SVG は形を描くのにブラウザが要るので、エディタで開くよう知らせる
- **export**：種類は `--as` か `--out` の終わりから。`ug9`（コンパイル）、`spine`（`export_spine`、`--out` はフォルダと名前）、`html`・`js`（`export_web`）、`sheet`（`export_sheet`、.png）、`gif`・`apng`・`mp4`・`webm`・`mov`（ProRes 4444、透過）・`frames`（`ugo_export`）。.ugo9 と作業用 JSON は先にコンパイルする（テクスチャの横で）。.ug9 はそのまま渡す（Spine へは作業用 JSON に戻してから）
- **書き出し先の版**（`--target`、2026-11-12、機能の比べ #13・利用者の声 #6・#32）：.ug9 を古い再生部品に合わせて書く。`--target 1.0` は、曲線のキー（形式 1.1）を、1.1 の芯が読み込む時に作るのと同じ直線のキーに切って、1.0 の表（21・22）で書く。1.0 の芯は 1.1 の曲線の表を読み飛ばすので、曲線のあるモデルの 1.1 のファイルは 1.0 の芯では動かないが、`--target 1.0` のファイルは同じに動く。`--target 1.1`（既定）は今の版（曲線の無いモデルはどちらでも 1.0）。.ug9 の時だけ（ほかの種類は自分の再生部品を持つ）。知らない版は 2。`compileFor(json, target)` も使える。確かめ（`tests/ugo9_cli_test.mjs`）：曲線のあるモデルが 1.0 と 1.1 で書け、ランタイムで動かすと、どの時刻もすべての頂点がビット単位で同じ
- **軽い版**（`--light [倍率]`、2026-11-12、利用者の声 #400 の 3）：.ug9 を書く時、テクスチャのページを半分（`--light 0.25` なら 4 分の 1）にした `名前@0.5x.ug9` とそのページ（`atlas@0.5x.png`）を、横に一緒に書く。モデル（メッシュ・骨・アニメ）は同じで、絵の画素だけ少ない（`tools/atlas_sizes.mjs`）。スマホや、大きな絵の読み込みが遅いエンジン向け。`--target 1.0` と一緒なら軽い版も 1.0。`--light` を付けない時、4096 px を超えるページがあれば、その事と `--light` を知らせる。.ug9 の時だけ（ほかの種類は 2）。確かめ（`tests/ugo9_cli_test.mjs`）：ページが半分・4 分の 1 になり、頂点とアニメの数が同じ。.ug9 から（絵は横の物）でも書ける。4100 px のページで知らせが出る
- **info**（2026-11-10、機能の比べ #8・利用者の声 #11・#18）：モデルの重さ（`tools/model_info.mjs`）。ランタイムの `model.stats()` の数とバイト（パラメータ・骨・パーツ・頂点・三角形・差分・キーなど、ファイル・モデル・1 体ぶん・1 コマのメモリ）に、作業用 JSON から：描く回数の見込み（描く順でテクスチャのページ・合成・マスクが変わる所で切れる。まとめて描くエンジンでの描画の回数の目安）、テクスチャのメモリ（ミップマップ込みも）、基準の姿で描く面積がキャンバスの何倍か（2 を超えると重ねて描く所が多い）、頂点の多いパーツ・差分の項目の多いパーツ。`modelInfo(bytes, json, opts)`・`formatInfo` も使える。確かめ（`tests/model_info_test.mjs`）：数は model.stats() と同じ、マスクのパーツの数だけ描く回数が増える、ページを分け・合成を変えると増える、テクスチャのバイト、.ug9 と作業用 JSON から同じ
- `--` の後ろは、動かす道具にそのまま渡す（例 `-- --fps 4`、`-- --spacing 32`）
- 間違ったコマンドは終わりの値 2 と使い方
- .ugo9 の読み書きはエディタと同じ物（`tools/lib/ugo9file.js`）を使う
- **日本語の名前**（2026-11-12、利用者の声 #400 の 2）：フォルダ・テクスチャ・パーツ・骨・パラメータ・アニメの名前は日本語のままでよい。.ug9 は名前を UTF-8 で持ち、`ugo_export` は Windows でも日本語のパスを開く。.ugo9 と PNG の ZIP は、名前に UTF-8 の印（ビット 11）を付けるので、ほかの zip の道具でも化けない。確かめ（`tests/japanese_names_test.mjs`）：日本語のフォルダの日本語の名前のモデルが、英字の名前の物と同じバイトで描け、.ug9 から戻した名前も、.ugo9 で一周した名前も同じ。Python の zipfile と unzip も名前をそのまま読む。日本語以外の Windows（地域の設定が英語など）での確かめは PC で
