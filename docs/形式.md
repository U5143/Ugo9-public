# ファイル形式（v1.1）

2 種類あります。

- **作業用 JSON**：人・エディタ・スクリプトが書く。差分が git で読める
- **配布用 `.ug9`**：`tools/compile.mjs` が作るバイナリ。読み込み時にそのまま使え、検査に通った物だけが動く

拡張子（1.0〜、2026-11-07 ユーザーの決定）：ランタイムが読むファイルは `.ug9`（0.7 までは `.ugo`）、表情などのプリセットは `.ug9x`（JSON）、エディタの作業ファイルは `.ugo9`。読む側は拡張子でなく中身（先頭の `UGO9`）で判断するので、`.ugo` の名前のファイルもそのまま読める（版が 0.8 なら）。

座標は**ピクセル**、x は右、**y は下**が正。角度は作業用 JSON では度、`.ug9` ではラジアン。

## 作業用 JSON

```jsonc

  "version": "1.0",
  "canvas": { "width": 420, "height": 600, "originX": 210, "originY": 590 }, // モデルの (0,0) がキャンバスのどこか

      "length": 40 },                          // 骨の長さ（IK の伸び縮みと 2 本の IK で使う）
    { "id": "browRot", "warp": "face", "x": -40, "y": -400 }  // ワープ格子の中の骨（回転デフォーマ）（v0.5〜）
  ],

    { "id": "leg", "type": "ik", "bones": ["thigh", "shin"], "target": "footTarget",
      "mix": 1, "bend": -1 },                  // 1 本か 2 本。bend は曲がる向き（+1 / -1）。1 本なら compress / stretch / uniform も

      "solid": false,                          // true ならマスクとして画像の透明度を見ず、メッシュ全体を覆う
      "blend": "normal",                       // normal / add / multiply / screen（v0.4〜）
      "color": "skin",                         // 色（下の colors の id）。乗算色・スクリーン色や Spine の tint（v0.4〜）
      "warp": "face",                          // ワープ格子に入れる（v0.5〜）。その時 bone / weights は書かない
      "order": 500                             // 描画順の値（v1.0〜、既定 500）。小さい順に描く。同じ値は parts の順
    }
  ],
  "warps": [                                   // ワープ格子（v0.5〜）。親が先でなくてもよい（並べ替える）
    { "id": "face", "cols": 4, "rows": 4,      // マス目の数。制御点は (cols+1)×(rows+1)、左上から行ごとに番号

      "bone": "head" },                        // 格子ごと骨で動く（省略で最初の骨）
    { "id": "eyeL", "cols": 2, "rows": 2, "rect": [-80, -440, 70, 60],
      "parent": "face" }                       // 入れ子：親の格子の中で一緒に曲がる
  ],
  "colors": [                                  // 色（v0.4〜）。複数のパーツで共有できる。どちらかの組で書く

    {

      "opacity": { "eyeClosedL": 1 },          // 不透明度に足す（最後に 0..1）

      "order": { "armL": 300 }                 // 描画順の値：重みが 1 の時の値（v1.0〜）。元の値からの差を重みで足す
    },
    { "id": "smear",                           // region を書かないと、アニメーションの morphs でだけ動く差分になる
      "morphs": { "face": { "dense": [ ... ] } } }
  ],
  "chains": [                                  // 骨の鎖の揺れ物（v0.6〜）。髪・リボン・スカートなど
    { "id": "hairL", "bones": ["hairL1", "hairL2", "hairL3"],   // 根元から先へ。どれも前の骨の子。id は .ug9 に鎖の名前として入る（0.7〜）

      "gravity": [0, 600],                     // 重力（モデル座標の px/秒²、y は下向き）
      "inertia": 1, "mix": 1 }                 // 画面で動いた時の取り残され方（0〜1）、骨を揺れに向ける割合（0〜1）
  ],
  "glue": [                                    // のり（v0.6〜）：2 つのパーツのつなぎ目を一緒に動かす。書き出し時に処理し、実行時の負担はない
    { "parts": ["armUpper", "armLower"],       // どちらも骨で動くか、どちらも同じワープ格子の中
      "pairs": [[12, 0], [13, 3]],             // [1 つ目のパーツの頂点, 2 つ目のパーツの頂点]（基準の姿で同じ位置に置く）
      "strength": 1,                           // 0〜1。1 なら組の 2 点はいつも同じ所へ動く
      "bias": 0.5 }                            // 0〜1。合わせる先：0 なら 1 つ目の動き、1 なら 2 つ目の動き、0.5 は半々
  ],
  "expressions": [                             // 表情（v1.0〜）：パラメータを名前で変える。描く側が重さを付けて足す
    { "id": "smile", "fadeIn": 0.5, "fadeOut": 0.5,   // フェードの秒（既定 0.5。描く側が使う）
      "params": { "MouthShape": ["add", 1], "EyeSmileL": ["set", 1], "BrowHeightL": ["multiply", 0.5] } }

    { "output": "HairSway", "inputs": { "AngleX": 1, "BodyAngleX": 2 },
      "stiffness": 30, "damping": 5, "gain": 0.12, "min": -1, "max": 1 }

      "order": { "armL": [[0, 500], [1, 300, "step"]] },                           // パーツの描画順の値を置き換える（v1.0〜）

      "colors": { "cape": { "tint": [[0, [1, 1, 1]], [0.5, [1, 0.5, 0.5], "smooth"]] } },  // 色を置き換える（[秒, [r, g, b], 補間]）（v0.4〜）
      "constraints": { "leg": { "mix": [[0, 1], [0.5, 0]], "bend": [[0, -1, "step"]] },  // 制約の効き具合（IK は mix と bend、
                       "sway": { "mixX": [[0, 0.01], [1, 0.1]] } } }                  //  transform は mixRotate〜mixShearY）
  ]
}
```

**コンパイラの警告**：`compileUgo(json, { warnings: [] })` と配列を渡すと、コンパイルは通るが怪しい所が `{ path, code, vars, level, message }` で入る。path はエラーと同じ書き方（例 `deformers[2]`）、code は種類の名前（camelCase、読み込み・書き出しの notes の code とぶつからない）、vars は文に入れる値、level は `warning` か `info`（よくあって問題の無いことも多い物）、message は英語の文（code を知らない道具のため）。日英の文はエディタの i18n.js（`note_<code>`）が持つ。

| code | level | vars | message（英語） |
|---|---|---|---|
| `paramUnused` | warning | param | parameter {param} is not used by any region, physics or animation |
| `regionOutOfRange` | warning | param, start, peak, end, min, max | region "{param}" [{start}, {peak}, {end}] is outside the parameter's range {min}..{max}: it never takes effect |
| `deformerEmpty` | warning | （無し） | this deformer changes nothing |
| `deformerConstraints` | warning | deformer, constraints | constraints in a deformer are not read ({constraints}): a constraint's mix moves with an animation's constraint tracks (animations[].constraints.<id>.mix, mixRotate, mixX ...), not with a parameter |
| `curveHandleClamped` | warning | anim, track, time | a curve of {track} at {time} s has a time handle outside its segment: kept inside (0..1) |
| `curveBaked` | info | curves | {curves} curve(s) too steep for the player's pieces: written as straight keys |
| `partNoTriangles` | warning | part | this part has no triangles: nothing of it is drawn |
| `partInOwnMask` | warning | part | part {part} is in its own mask |
| `partOutsideWarp` | warning | part, warp, outside, total | {outside} of {total} vertices lie outside warp grid "{warp}" (they only continue along the edge) |
| `glueApart` | warning | partA, vertexA, partB, vertexB, distance | vertex {vertexA} of {partA} and vertex {vertexB} of {partB} are {distance} px apart in the rest pose |
| `chainTipNoLength` | warning | chain, bone | the last bone "{bone}" has no length: it has no tip to swing |
| `keyOutOfRange` | warning | anim, param, time, value, min, max | a key of {param} at {time} s is {value}, outside the parameter's range {min}..{max}（トラックごとに最初の 1 つ。再生では幅に切り詰める） |

`{ timings: {} }` を渡すと、区分ごとのコンパイルの時間（ms）が入る（エディタの重さの計測用）。`{ checkOnly: true }` を渡すと、検査（エラーと警告）だけをして .ug9 を作らず、`null` を返す（保存の前の確かめや「問題」一覧の更新用）。

**source**：エディタが持つ取り込み元の情報（PSD を読み直すための、レイヤーの名前・グループの道筋・PSD とアトラス上の位置など）。中身はエディタが決める。コンパイラとランタイムは読まず、`.ug9` には入らない。一般に、コンパイラは知らない欄を無視するが、エディタなどが自分用の情報を置く時は、ほかと重ならないようトップの `source` のような決まった欄にまとめる。

**editor**：エディタの道具の設定（球体・円柱デフォーマの形、パーツの奥行きなど。中身はエディタが決める。`docs/球体デフォーマ.md`）。`source`（取り込み元の情報）とは分ける。コンパイラとランタイムは読まず、`.ug9` には入らない。道具が焼き込んで作ったデフォーマには、`deformers[]` の中に `"baked": "<道具の中の id>"` の印を付けてよい。コンパイラはこの印を読まずに通す（出力は印が無い時と同じバイト）。焼き直す時は、その印の付いたデフォーマだけを入れ替える。（デフォーマの `id` はアニメのトラックがモーフを指すための物で、モーフを持つデフォーマの間で重ならない必要があるので、印には使わない。）

- `editor.paramPairs`：結合した 2 本のパラメータの組の一覧（例 `[["AngleX","AngleY"]]`）。組の上が横の軸、下が縦の軸
- `editor.paramOrder`：エディタのパラメータの欄の並び（パラメータの `id` の一覧）。`parameters[]` の順は変えない
- `editor.savedBy`：保存したエディタ（`{ "app": "Ugo9 Editor", "version": "0.1.1", "formatVersion": "0.7" }`）。新しいエディタ・新しい形式で作られた物を古いエディタで保存し直した時は、その新しい版を `newerSeen` に残す。エディタが開く時に「新しい版で作られています」と知らせるのに使う。コンパイラとランタイムは読まない

どちらもエディタだけが使い、コンパイラは読まないので、`.ug9` は変わらない。

補間は `step`（次のキーまで据え置き）・`linear`（直線、既定）・`smooth`（なめらか）・`bezier`（曲線、v1.1〜）。キーは時間の順。

**曲線のキー**（v1.1〜、Spine の曲線に当たる）：`[秒, 値, "bezier", cx1, cy1, cx2, cy2]`。次のキーまでを、(このキーの時刻, 値) から (cx1, cy1)・(cx2, cy2) を通って (次のキーの時刻, 値) へ向かう 3 次ベジェで動く。cx は区間の時間の割合（0〜1。外の値は収めて警告）、cy は値そのもの（トラックの値の単位。範囲の外に出てよい）。smooth は cx1 = 1/3、cy1 = このキーの値、cx2 = 2/3、cy2 = 次のキーの値の曲線と同じ。曲線を 1 つでも使うモデルは `.ug9` が 1.1 になる（1.0 の芯では読めない。下の「曲線のキー（1.1）」）

アニメーションは、パラメータを動かす（Live2D 式）ことも、骨・不透明度・差分を時間で直接動かす（Spine 式）こともできる（v0.2〜）。骨のトラックは基準の姿からの差で、パラメータが動かす分と足し合わされる。不透明度のトラックはパーツ自身の不透明度を置き換え、パラメータが動かす分はその上に足される。毎フレーム `reset_params` で全部が基準に戻る。

**マスク**（v0.4〜）：`mask` に並べたパーツの形の和（画像の透明度。`solid` のパーツはメッシュ全体）の中だけに描く。`maskInvert` なら外だけ。マスクは描く順に関係なく決まり、マスクにするパーツの不透明度は見ない（不透明度 0 のパーツもマスクとして働く）。マスクにされたパーツ自身のマスクは見ない（入れ子にしない）。Spine のクリッピングは、多角形を `maskOnly`・`solid` のパーツにし、クリッピングのスロットから終わりのスロットまでのパーツに `mask` を付けて表す。

**ワープ格子**（v0.5〜）：Live2D のワープデフォーマに当たる。格子に入れたパーツの頂点は、格子の制御点が作る曲面で曲がる（骨では動かない）。

- 曲面：制御点の外側に 1 周、延長の点（P₋₁ = 2P₀ − P₁、反対側も同じ。角は縦横の順に延長）を足し、一様な 3 次 B スプラインで結ぶ。曲面は外周の点を通り、内側の点は曲面を引っぱる点（曲面の上にはない）。基準の姿（等間隔の格子）では曲面は平らで、頂点は書いた所にそのまま来る
- 格子の外にはみ出した頂点は、端の傾きでまっすぐ延ばす
- 頂点・差分（morphs）・入れ子の格子の点と動きは、どれもモデル座標の px で書く。コンパイラが格子のマス目の座標に直す。そのため、格子の中の差分（目を閉じるなど）は、格子の曲がり（振り向きなど）と一緒に曲がる
- 一番外の格子は `bone` の動き（骨の行列 × 基準の逆）で動き、入れ子の格子は親の曲面の上で動く
- 差分の px はどれも「骨と親の格子で動かす前の、基準の姿のモデル座標」（格子の `rect` と同じ空間）。今の位置から逆に求めるには、`UgoInstance.warpEval`（`ugo_warp_eval`）の差分で解く
- **格子の中の骨**（Live2D の回転デフォーマ）：骨に `"warp"` を書くと、その骨の根元は格子の曲面の上を動き、向きはその点での格子の横の線の傾きだけ回る（格子の伸び縮みは受け継がない）。骨自身の回転・位置・拡大は今までどおりパラメータとアニメで動き、角度で補間するので縮まない。子の骨はそのまま付いていく。制限：`parent` は書かない、その骨と子孫を制約で使わない、その骨と子孫にワープ格子を付けない（コンパイラがエラーにする）
- **格子の角度**（v1.0〜）：`angle`（度）を書くと、`rect` を格子自身の向きで見た四角として、その中心のまわりに回す（パーツに一番隙間の少ない外接長方形を、そのまま格子にできる）。マス目の i, j（点の番号の並び）は回した向きに沿う。頂点・差分・格子の点の動き（`deformers[].warps`）は回しても今までどおりモデル座標の px で書き、コンパイラが回転を戻してマス目に直す。基準の姿では、回した格子も平らで、頂点は書いた所に来る（B スプラインは 1 次の式をそのまま作るため）。骨で動く格子・入れ子の格子（親も子もそれぞれ角度を持てる）・格子の中の骨はどれもそのまま使える。格子の中の骨は、基準の姿での格子の向きを引いて回すので、回した格子に入れても基準の姿では回らない
- 格子の id を参照する所：`parts[].warp`、`warps[].parent`、`deformers[].warps` のキー、`bones[].warp`
- 見本：`tests/warp/`（顔の格子を頭の骨に付け、目の格子をその中に入れ、2 軸の角の補正と、目の格子の中の差分を持つ。`node tests/warp/make_model.mjs` で作り直す）
- アニメーションのトラックで格子を直接動かす物はまだ無い（パラメータの範囲で動かす）

**描画順**（v1.0〜、Live2D の描画順のキーに当たる）：パーツは描画順の値の小さい順に描く。同じ値なら `parts[]` の順（今までと同じ）。

- 値 =（アニメの `order` のトラックの値、無ければ `parts[].order`、既定 500）＋ Σ 範囲の重み ×（`deformers[].order` の値 − `parts[].order`）。不透明度と同じ足し方で、値は補間するので、2 つのパーツの値が交わった所で入れ替わる
- 値は −1,000,000〜1,000,000（目安は Live2D と同じ 0〜1000）
- `deformers[].order` には範囲が要る。アニメの `order` はパーツ自身の値を置き換え（重みで混ぜる）、毎フレーム `reset_params` で元に戻る
- どのパーツも 500 のままで、何も変えない時は、`.ug9` に描画順の表が入らない（今までと同じ大きさと速さ）
- 描く側：`ugo_draw_order(inst)` が描く順のパーツの番号、`ugo_draw_order_key(inst)` がその並びの印（保存の順なら 0、並びが変わると変わる）。Web の描き方は、並びの印ごとにインデックスの並びを作って覚え（8 通りまで。それより多いと古い物から作り直す）、隣り合うキャラで同じ並びの物をまとめて描く。描画順を使わないモデルの描き方は今までと同じ
- マスクは描画順に関係なく決まる（今までと同じ）

**表情**（v1.0〜、Live2D の表情に当たる）：笑顔・怒りなどを、パラメータの値の変え方の組として持ち、描く側が名前で選んで重さ w（0〜1）を付けてかける。

- 項目はパラメータの**名前**で書く。`set`：v ← v + (x − v)·w、`add`：v ← v + x·w、`multiply`：v ← v·(1 + (x − 1)·w)。複数の表情はかけた順に重なる
- かける時：アニメ（`ugo_apply_animation`）とトラッキング（`ugo_set_param`）の後、`ugo_update` の前。物理は表情で変わった値を入力に使い、パラメータで動く物（差分・骨・不透明度・色・格子・描画順）はみな付いてくる。範囲は `ugo_update` が今までどおり min〜max に収める
- フェード：芯は状態を持たない。描く側が毎フレーム重さを渡す（`fadeIn`・`fadeOut` はそのための値として入っている）。Web には `UgoExpressionMixer`（show・hide・update(dt)・apply）がある
- **プリセット**：表情だけの単独のファイル（拡張子 `.ug9x`）`{ "format": "ugo9-expressions", "version": 1, "expressions": [ ... ] }`（中身は作業用 JSON の `expressions` と同じ）。名前で書いてあるので、同じ名前のパラメータを持つ別のモデルにそのまま使える。`tools/expressions.mjs`（読む・書く・無い名前の一覧）、Web の `model.loadExpressions(preset)`（→ 無い名前の一覧と、かけられる形）・`model.exportExpressions()`
- 芯で別のモデル用の表情をかける：`ugo_resolve_params`（名前 → 番号を 1 回。無い名前は −1 で、その数を返す）と `ugo_apply_params`（毎フレーム。−1 は飛ばす）
- よく使うパラメータの名前は [パラメータの名前](パラメータの名前.md) に表がある（合わせると表情のプリセットが流用できる。形式は名前を決めない）
- コンパイラは、モデル自身の表情に無いパラメータの名前があればエラーにする（`unknownParam`、場所は `expressions[i].params.<名前>`）

**合成**（v0.4〜）：s は描くパーツの色（不透明度・色・マスクを掛けた後、アルファを掛けた形）、d は下の色。

| blend | 色（rgb） | アルファ |
|---|---|---|
| `normal` | s + d (1 − sa) | sa + da (1 − sa) |
| `add` | s + d | da（変えない） |
| `multiply` | s · d + d (1 − sa) | da（変えない） |
| `screen` | s + d (1 − s) | sa + da (1 − sa) |

**色**（v0.4〜）：画像の色 C（アルファを掛けた形）、アルファ a に対し、描く色は rgb = C · X + a · Y。

- `multiply` / `screen`（Live2D）：X = multiply × (1 − screen)、Y = screen。つまり c × multiply にスクリーン色を重ねた物
- `tint` / `dark`（Spine の二色）：X = tint − dark、Y = dark。暗い色だけを使わない時は dark = 0 で、tint を掛けるだけ
- Spine の色のアルファ（tint の a）はパーツの不透明度で表す

**骨の受け継ぎ方**（`inherit`、Spine と同じ 5 種類）：`normal`（全部）、`onlyTranslation`（位置だけ）、`noRotationOrReflection`（親の回転と裏返しを除く。拡大は受け継ぐ）、`noScale`（拡大を除く。裏返しは受け継ぐ）、`noScaleOrReflection`（拡大と裏返しを除く）。位置はどれでも親の行列で決まる。

**制約**は書いた順にかける。かけるたびに、動いた骨とその子孫だけを計算し直す。IK は目標の点に骨の向き（2 本なら余弦定理で肘の角度）を合わせる。transform は目標の骨の世界（または親からの）回転・位置・拡大・せん断に、`mix` の割合で寄せる。`mix` が負なら逆向きに動く（打ち消し用）。計算の決まりは `tools/skeleton_pose.mjs` と `core/src/ugo.c` が同じ物を持ち、`tests/pose_test.mjs` が両方を突き合わせる。

**のり**（v0.6〜）：コンパイラが、組の 2 つの頂点に同じ動きを配る。差分（morphs）と骨の重みのそれぞれについて、合わせる先 =（1 − bias）× 1 つ目の物 ＋ bias × 2 つ目の物、とし、各頂点は自分の物から合わせる先へ strength の割合だけ寄せる。差分も骨の重みも足し算で効くので、strength 1 なら組の 2 点はどの姿勢でも同じ所へ動く（基準の姿で同じ位置にある時）。`.ug9` の形は変わらない（頂点の差分と重みが変わるだけ）。

**四隅の補正**：形式は前から対応している。範囲に軸を 2 つ書くと、その範囲の重みは各軸のテントの積になり、角（例 AngleX = 30 かつ AngleY = 30）だけで効く差分になる。角で見た目がずれる時は、「角で見せたい形 − 各軸だけの差分の和」をその範囲に書く。作りやすくするのはエディタの仕事。

**骨の鎖**（v0.6〜）：鎖の関節（各骨の根元と、最後の骨の先＝`length`）を点にして、1/120 秒刻みの Verlet 法で動かす。根元の点はアニメの姿に固定。他の点は、アニメの姿へ戻るばね（`stiffness`）・減衰（`damping`）・重力（`gravity`）で動き、骨の長さ（アニメの姿での長さ）を根元から順に保つ。キャラの置き方（`ugo_set_transform`）が前の更新から動いた分は、モデル座標に直して点を逆に動かす（`inertia` の割合）。最後に各骨を次の点の方へ回す（`mix` の割合。角度で回すので縮まない）。計算は骨・制約の後、ワープ格子の前。制限：鎖の骨を制約で動かさない（目標にするのは可。鎖で揺れる前の姿を読む）、格子の中の骨は鎖にしない、1 本の骨は 1 つの鎖だけ。`ugo_reset_physics` で止まった状態に戻る。

物理の出力は「ばねの位置 − 入力」× gain で、入力が急に動くほど大きく揺れ、止まると 0 に戻ります。1/120 秒より細かい刻みで計算し、同じ入力なら同じ結果になります。

**範囲の重み**（可変フォントと同じ）：値が peak なら 1、start 以下・end 以上なら 0、間は直線。`[0, 0, 1]` のように start = peak なら、0 で 1、1 に向かって 0 へ。

## 配布用 `.ug9`（バイナリ）

全てリトルエンディアン、4 バイト境界。ヘッダの後に表の目次があり、表はそこに書いた位置にある（1.0〜）。ファイルの大きさが合わない・目次の表がファイルの外や重なり・数や番号が範囲外・浮動小数点が NaN か無限大、のどれかなら読み込みを断ります。

### 版の決まり（1.0〜、2026-11-09 ユーザーの決定）

Live2D の「新しい版で保存した物が古い版で開けない」を避けるための決まりです。

- 版は主・副。**主が同じなら、副が上でも下でも読む**（1.0 の芯は 1.x を全部読む）。主が違えば読まない（`UGO_ERR_VERSION`）
- **副を上げる**（古い芯でも読める）変更：新しい種類の表を足す、ヘッダーの後ろに欄を足す、新しいトラックの種類を足す
- **主を上げる**（古い芯では読めない）変更：今ある表の 1 件の形や意味を変える、今ある欄の値の意味を変える。避ける。今ある表の 1 件に欄を足したい時は、同じ件数の「追加の表」を新しい種類で足す（副で済む）
- 古いファイル（副が下）は、新しい表が無い＝その機能を使っていない、として読む
- 新しい種類の表には、知らない芯がどうするかの印を書く側が付ける（目次の flags の下 2 ビット）
  - 0：飛ばしてよい（絵は変わらない：名前・エディタ用の情報など）
  - 1：飛ばすと絵が変わる（新しい変形・描画の仕組みなど）。古い芯は飛ばして読み、`ugo_model_warnings(m)` に `UGO_WARN_SKIPPED_TABLE` を立てる（Web は console に警告、`UgoModel.warnings`）
  - 2：分からないと正しく動かない。古い芯は読まない（`UGO_ERR_VERSION`。Web は「update the player」と言い、`e.code` は `ugoNewer`）
- **機能の印**：件数 0 の目次の行も書ける。今ある欄に新しい値を入れる時（例：合成の種類 4 を足す）は、その機能の印を印 2 で書き、古い芯が黙って読み間違えないようにする
- 知らない種類のトラックは、古い芯は再生で飛ばし、`UGO_WARN_SKIPPED_TRACKS` を立てる（トラックは種類ごとにまとまって並ぶ）
- 版を上げる PR は、この決まりのどれに当たるかを説明に書く。`tests/future/`（後の 1.x を真似たファイル）と compile_test の「前の芯が後の版を読める」確かめを、新しい表やトラックの種類ができるたびに足す
- 0.x（0.7 まで）は 1.0 の芯では読まない（作業用 JSON からコンパイルし直す）。0.7 → 1.0 が最後の「読めなくなる」上げ

差分の項目は**頂点ごと**に並んでいます（GPU が頂点ごとに自分の項目だけを読むため）。

**マスクのチャンネル**：同じパーツの組のマスクは 1 件にまとめる。マスクが 16 件以下なら 1 件ずつ別のチャンネル。それより多い時は、基準の姿で範囲（マスクと、それで切り抜くパーツを 25% 広げた四角）が重ならないマスクどうしでチャンネルを共有する（`compile.mjs`）。描く側は、全キャラのマスクを先に画面と同じ大きさの画像のチャンネルへ描き、本番の描画でそこを読む（[設計](設計.md#マスクと合成)）。

**フレームの塊**（0.4〜）：差分の重みの後に、色ごとに 8 個（X の rgb、0、Y の rgb、0）が続く。その後に格子ごとに、延長の点を含む (cols+3)×(rows+3) 点のモデル座標（x, y、行ごと。4 の倍数にそろえる）が続く（0.5〜）。マス目の座標 (x, y) の頂点は、floor(x)・floor(y) から 4×4 点を、端数 t の B スプラインの重み ((1−t)³, 4 − 6t² + 3t³, 1 + 3t + 3t² − 3t³, t³) / 6 で足す。

**キーの丸め**（0.7〜）：コンパイラは、時刻を刻みの近い整数に丸める（同じ時刻のキーが 2 つある飛び＝step などは切り捨てて、遅れないようにする）。値はトラックの幅（最小〜最大）の 65535 分の 1 の近い整数に丸める。丸めの差は、時刻が刻みの半分（8 秒のアニメで 0.06 ms）、値が幅の 131070 分の 1（幅 360° で 0.003°、幅 400 px で 0.003 px）まで。値がずっと同じトラックはキーを持たず、値をそのまま f32 で持つ（丸めない）。

### 曲線のキー（1.1、2026-11-10 ユーザーの決定。芯は読める。コンパイラは準備中）

曲線（3 次ベジェ）のキーを持つための表です。曲線を使うモデルは、トラックとキーを表 21・22 の代わりに表 41・42・43 で書き、ヘッダの副版を 1 にします（41〜43 の目次の印は 2：1.0 の芯は読まずに「update the player」）。曲線を使わないモデルは今までどおり 21・22 の 1.0 で書く。1 つのファイルに 21・22 と 41〜43 の両方は書かない（読まない）。

芯は読み込む時に、41〜43 を 21・22 と同じ形のトラックとキーに広げます（曲線は短い直線に分ける）。再生の仕組みは 1.0 と同じで、速さも変わりません。広げたトラックとキーはモデルのメモリに置くので、1.1 のファイルには `ugo_model_mem_size_for(data, size)` のバイト数を渡して `ugo_model_init_sized(mem, mem_size, data, size)` で読みます（`ugo_model_init` は 1.0 の大きさ：表 41〜43 を持つファイルは、曲線が無くても `UGO_ERR_SIZE`。読む側は、どの版のファイルにも mem_size_for と init_sized を使えばよい）。JS の同じ計算は `tools/curve_keys.mjs`（`expandTracks`・`readCurveTracks`。芯とビット単位で同じ）。

**トラック 1.1（41）**：1 件 12 バイト。アニメーションの「最初のトラック・トラック数」はこの表の番号。

| バイト | 中身 |
|---|---|
| 0 | 対象 u32（21 と同じ：最上位ビットが「なめらか」の印、続く 7 ビットが種類、下位 24 ビットが番号） |
| 4 | base f32 |
| 8 | step f32。0 ならキーを持たず、値は base（21 のキー数 1 に当たる） |

**キー 1.1（42）**：4 バイトの語の並び。step が 0 でないトラックごとに、トラックの順に：

| 語 | 中身 |
|---|---|
| 0 | キー数 n u32（2 以上） |
| 1〜n | キー：t u16、v u16（22 と同じ。値 = base + v × step） |

語が足りない・余る・キー数が 2 未満なら読まない。

**キーの曲線（43）**：1 件 16 バイト。キーの番号の順（同じ区間に 2 つは無い）。

| バイト | 中身 |
|---|---|
| 0 | key u32：区間の始まりのキーの、表 42 の中の語の番号（キー数の語や、トラックの最後のキーは指せない） |
| 4 | n u16：分ける数（2〜256） |
| 6 | cx1 u16：1 つ目の制御点の時刻。区間の時間の割合 × 65535 |
| 8 | cy1 u16：1 つ目の制御点の値。キーの v と同じ単位（0〜65535） |
| 10 | cx2 u16、12 cy2 u16：2 つ目の制御点 |
| 14 | 予約 u16（0） |

区間（キー a = (t0, v0) から次のキー b = (t1, v1)）は、(0, v0)・(cx1/65535, cy1)・(cx2/65535, cy2)・(1, v1) の 3 次ベジェ（x は区間の時間の割合、y は値）。芯は s = i/n（i = 1〜n−1）の点を、整数だけで正確に計算します（u = n − i として）：

- 時刻 = t0 + round(X × (t1 − t0) / (65535 n³))、X = 3u²i·cx1 + 3ui²·cx2 + i³·65535
- 値 = round(Y / n³)、Y = u³·v0 + 3u²i·cy1 + 3ui²·cy2 + i³·v1
- round は半分を上へ（floor((2x + d) / 2d)）。どの機械でも同じ結果
- 時刻が前の点（または a）より後でない点、t1 より前でない点は捨てる

「なめらか」の印のトラックに曲線は付けない（読まない）。t1 < t0 の区間も読まない。広げた後のキーは 1.0 のキーと同じに確かめる（時刻の順、数の上限）。

コンパイラは、曲線ごとに n を `tools/curve_keys.mjs` の `curvePieces`（直線に分けた時のずれが許す幅に収まる最小の n）で選び、cy が 0〜65535 に収まるようトラックの最小・最大を制御点まで広げます。smooth は、トラックのキーが全部 smooth なら今までどおり印。直線や曲線と混ざるトラックでは、1.1 のファイルでも今までどおり短い直線に分けて書く（曲線にすると、キーの時刻が刻みに丸められた分だけエディタの値と値の刻み 1〜2 つずれるため）。曲線を使わないモデルが smooth のためだけに 1.1 になることはない。ほかのコンパイラが smooth を cx1 = 1/3、cy1 = v0、cx2 = 2/3、cy2 = v1 の曲線で書くのはかまわない（smoothstep と同じ形。読み込みは smooth に戻す）。
