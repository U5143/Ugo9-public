## 形式 0.8（2026-11-04 ユーザーの決定）

芯と形式の担当の案を、4 つとも勧めのとおりに決めた。
- 格子の角度：`warps[].angle`（度、省略で 0）。`rect` は格子自身の向きで見た四角、`angle` はその中心まわりの回転。格子の中の骨の表を 24→40 バイトにして、回した格子にも骨を入れられる（骨 1 本 +16 バイト、速さは同じ）
- 描画順のキー：`parts[].order`（0〜1000 の目安、既定 500）、`deformers[].order`（その範囲の頂点での値）、`animations[].order`。値は不透明度と同じ足し方で補間し、小さい順に描く（交わった所で入れ替わる。同じ値はパーツの並び順）。.ugo に表を 2 つとトラックの種類 12 を足す。使わないモデルは今と同じ手間
- ヘッダーの数の欄を 32→48 に広げる（+64 バイト。この先の表の増えに備える）
- 0.7 の .ugo は読まず、「作業用 JSON からコンパイルし直して」のエラーにする（0.6→0.7 の時と同じ）。作業用 JSON はそのまま使える
- 入れる時：Unity・Godot の確かめは CI でしかできないので、作っておき、CI が戻ってから Unity・Godot まで通して main に入れる。それまで main は 0.7。芯の PR に、読み込み・書き出し（ugo_three.js・cli）とゲームエンジン（Unity・Godot）の対応を、それぞれのブランチから PR で集め、1 つにまとめて入れる
