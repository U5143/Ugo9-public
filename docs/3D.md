# 3D の場面に置く

Ugo9 のキャラを 3D アプリの中に置く方法は 3 つある。

| 方法 | 動き | 使える所 | 確かめたこと |
|---|---|---|---|
| ① Ugo9 の部品で描く（`web/ugo_three.js`） | 全部（表情・揺れ物・透け・トラッキング・パラメータ） | three.js（Web の 3D）。各ゲームエンジン用は今後 | 正面から見た絵が 2D の描画と完全に同じ（差 0）。カメラを向く・箱に隠れる |
| ② glTF に焼いて書き出す（`tools/export_gltf.mjs`） | 決まったアニメーション。透けは表示・非表示の切り替え | Blender・Godot・three.js・Unity・Unreal など | Blender 5.2.3・Godot 4.7.2・three.js r186 で読み込み、絵が一致 |
| ③ VRM 1.0 に書き出す（`tools/export_vrm.mjs`） | 表情・まばたき・口・目線・揺れ物。振り向きは板が回る | Warudo・VMagicMirror など 3D の VTuber アプリ | pixiv の three-vrm で読み込み、表情ごとの絵が Ugo9 と一致 |

## ① Web の 3D に Ugo9 のまま置く

ランタイムが読むファイルは `.ug9`（2026-11-07 に `.ugo` から名前を変えた。中身は同じで、道具は `.ugo` の名前も読む）。

```js
import * as THREE from 'three';
import { UgoRuntime, loadImage } from './ugo.js';
import { UgoThreeCharacterFactory } from './ugo_three.js';

const rt = await UgoRuntime.load();
const model = rt.loadModel(await (await fetch('model.ug9')).arrayBuffer());
const factory = new UgoThreeCharacterFactory(THREE, model, new THREE.Texture(await loadImage('atlas.png')));
const ch = factory.create({ metresPerPixel: 1.6 / model.canvas[1], billboard: true }); // 1.6 m の背丈、カメラを向く
scene.add(ch);
// 毎フレーム
ch.instance.reset(); ch.instance.play('idle', t); ch.instance.update(dt); ch.sync(renderer); // マスクのあるモデルは renderer が要る
```

- 変形は GPU で行い、2D 版と同じシェーダーを使う。1 体ごとに描画 1 回
- `billboard: true` で、いつもカメラを向く（立ち位置と大きさは保つ）
- `depth` で、パーツを少しずつ手前にずらせる（カメラが動くと少し立体的に見える）
- デモ：`node tools/serve.mjs` → `http://localhost:8099/web/three3d.html`（3D の場面を歩き回るキャラ）

## ② glTF に焼いて書き出す

```
node tools/export_gltf.mjs model.ug9 out.glb [--height 1.6] [--depth 0.002] [--lit] [--billboard] [--fps 30]
```

| 設定 | 意味 |
|---|---|
| `--height 1.6` | キャラ（モデルのキャンバス）の高さをメートルで。省くと 1 px = 1 cm |
| `--depth 0.002` | パーツごとに手前へずらす量（メートル）。**Blender（Cycles）には必須**（下） |
| `--lit` | 場面の光で陰影を付ける（法線を足し、光を受けない設定を外す）。省くと 2D の絵のまま |
| `--billboard` | 「カメラを向く」印を付ける（glTF に決まりは無いので、各エンジンで小さなスクリプトが要る） |

キャラ全体は「Ugo9 character」という 1 つのノードの下にまとまり、これを動かせばキャラが動く。印や大きさは、そのノードの extras（`ugo9`）に入る。

### 行き先ごとの注意

- **Blender 5.2.3**（確認済み）：骨 15・シェイプキー 13（名前付き）・アクション（idle・talk）・素材（半透明）が読み込まれる。Cycles は光線をたどって描くので、描く順番を使わない。**全部のパーツが同じ深さだと、どれが手前か決まらず、絵が崩れる**。`--depth 0.002` を付けると Ugo9 と同じ絵になった（`tests/gltf/verify_blender.py`）
- **Godot 4.7.2**（確認済み）：読み込みの設定「Remove Immutable Tracks」を切る（切らないと、アニメを切り替えた時に前の姿が残る）
- **three.js r186**（確認済み）：そのまま
- **Unity・Unreal**：公式の説明では読める（glTFast・Interchange）。この環境では未確認

詳しい検証の結果は [検証_glTF.md](検証_glTF.md)。

## ③ VRM 1.0（3D の VTuber アプリ用）

```
node tools/export_vrm.mjs model.ug9 out.vrm [--height 1.0] [--name 名前] [--author 作者] [--expressions 表情.json] [--spring 骨1,骨2]
```

- キャラは +Z を向いた 1 枚の板のまま。VRM が必ず求める腕・脚の骨は、動かない骨として足す（胸から下が無い 2D のキャラでも読み込める）
- **表情は Ugo9 で計算して焼く**：まばたき・口・目線・眉などを、パラメータの値ごとに Ugo9 の芯で計算し、ブレンドシェイプにする。その時に見えないパーツ（開いた目と閉じた目など）は 1 点に縮めて入れるので、まばたきで閉じた目に切り替わる
- 表情とパラメータの対応は、標準の名前（[パラメータの名前.md](パラメータの名前.md)：EyeOpenL・MouthOpen・PupilX・BrowHeightL など）を既定にしている。前の名前（EyeBallX・EyeBallY・BrowY）や Param の付いた名前のモデルも、そのまま当たる（2026-11-12、利用者の声 #409）。違う名前のモデルは `--expressions` の JSON で決める（例 `{"blink": {"EyeOpenL": 0, "EyeOpenR": 0}, "aa": {"MouthOpen": 1}}`）。画面の左の目は、キャラにとっての右目（VRM の blinkRight）
- 目線は VRM の「expression」型（lookLeft など）で動く
- 揺れ物：名前に hair・ribbon・tail・skirt などを含む骨を、VRM の揺れ物（spring bone）の鎖にする。`--spring` で指定もできる
- 頭の左右の向きは、アプリが頭の骨を回すので**板が回る**（Ugo9 自身の振り向きは使われない）。VRM には頭の向きでブレンドシェイプを動かす決まりが無いため
- **VRM で動かない物は、書く前に知らせる**（2026-11-12、利用者の声 #400 の 5）：アニメ（VRM には無い：`vrmAnimations`）、どの表情も使わないパラメータ（頭と体の向きはアプリが骨を回す：`vrmParamsUnused`）、物理で揺れるパラメータ（揺れ物の骨の鎖だけが spring bone になる：`vrmPhysicsParams`）。`checkExport(model, 'vrm')` の知らせ（エディタの書き出しの窓）と、`export_vrm.mjs` が書く前に出す行。マスク・合成・色・描画順・制約なども同じ所で知らせる（[警告の一覧.md](警告の一覧.md)）
- 使用条件（meta）は最も厳しい既定値（本人のみ・非営利・再配布不可）にしている。配る前に、自分の条件に直す

### 確かめたこと（`tests/vrm_test.mjs`）

- pixiv の three-vrm 3.5.5 で VRM 1.0 として読み込める。人型の骨・表情 15 個・揺れ物の関節が見つかる
- 表情ごとに Ugo9 の絵と比べた：通常・まばたき・片目・口（aa）・目線・驚きで、差が 16 を超える画素は 0〜50 個（25 万画素中）
- 体を横に動かすと、揺れ物で髪の骨が 35 度ほど揺れる
- 実際の VTuber アプリ（Warudo など）では未確認

## 骨の形が複雑なモデル（Spine から持ち込んだ物など）

IK・transform 制約・せん断・normal 以外の受け継ぎ方を使うモデルは、glTF の親子の骨では表せない。`export_gltf.mjs` はこの時、自動で骨を**平らに**書く（`--flat` で常にそうする）：

- 骨はすべて「Ugo9 character」の直下に並ぶ。1 本の骨を 2 つのノードで表す：`骨名:basis`（位置・回転・拡大）と、その子の `骨名`（回転、裏返しの ±1）。この 2 つで、せん断を含むどんな 2D の行列も正確に表せる（極分解と固有分解）。肌（skin）の関節は `骨名` の方
- 毎フレーム、芯が計算した骨の世界行列を焼く。制約・受け継ぎ方・せん断は全部入る。手で骨を動かすための骨組みではなくなる（親子が無い）
- キーは、直線（回転は球面の補間）でつないで済む所を間引く（ずれ 0.002 px・0.001 度以内）

**見え隠れ**：アニメで見え隠れするパーツ（Spine の付け替え・描く順の複製）も探して隠す（前はパラメータで動く物だけだった）。1 本の骨にだけ付いたパーツは、今までどおり「見え隠れの骨」を縮める。複数の骨に重みのあるパーツは、そのパーツ専用に、使う骨ごとの写し（`vis:パーツ:骨`、骨の子）を作る。隠れている間は、写しを全部 1 点に集めて縮める。

**確かめたこと**（`tests/gltf_skin_test.mjs`）：glTF の決まり（ノードの親子、キーの補間、関節の行列 × 逆バインド行列、変形キー）をテストの中で計算し、全部の頂点と見え隠れを芯と比べる。

| モデル | 骨 | 全姿勢での最大のずれ | 見え隠れ |
|---|---|---|---|
| `tests/pose/rig`（IK 1 本・2 本、transform、せん断、受け継ぎ方 5 種） | 15 | 0.001 px | 一致 |
| `samples/basic`（親子のまま／`--flat`） | 9 | 0.02 px | 一致 |
| 提供の Spine 5 体（提供のモデル A〜E、`build/` で確認） | 91〜395 | 0.05 px 未満 | 一致 |

three.js r186 でも、提供のモデル E を読み込んで、頂点の位置・見え隠れが芯と一致した。絵の差は細い線のふちだけ。

**three.js で使う時の注意**：three.js は両面表示の半透明の素材を「裏向き → 表向き」の 2 回に分けて描くので、裏返った（反転した）パーツが先に描かれ、順番が崩れる。`material.forceSinglePass = true` にする。

**骨の重みが 5 本以上**（形式 0.4〜）：4 本ずつ `JOINTS_1` / `WEIGHTS_1`、`JOINTS_2` … に入れる（提供のモデル C：最多 9 本で 3 組）。Blender・Godot・Unity は読むが、three.js は最初の 4 本しか使わない。`tests/gltf_skin_test.mjs` で、7 本の重みを持たせた見本が芯と一致することを確かめた。

**ワープ格子**（形式 0.5〜）：glTF に格子の仕組みは無い。格子の中のパーツは、格子の付いた骨（一番外の格子の骨。骨が無ければ 0 番の骨）に丸ごと付け、基準の形で書く。格子の曲がりはモーフ（ブレンドシェイプ）にする：パラメータごとの両端と半分の所の形、それに 2 つのパラメータの組の角の形（組が多すぎる時は省く）。焼いたアニメでは、毎フレーム、芯の形に一番近くなるモーフの重みを最小二乗で選ぶ。`tests/warp`（入れ子の格子・骨付き・2 軸の角の補正・アニメ）で最大 0.002 px、`tests/pose/rig` で 0.000 px。モーフを手で動かす時（パラメータの代わり）は、組み合わせの形が足りず、ずれることがある。格子の中の骨（回転デフォーマ）があるモデルは、骨を平らに書く（親子では格子の上の動きを表せないので、書き出す前に確かめて自動で切り替える）。

VRM：格子の中のパーツは、格子の骨に付け、表情ごとに芯が計算した形を焼く（表情はもとから Ugo9 で計算して焼いているので、格子もそのまま効く）。

**骨の鎖の揺れ物**（形式 0.6〜）：鎖があると骨を平らに書き、揺れた後の骨を毎フレーム焼く（`tests/pose/rig` の鎖で芯と 0.002 px）。焼いたアニメの揺れは書き出した時の物で、エンジンの中でキャラを動かしても揺れない。VRM では、モデルの鎖をそのまま VRM の揺れ物（springBone）にする（`--spring` を書いた時と、鎖の無いモデルは、今までどおり名前で選ぶ）。式が違うので値を換算する：

| VRM | Ugo9 の鎖から |
|---|---|
| dragForce | 1 − e^(−damping/60)（60 fps の 1 フレームで残る動き） |
| stiffness | 0.1 · √stiffness · 骨の長さ（m） |
| gravityPower | stiffness · \|gravity\| / (鎖の stiffness · 骨の長さ（px））（止まった時の垂れ方が同じ） |
| gravityDir | gravity の向き（y を上向きに） |

VRM の揺れ物は「一定の速さで元の向きへ戻る」作りで、Ugo9 の鎖（ばね）と式が違う。0.1 は、体を動かした後の揺れの最大が合うように合わせた値（ばね 10〜100・減衰 2〜8 でおおむね ±10%、ばねと減衰がどちらも強い時は 1.5 倍ほど）。three-vrm で、見本の髪の鎖が VRM 29.8 度・Ugo9 28.7 度揺れた（`tests/vrm_test.mjs`）。`inertia`・`mix` は VRM に無い（1 として動く）。

**大きさ**：骨が多く、アニメも多いモデルは大きい（提供のモデル C：骨 205 本・36 アニメで 23 MB。キーを間引く前は 78 MB）。JSON が約 4 割（トラックの数が多い）。

## ブラウザから書き出す（エディタの書き出しの窓）

コマンド（`node tools/export_gltf.mjs`・`export_vrm.mjs`）は、ファイルを読み書きするだけの薄い物。書き出しの中身は、ファイルを使わない関数で、ブラウザでも動く。

```js
import { UgoRuntime } from './web/ugo.js';
import { exportGlb } from './tools/gltf_export.mjs';
import { exportVrm } from './tools/vrm_export.mjs';
const rt = await UgoRuntime.load();
const { glb } = exportGlb(rt, ugoBytes, pngBytes, { height: 1.6, depth: 0.002, lit: false, billboard: false, fps: 30, log: (s) => notes.push(s) });
const { vrm } = exportVrm(rt, ugoBytes, pngBytes, { height: 1.0, name: 'model', author: 'Unknown', expressions, spring: 'hairL1,hairR1', log });
```

- `ugoBytes` は .ug9（作業用 JSON を `compileUgo` した物）、`pngBytes` はアトラスのページの PNG の配列（`model.textures` の順。1 ページなら Uint8Array 1 つでもよい）
- ページが 2 つ以上なら、画像とマテリアルをページごとに分け、続けて同じページを使うパーツの並びごとに primitive を 1 つにする（描く順は保つ）
- `maskOnly` のパーツ（マスクにだけ使う物）は描かない。マスクの効果が書けないことは `checkExport` の `exportMasks` で知らせる
- オプションはコマンドの `--` の物と同じ意味。`log` に、書き出しの警告と知らせ（コマンドが表示する物）が来る
- `exportVrm` は head・body の骨が無いと、code `vrmNoHumanoid` のエラーを投げる（`checkExport` で先に分かる）
- コマンドの出力は、分ける前とバイト単位で同じ。ブラウザで書き出した物もコマンドと同じバイトになることを `tests/export_browser_test.mjs` で確かめている

## 書き出す前の確かめ（`tools/check_export.mjs`）

書き出す前に、その書き出し先で失う物を一覧にする関数。エディタは書き出しの窓で、書き出す前に見せる。作業用 JSON だけを読む（wasm は要らない）。

```js
import { checkExport } from '../tools/check_export.mjs';
const { notes, ok } = checkExport(model, 'gltf'); // 'ugo' | 'gltf' | 'vrm'
```

- `notes`：`{ code, level, vars, text, fix }` の並び（`warnings` に同じ順の英語の文）
  - `level`：`error`（書き出せない）・`warn`（書き出し先で絵や動きが変わる）・`info`（別の形で書くが、ほぼ同じ）
  - `vars`：パーツの名前（`parts`）・骨の名前（`bones`）・物の名前（`names`）は最初の 10 個、`count` は全部の数
  - `fix`：直し方の一言（英語）。エディタは code と vars から自分の言葉で書く（日本語の文は [警告の一覧.md](警告の一覧.md)）
- `ok`：`error` が無い
- 行き先：`ugo`（.ug9 をそのまま描く物：Web・three.js・Unity・Godot・PNG・GIF・動画。コンパイラ自身の警告だけ）、`gltf`（tools/export_gltf.mjs）、`vrm`（tools/export_vrm.mjs）
- どの行き先でも、コンパイルできないモデルは `exportCompileError`（error）だけを返す

## まだできないこと

- VRM：人型の骨は親子が要るので、平らな骨は使えない。複雑な骨のモデルを VRM にする方法はまだ（書き出すと警告が出る）
- マスク・合成モード・パーツの色（形式 0.4〜）は glTF に書けない。書き出す時に警告が出る（マスクの無い絵、通常の合成になる）
- 描画順（形式 0.8）：glTF・VRM には、基準の姿の順で書く（三角形の並びと、パーツの奥行き）。パラメータやアニメで順が変わる所は書けない。書き出す時に警告が出る
- ワープ格子の角度（形式 0.8）：格子は芯で計算してから焼くので、そのまま書ける
- VRM：骨の重みは 4 本まで（5 本目からは捨てて警告）
