# 球体・円柱デフォーマ（設計の下書き）

2026-11-01 ユーザーの決定（ハブ経由）。エディタが取りまとめ、読み込み・書き出し（焼き込みの計算）と芯と形式（作業用 JSON の置き場所）と 3 者で決める。**3 者の案をまとめた版（2026-11-01）。ハブへ送った。**

## 何を作るか

顔の XY・体の丸い所を、四角の格子ではなく「球（楕円体）や円柱が回る・伸び縮みする」動きで変形する道具。

| 道具 | 動き | 主な使い道 |
|---|---|---|
| 球体 | 楕円体を左右（yaw）・上下（pitch）に回す。半径を伸び縮みさせる | 顔の向き、頭、胸・お尻などの丸い所 |
| 円柱 | 縦の軸のまわりに回す（ひねり）。半径を伸び縮みさせる | 体のひねり、腕・脚 |
| パーツの奥行き | パーツごとの「面からの高さ」。回すと高さに応じて多く・少なく動く（視差） | 目・鼻・前髪は手前、耳・後ろ髪は奥 |
| 引き伸ばし・つぶし | 半径（や高さ）をパラメータで変える | 驚き・つぶれ、呼吸 |

## 入れ方（A：決定）

- エディタの道具として作り、結果を**今の形式の物に焼き込む**：ワープ格子のキーの形（`deformers[].warps`）と、パーツの差分（`deformers[].morphs`）
- `.ugo` と芯（ランタイム）は変えない。今の再生の部品（Web・Godot・Unity…）で、そのまま動く
- 芯に新しいデフォーマとして入れる案（B、形式 0.7）は、A で見た目を確かめてから決める

## 今の問題（face_angles.mjs）と、直し方

| 問題 | 原因 | 直し方 |
|---|---|---|
| キーの間（15° あたり）で、顔の縁が半径の約 3% 内側に寄る | キーが ±30° と四隅だけで、キーの間は点が直線で動く（弦） | キーを細かくする。弦の誤差は `r (1 − cos(Δθ/2))` なので、10° ごとで 0.38%、15° ごとで 0.86% |
| 楕円の縁で動きが折れ、四隅が歪む | 楕円の外の点を奥行き 0 として回すため、縁で動きの傾きが飛ぶ | 縁の外は「減り方」（falloff）で、動きを 0 までなめらかに減らす（縁で値も傾きも続く） |
| 粗い格子では曲面が合わない | 格子の点は B スプラインの制御点で、面の上には無い（外周を除く） | 焼く時に、パーツの頂点の位置で合うように制御点を求める（今の face_angles の当てはめを広げる）。格子の細かさの目安を道具が出す |

### 今の値（tests/sphere_metric.mjs、2026-11-01）

測るための円盤（楕円 100×120 px を 8 px ごとのメッシュ、外に 1.6 倍までの輪）を格子に入れ、今の face_angles（キー 8 つ、奥行き 0.6、左右 ±30°・上下 ±20°）で焼き、芯で動かして頂点を正確な楕円体と比べた。

| 格子 | 楕円の中のずれ（最大、半径に対して） | 1.3 倍より外の動き | .ugo |
|---|---|---|---|
| 6×6 | 9.2%（30°・30° の角）。キーの上の 30°・0° でも 7.9%、15°・0° で 6.6% | 最大 36 px | 114 KB |
| 12×12 | 8.0% | 36 px | 123 KB |
| 24×24 | 6.3% | 36 px | 155 KB |

- キーの上でも大きくずれる。細かい格子でもあまり減らない。主な原因は**縁の外**：楕円の外の点を奥行き 0 のまま回すので、縁で動きが折れ、外も 36 px 動く。なめらかな格子はこの折れに沿えず、内側まで乱れる
- なので、直す順は「1. 縁の外をなめらかに減らす」→「2. 頂点で合わせる当てはめ」→「3. キーを細かくする」がよさそう

## 設定（エディタの画面）

球・円柱ごとに：

- 種類（球・円柱）、名前
- 中心・半径（x・y）・奥行き（z。半径に対する割合）。ビューポートで円・楕円をつかんで動かす
- 減り方：縁の外のどこまで動きを残すか（半径の倍率、例 1.3）
- 回す角度の範囲：左右・上下（例 ±30°・±20°）。どのパラメータで回すか（既定 AngleX・AngleY。円柱は BodyAngleX など）
- キーの細かさ（既定 10°）
- 引き伸ばし：どのパラメータで、半径を何倍にするか（任意）
- どの格子・パーツに焼くか（既定：中に入っているパーツを囲む格子を作る、または選んだ格子）

パーツごとに：奥行き（面からの高さ。半径に対する割合。既定 0）。パーツの欄に 1 つ。

「焼き直し」ボタン：設定を変えたら、焼いた物を作り直す。

## 作業用 JSON のどこに置くか（芯と形式と合意）

- トップに **`editor`** の欄を置く。エディタだけが読み、コンパイラは読まない（知らない欄は無視される。`.ugo` に入らない）。`source`（取り込み元の情報）とは分ける。芯と形式が docs/形式.md の `source` の節の横に「コンパイラは読まない欄」として書く
- 焼いたデフォーマには **`baked: "<shape の id>"`** の印を付ける（コンパイラは読まずに通す。芯の compile_test で「editor と baked があっても .ugo は同じバイト」を固定済み、ugo9/core 23d9d37）。デフォーマの `id` は、アニメのトラックがモーフを指すための物なので、印には使わない。焼き直しは、その印の物だけを消して作り直す。手で足したキーとは混ざらない
- 中身の形はエディタが決める：

```jsonc
"editor": {
  "shapes": [
    { "id": "head", "type": "sphere",             // sphere | cylinder
      "center": [0, -245], "radius": [92, 97],     // 楕円（円柱は横の半径だけ使う）
      "axis": 0,                                   // 円柱の軸の傾き（度）
      "depth": 0.6, "exact": 0.9, "falloff": 1.6,  // 奥行き（半径に対して）、正確な球の範囲、動きが 0 になる所
      "params": { "x": "AngleX", "y": "AngleY" },  // 円柱は x だけ
      "turn": { "x": 30, "y": 20 }, "step": 10,    // パラメータの端で何度回すか、キーの間隔（度）
      "stretch": { "param": "FaceStretch", "scale": [1.1, 0.9], "exact": false },   // 任意。最大で scale、最小でその鏡（2 − scale）
      "target": { "warp": "face" }                 // または { "parts": [...] }
    }
  ],
  "depth": { "eyeL": 0.15, "nose": 0.2, "earL": -0.3 }   // パーツの奥行き（半径に対して。手前が正）
}
```

## どう焼くか（読み込み・書き出しの案、測った値つき）

1. **球の形**：顔は半径の 0.9（`exact`）まで正確な楕円体。その外は奥行きを 3 次のなめらかな線（傾きもつながる）で下げ、1.6（`falloff`）で 0。球の半径を顔より少し大きく取れば、顔の上は全部「正確な球」の中に入る
2. **キーは 10° ごと**：±30° なら X・Y それぞれ 6 つ、2 軸の補正（交点の形 − 両方の軸の形）36、合わせて 48 の動き。2 軸の範囲は tent の積なので双一次の補間とちょうど合う（芯で確かめ済み）
3. **制御点は最小二乗で合わせる**：顔の中の点（パーツの頂点か細かい格子の点）が、格子の曲面の上で正確な楕円体の位置に来るよう解く（制御点に対して線形なので 1 回の連立方程式）
4. **焼く先**：球・円柱は**ワープ格子のキー**に焼く。格子は細かめ（例 8×8）にすると球に沿いやすい
5. **パーツの奥行き（視差）**：1 枚の格子は 1 つの曲面しか持てないので、奥行きのあるパーツは、格子の動きに加えて**パーツの差分**に焼く。差分は格子の前の基準の座標で、「格子を通した後に正しい位置に来る差分」を解く（今の中の格子と同じニュートン法）。**キーは粗く**（15° ごと、5×5 の 24 の動き）：芯と形式の計測で、差分は頂点ごとの数だけ GPU が毎コマ表を読むため（7×7 だと頂点ごとに 48、何体も出すと重い）。視差はほぼ平行移動なので、粗いキーでも誤差は小さい（数字は試して決める）
6. **円柱**：縦の軸まわりだけ回す（パラメータ 1 つ）。奥行きは横の位置だけで決まる。10° ごとで 6 つの動き
7. 返り値の形は今の下書き関数と同じ（`{ motions, params, notes, warnings }`）。動きの各デフォーマに `baked` を付けてもらう（または、エディタが書く時に付ける）。エディタは `motionsCommand` で 1 手に書く

## 後で決めること

- **引き伸ばし・つぶし**：角度と掛け合わせるとキーが掛け算で増える（半径 3 段なら 48 → 約 150）。(a) 半径のキーは 1 軸だけにし、角度とは足し算で合わせる（小さい・近似）、(b) 角度を 15° ごとにして 3 軸の掛け算（正確・大きい）。読み込み・書き出しが数字を出して決める
- **B（芯で再生の時に計算する案、形式 0.7）**：芯と形式が下に書く。A で見た目を確かめてから決める

### 後で：芯に入れる案（B、形式 0.7）（芯と形式）

- **計算**：形ごとに、中心・半径（楕円体なら 3 つ）・回転を持つ。回転（yaw・pitch から作る 3×3）は CPU で 1 回作り、フレームの塊に入れる。点ごとに、中心からの位置 (x, y) から z = √(1 − (x/rx)² − (y/ry)²)·rz（＋パーツの奥行き）で面に乗せ、3×3 をかけて正射影で (x, y) に戻す。縁の外は減り方でなめらかに 0 にする。点ごとの手間は掛け算 20 回ほどと平方根 1 回で、今のワープ格子（16 点の B スプライン）より軽い
- **データ**：形 1 つあたり、モデルに十数個の数（中心・半径・減り方の幅・どのパラメータで回すか）、フレームに 12 個の数（3×3 と中心）。パーツの表に「どの形に乗るか」と奥行き
- **入れ子**：形の中に格子（目など）を入れる時は、今の入れ子の格子と同じく、CPU で外側から順に計算する
- **各エンジン**：Web（シェーダー）、Godot、Unity、three.js、ugo_export（CPU）のすべてに同じ計算が要る。共通の部分は芯の C（ugo_deform_cpu）にも入れて、エンジンの結果を芯と比べるテストで合わせる
- **形式**：0.7 で、ほかの案（データの圧縮、鎖の名前）と一緒に 1 回で版を上げる。古い .ugo は作業用 JSON からのコンパイルし直しになる
- **A との関係**：A で焼いた作業用 JSON の `editor.shapes` がそのまま B の設定になる。B にしたら、焼いた物（`baked`）を外して形を直接書き出せる

## ハブの決定（2026-11-01、読み込み・書き出しの数字を受けて）

1. **引き伸ばし**：伸びの幅で自動で選ぶ。|倍率 − 1| ≤ 0.05 なら足し算（角度とは別の 1 軸）、それより大きければ 3 軸の掛け算・角度 15° ごと。設定に「正確に（データが大きい）」を置き、選べば常に掛け算
2. **確かめ方の面積比**：「どのマスも 0.5〜2」をやめ、「**折れ無し**（どのマスも面積比 > 0）、**falloff の外のマスは 0.9〜1.1**」にする（正確な球でも、30°・30° で向こう側のマスは 0.3 倍まで縮むため）
3. **データの大きさ**：14×14 の格子・10° ごとで約 93 KB を許す（1% 未満を優先）

### 決まった形（読み込み・書き出し ugo9/io-sphere 90b2825 時点）

- 関数：`makeSphereBake(model, shape)` → `{ motions, keys, params, notes, warnings }`（tools/sphere_bake.mjs）。shape は `editor.shapes` の 1 つをそのまま、パーツの奥行きは `model.editor.depth` から読む
- エディタは、motions の 1 つずつを `baked: shape.id` 付きの自分のデフォーマにし、範囲は「焼いたキーどうしの tent」で書く（editor/shapes.js の bakeCommand）。**格子の動きと、差分だけの動きは、別のキーの並びを持てる**（差分だけの動きは格子の動きと分けて返してもらえば、差分を 15° ごとにして頂点ごとの差分を 24 に減らせる）
- 格子の細かさ：球の直径に格子のマスが 7 より少ないと note `sphereGridCoarse` を出す。エディタが格子を作る時は **14×14**
- 円柱：`type: 'cylinder'`、params.x の 1 軸だけ、axis で軸を傾ける。キー 6 つ

### エディタの書き方を通した値（tests/sphere_metric.mjs、2026-11-01）

楕円 100×120 の円盤を 1.7 倍まで、エディタのコマンドで格子を作り、`makeSphereBake` の結果を `bakeCommand` で書き、芯で動かした。途中の角度 12 通り（2 軸の組み合わせ・負の角度を含む）。

### 奥行きと引き伸ばし（読み込み・書き出し ugo9/io-sphere aa09381、芯で測定）

| 何を | やり方 | 動き | 頂点ごとの差分 | 誤差 | .ugo の増え |
|---|---|---|---|---|---|
| パーツの奥行き（目 33 頂点、0.15） | 差分だけの動きを別に返す（15° ごと、交点も。既定） | — | **24** | **0.16%** | — |
| 引き伸ばし 1.04×0.96 | 足し算（\|倍率 − 1\| ≤ 0.05）、note `sphereStretchAdd` | 50 | — | 2.08% | +92 KB |
| 引き伸ばし 1.1×0.9 | 角度 15° ごと × 伸びの 3 軸、note `sphereStretchFull` | 74 | — | **0.86%** | +136 KB |

- 奥行きの差分は、その角度での格子（まわりの格子のキーの双一次の混ぜ）を通した後の位置で解く。エディタは格子と差分でキーの並びを分けて書くので、合わせて正しい位置になる。間隔は `shape.depthStep`
- 足し算の引き伸ばしは 1% を超える（2.08%）が、ハブの決めた 0.05 の境の中なので、そのままにする。正確にしたい時は `stretch.exact: true`
