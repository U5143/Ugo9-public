# Spine から持ち込む

Spine で書き出したデータ（JSON の `.json`、または 3.8 のバイナリ `.skel` / `.skel.bytes`）と、アトラス（`.atlas` / `.atlas.txt` と画像）を Ugo9 のモデルに変える。

```
node tools/import_spine.mjs skeleton.json skeleton.atlas 出力フォルダ [--scale 1]
node tools/import_spine.mjs skeleton.skel.bytes skeleton.atlas.txt 出力フォルダ
```

出力フォルダに `model.json`（作業用）・`model.ug9`（配布用）・アトラスの画像ができる。Web のデモや `ugo_export` でそのまま使える。読めない物は「warning」として表示される。JSON かバイナリかは中身で見分ける。

## 権利について

- Spine の書き出し形式（JSON・バイナリ・アトラス）は Esoteric Software が公開しており、開発元は自分のコードで読むことを認めている（調査_権利_Live2D_Spine.md）
- この読み込みは公開されている形式の説明だけから書いた。Spine の公式ランタイムのコードは使っておらず、読んでもいない
- テストには自分で作ったデータ（`tests/spine/`）を使い、Spine の見本データは使っていない
- `.spine`（Spine の編集用のファイル）は読まない

## 読める物

| Spine | Ugo9 での形 |
|---|---|
| 骨（位置・回転・拡大・**せん断**・**受け継ぎ方 5 種**・長さ） | 骨（v0.3〜） |
| **IK**（1 本・2 本、mix、曲がる向き、compress / stretch / uniform） | 制約（v0.3〜） |
| **transform 制約**（world / local、absolute / relative、4 つの mix とずれ） | 制約（v0.3〜）。複数の骨にかかる物は骨ごとに分ける |
| スロット（描く順） | パーツの順 |
| region（四角い画像） | 4 頂点のパーツ（余白を詰めたアトラスにも対応） |
| mesh（重みあり・なし）、linked mesh | パーツ（重みは最大 4 本） |
| スロットのアタッチメントの切り替え | パーツの不透明度のトラック（瞬時に切り替え） |
| スロットの透明度（alpha・rgba の a） | パーツの不透明度のトラック（曲線は曲線のキーのまま。アタッチメントや描く順の切り替えが曲線の途中に入る所だけ短い直線） |
| スロットの色（color・dark、rgba・rgb・rgba2・rgb2・color・twoColor のタイムライン、2026-11-10〜） | Ugo9 の色（tint・dark：Spine の二色と同じ決まり）。色の付いたスロットのパーツが共有する。キーは色ごとの曲線を短い直線にして（色には曲線のキーが無い）。白で暗い色も無いスロットは色を作らない |
| クリッピング（clipping、2026-11-10〜） | 多角形をマスクだけのパーツ（`maskOnly`・`solid`）にし、クリッピングのスロットの次から end のスロットまでのパーツ（描く順の複製も）にマスクとして付ける。基準の姿の添付だけ（Ugo9 のマスクは途中で付け外ししない）。描く順のタイムラインがあっても、基準の順で決める（警告）。提供データの 2 体（髪の影を頭に収める物）で、最初のコマの絵は 4 万画素中 7 画素と 0 画素変わる |
| rotate・translate・scale・**shear** のタイムライン | 骨のトラック（基準の姿からの差）。3.x の回転は、隣のキーと 180° より離れるキーを 360° 単位でずらし、近い向きに回す（下の「回転のキー」）。4.x はそのまま（数を警告） |
| **IK・transform のタイムライン**（mix・曲がる向き） | 制約のトラック（v0.3〜） |
| **描く順のタイムライン** | 動くスロットに「描く位置ごとの複製」を作り、不透明度で今の順の複製だけを見せる（1 回の描画のまま） |
| deform のタイムライン | キーごとの差分と、その重みのトラック |
| ベジェ曲線 | 形式 1.1（2026-11-10）からは、曲線のキー（`[秒, 値, "bezier", cx1, cy1, cx2, cy2]`）のまま持つ。芯が読み込みで直線に分け、分け方の細かさはコンパイラが決める（角度 0.05 度・移動 0.05 px 以内）。分けた直線で収まらない、ほぼ垂直な手の曲線だけは、コンパイラが許しの中に収まるだけの直線のキーにする（`curveBaked`）。スロットの透明度も曲線のキーのまま（アタッチメントや描く順の切り替えが曲線の途中に入る所だけ短い直線）。前（1.0 まで）は：1 秒あたり 120 の直線に分けてから、直線で済む所のキーを間引く。骨ごとに、その骨が動かす一番遠い頂点で 0.05 px 以内になる細かさで間引く（角度は 0.05 度まで）。IK・transform の拘束が使う骨とその親は、前の細かさ（0.005 度・0.005 px）のまま |
| アトラスの回転（`true`・90・180・270） | UV を回す（反時計回り、大きさは回す前の物） |
| Spine 3.7・3.8・4.x の JSON、3.8 のバイナリ | どれも読む |

## まだ読めない物（warning が出る）

- path・physics の制約、IK の softness
  - path・physics は、動かし方が Spine の公開された形式の説明に無い（physics は欄の名前も無い）ので読まない。警告は、拘束ごとに名前と動かす骨を出す（例：`path constraint tail: not read; it moves bones arm1, arm2 along the path in slot flag ...`）。その骨は自分の姿のままで、アニメはそこが違う。アニメにその拘束のキーがあれば、それも警告に出す
  - physics の揺れは、エディタで鎖（`chains`）を足すと近い物になる
  - path を使ったデータが届いたら、読み込みの時に骨のキーに焼く形を考える（2026-11-05 の調べ）
- イベント（絵は変わらない）、sequence
- 5 本以上の骨に重みのある頂点（強い 4 本だけ残し、合計を 1 に直す）
- バウンディングボックス（当たり判定。絵は変わらない）
- アトラスが複数ページの時の 1 回描画（Web の描画は今は 1 ページ目だけ）
- 4.x のバイナリ（JSON で書き出す）

## スキン（2026-11-10、利用者の声 #44）

Ugo9 にスキンは無いので、見せるスキンを 1 つ選び、ほかのスキンの絵は隠れたパーツとして入れる。

    node tools/import_spine.mjs skel.json skel.atlas 先 --skin red      # importSpine(skel, atlas, { skin: 'red' })

- 見せるスキン（既定は default）：Spine と同じく、そのスキンの添付を先に、無ければ default スキンの添付を使う。アニメの添付の切り替え・deform のキーは、見せるスキンの物に効く
- ほかのスキンの添付：`スロット/添付@スキン` という名前の隠れたパーツ（不透明度 0）として、そのスロットの描く順の所に入る。見せたい時は不透明度のキーで（例：服を替えるアニメ）。アニメは切り替えない
- 結果の `skins`：スキンの名前、見せるスキン、スキンごとの隠れたパーツの名前（エディタで「スキンを替える」を作る時に使える）
- linkedmesh は、`skin` に書かれたスキン（無ければ自分のスキン）の同じスロットの親を使う
- ほかのスキンのクリッピングは使わない（知らせる）。無いスキンの名前は、あるスキンを挙げて止まる
- 確かめ（`tests/spine_skins_test.mjs`）：試しの骨組みに 2 つのスキン（胴を旗の絵に・目を閉じた絵に／腕の linkedmesh）を足すと、既定では今までと同じパーツに隠れたパーツが足され、描く順はスロットの所。red を見せると胴と目が red の絵になり、default の物と二重にならない。アニメの切り替えは同じパーツ、どちらもコンパイルできる、無いスキン、コマンド

## 確かめたこと（`tests/spine_test.mjs`）

自分で作った Spine 4.2 形式の見本（胴・2 本の骨にまたがる腕・開閉する目・形と透明度が変わる旗）を読み込み、Spine の形式の決まりをテストの中で別に計算した位置と比べた。基準の姿と 7 つの時刻で、全頂点の誤差は 0.011 ピクセル以下。目の切り替えと旗の透明度も一致。

Spine 4.x のベジェ曲線の数値は「時間と値そのもの」として読んでいる（4.0 からの書き方と理解している。公開の説明は 3.8 のまま）。実際の 4.x の書き出しで違いが見つかれば直す。

## 提供データで確かめたこと（2026-10-30）

ユーザーから受け取った Spine 3.8.95 のバイナリ 3 体（骨 205〜395 本、制約あり）と Spine 3.7.94 の JSON 6 体（四角い画像だけで組まれた物）で確かめた。データは `samples/提供/spine/`（配布物には入れない）。

- **バイナリの読み方**：3 体とも最後のバイトまでずれずに読めた。公開の説明で曖昧な所（重み付き頂点の並び、アニメの名前、描く順の値が符号付き、変形キーの数）はこの読み方で決めた
- **アトラスの回転**：3 体のページで、全部の部品の輪郭が不透明な画素を 1 つ残らず覆うのは「反時計回り・大きさは回す前」の読み方だけ（逆向きだと約 1 割が覆われない）。回したアトラスで「回す前の大きさ」と読まないと 1〜10 個の領域がページからはみ出す
- **回転のキー**（2026-11-10）：公開の説明は、キーの間を値のまま回すか近い向きに回すかを書いていない。9 体の隣り合う回転キー 65,580 組のうち 705 組（ステップを除く）が 180° より離れていて、値のまま回すと回る速さの中央値が 1141°/秒（上位 10% で 2158°/秒）。近い向きなら中央値 40°/秒・上位 10% で 199°/秒で、ほかの 60,603 組（中央値 12°/秒・上位 10% で 62°/秒・上位 1% で 263°/秒）と同じ程度。9 体とも 3.7・3.8 なので、3.x は近い向きに回すとした。4.x は確かめるデータが無いので値のまま
- **受け継ぎ方と制約**：Spine は基準の姿で重みを付けるので、正しく計算できていれば、重み付き頂点の「骨ごとの位置」は一致する。3 体の全頂点で、この差は受け継ぎ方も制約も無視すると最大 1,030 px、受け継ぎ方だけだと 0.9 px、両方を入れると 0.013〜0.084 px になった
- **C の芯と JS の計算**：`tests/pose_test.mjs` が、受け継ぎ方 5 種・せん断・IK 1 本と 2 本・transform 4 種・アニメで動く mix と曲がる向きを使う骨組みで、40 通りのランダムな姿勢を比べる（差は 10⁻⁶ 以下）
- **まだ確かめていないこと**：アニメの途中の見た目が Spine と同じか。Spine で描いた絵（同じ時刻の PNG）と並べて比べる必要がある（下の「Spine の絵と比べる」。参照の絵はユーザーにお願い中）

## Spine の絵と比べる（`tools/compare_frames.mjs`）

Spine エディタの画像の書き出し（PNG 連番）と、同じアニメ・同じ時刻の `ugo_export` の絵を並べて、違う画素を数える。

```
node tools/compare_frames.mjs --model build/spine/キャラ/model.ug9 --anim アニメ名 --ref 参照のPNGのフォルダ \
     [--fps 30] [--start 0] [--scale 1] [--align fixed|each] [--out build/visual/名前]
```

- 参照の絵は切り抜かれていてよい。置き場所（ずれ）は絵の不透明な所から探す。全部の絵が同じ大きさなら `fixed`（既定、1 つのずれ）、1 枚ずつ大きさが違うなら `each`
- 色は乗算済み（premultiplied）に直してから比べる。どれかのチャンネルが 16/255 より違う画素を「違う」と数える。輪郭の丸めの違いを除くため、1 画素までずれた所に同じ色があれば「同じ」とする数（tolerant）も出す
- 出力：`report.json`（フレームごとの割合・平均の差・不透明な所の重なり IoU）と、最初のフレームと差の大きいフレームの「参照 ｜ Ugo9 ｜ 差（赤）」の PNG。`build/` に置く（提供データの絵なので配らない）
- `ugo_export` に `--pad`（キャンバスの周りに余白）と `--start`（最初のフレームの時刻）を足した
- 自分の見本で確かめる：`node tests/compare_frames_test.mjs`（自分の絵をずらして切り抜いた物を参照にし、ずれを見つけて差 0、0.05 秒ずれた絵は差ありと出るか）

骨の多いキャラでは、骨と制約の計算が CPU の時間の大半になる（骨 395 本・制約 16 個で 1 体 46 µs）。制約が根元近くの骨を動かすと子孫を全部計算し直すため。速くする余地がある。

## Spine へ書き出す（`tools/export_spine.mjs`、2026-11-10〜、利用者の声 #45）

Ugo9 の作業ファイルを、Spine の JSON とアトラスにする。Spine の公開の形式の説明（JSON・アトラス）だけから書く。絵はモデルのアトラスのページをそのまま使い、パーツ 1 つを 1 つの領域にする。

```
node tools/export_spine.mjs model.json --out build/spine/名前    # 名前.json・名前.atlas と絵のページ
```

段 1：基準の姿。
- 骨：受け継ぎ方・せん断・長さ。Spine は y が上・角度が反時計回りなので、y・回転・せん断の向きを返す
- スロット：パーツ 1 つに 1 つ、描く順（描画順の値、同じなら並び順）。合成（add → additive・multiply・screen）、不透明度（スロットの色の透明度）
- 添付：パーツ 1 つに 1 つのメッシュ。輪郭の頂点を先に並べて Spine の hull にする（輪郭が 1 周でない時は hull 0、info）。重みのあるパーツは骨ごとの基準の姿の中の位置と重み、無いパーツは骨の中の位置
- Spine に置き場の無い物は書かずに知らせる（`spineLeftOut`）：パラメータ（info）・デフォーマ・物理と鎖・のり・表情。ワープ格子の中のパーツは基準の形のまま格子の骨に（`spineWarp`）。マスクはまだ書かない（`spineMask`）
段 2：制約とアニメーション。
- 制約：IK（mix・曲がる向き・compress・stretch・uniform）と transform（ずれ・mix 6 つ・local・relative）を、書いた順を order にして書く。基準の姿は制約を解いた後の姿で、メッシュはその姿で骨に付ける（Spine と同じ）
- アニメーション：骨は回転・移動・拡大・せん断を 1 つずつのタイムライン（Spine 4.1 の rotate・translatex・translatey・scalex・scaley・shearx・sheary）。拡大は Ugo9 の「基準に足す量」を Spine の「基準に掛ける数」に直す。パーツの不透明度はスロットの alpha。制約の mix と曲がる向き（いくつものチャンネルが 1 つのキーの並びを使うので、全部のキーの時刻で直線に。曲線のあった時は `spineCurveStraight`、info）
- キー：ステップは stepped、smooth は (1/3, v0)・(2/3, v1) のベジェ、曲線のキー（形式 1.1）は Spine 4 のベジェ（時刻と値そのもの）
- アニメの長さ：Spine の長さは最後のキーの時刻なので、短くなる時は最初の骨の回転に終わりのキーを足して保つ
- 書かない物（`spineAnimLeftOut`）：パラメータのトラック（Spine にパラメータが無い）・描画順・差分・色
段 3（その 1）：色。
- パーツの色（tint・dark はそのまま、Live2D 式の乗算色・スクリーン色は light = 乗算 × (1 − スクリーン) + スクリーン、dark = スクリーン。芯の色の決まり rgb = C X + a Y で同じ X・Y になる）をスロットの色と暗い色に。不透明度はスロットの色の透明度
- アニメの色のキーはスロットの rgb（暗い色がある時は rgb2）のタイムライン。全部のチャンネルのキーの時刻で直線に（smooth は `spineCurveStraight`、info）
段 3（その 2）：描画順。
- Ugo9 は描画順の値（キーの間は直線）で描き、Spine はスロットの並びをある時刻に動かす。全部のキーの時刻と、2 つの値が入れ替わる時刻で並びを求め、変わる所に drawOrder のキーを書く（基準の場所に無いスロットを、動いた数だけ。ほかは空いた場所に基準の順で）
段 3（その 3）：マスクをクリッピングに。
- マスクのパーツ 1 つだけで、反転していないマスクを付けたパーツが描く順に続いていれば、その最初のパーツの直前にクリッピングのスロット（`マスクの名前#clip`、多角形はマスクのパーツの輪郭、end は最後のパーツ）を置く。マスクだけのパーツ（`maskOnly`）は描かない
- Spine のクリッピングは輪郭の多角形で切るので、絵の透明な所で切るマスク（`solid` でない）は輪郭の中が全部残る（`spineMaskSolid`、info）
- 続いていない・2 つ以上のマスク・反転は書かずに知らせる（`spineMask`）

確かめたこと（その 3）：見本の瞳（白目のマスク）と、回した骨の上のマスクだけのパーツを書き出して読み戻すと、クリッピングの多角形がマスクの輪郭の位置にあり、同じパーツがそれでマスクされる。続かないマスクは知らせて外す

確かめたこと（その 2）：値が直線で動く・ステップで跳ぶ描画順のアニメを書き出し、Spine の説明の決まりで並びを組み直すと、11 の時刻（入れ替わりの前後を含む）で Ugo9 の描く順と同じ

確かめたこと（段 3）：tint・dark、乗算色・スクリーン色、tint だけの 3 つの色と色のアニメを書き出して読み戻すと、芯の X・Y が同じ（8 ビットの丸めの中）。Spine の取り込みが色を読むようになった（提供データには色の付いたスロットが無いので、その取り込みは変わらない）

確かめたこと（段 2）：2 本の IK・transform 制約・曲線・smooth・ステップ・直線のキー・回転・移動・拡大・せん断・不透明度・制約の mix を持つ作り物を書き出して読み戻し、Ugo9 の芯で 7 つの時刻に動かすと、全部の頂点が 0.01 px 以内、不透明度も同じ

確かめたこと（`tests/export_spine_test.mjs`）：書き出した物を Ugo9 の Spine の取り込みで読み戻すと、見本の 16 パーツも、回した・拡大した・せん断した・拡大を受け継がない骨と重みのあるパーツの作り物も、頂点（モデル座標）・絵の位置・三角形・重み・合成・不透明度が同じ。Spine のエディタで開く確かめは PC 確認で
